## 要件 1 · 问题定义与可测量验收判据

### 1.1 问题定义与选题依据

**能力问题(一句话)**:在 **MT3 式免训练检索操作策略**的**设计空间**里(检索度量 /
alignment–interaction 分解粒度 / 两阶段接口 / 库内搜索与插值),**哪些配置在固定预算下有效,
以及"test-time 算力 ↔ 专家演示"的兑换率是多少?** —— 并且,**用一套能抗已知失效模式的
测量协议给出答案**,而不是又报一个 in-loop 成功率。

**选题依据(三条,均已核实)**:

1. **能力缺口在哪**:①**载体缺口**——现有全部自主搜索工作的搜索对象是 code-as-policy 代码 /
   RL 奖励超参 / VLA 微调配方 / 技能库 / 机器人形态,**无一篇以"检索式免训练策略的设计选择"
   为搜索对象**(硬门 5 篇全文级 grep 12 词根 = **0 命中**:`MT3`/`training-free`/`retrieval-based`/
   `k-nearest`/`demonstration library`/`nonparametric`/`trajectory transfer`/`exchange rate`/
   `reuse rate`/`interaction curve`/`mode collapse`/`blind`);SEAR(2610.18792)的 "Policy form"
   分类学只有 **CaP/AaP/AR 三格,无第四格**。②**测量缺口**——四篇综述/批判文全文级 **4/4 共同指认**
   头两条:(a)**in-loop 代理指标增益 ≠ 独立 held-out 增益**(P3 2609.00077 实测:迭代 300 轮
   **in-loop 夸大 held-out 2.0~2.6 倍**,ρ^audit **0.38-0.49**,1000 轮后 "collapse deepens rather
   than self-corrects");(b)**缺"自我改进"的共享基准与协议**(P4 2608.01851 逐字:"**No standard
   benchmark yet plots held-out success as a function of accumulated interaction**")。
2. **为什么是现在**:①**MT3(Science Robotics 2025)已把免训练检索推到千任务规模**,且**委托人已
   有复现基础**——载体现成;②**autoresearch(Karpathy,2026-03,97,940★)确立了"固定预算 +
   单一指标 + keep/discard + 人写 program.md / agent 跑实验"的可行范式**,且已有机器人 fork
   (`jellyheadandrew/autoresearch-robotics`,发布后第 4 天)——机制现成;③**测量协议的全部通用件
   已被发表**(P3 三层指标 / SEAR sealed judge+五种假学习对照 / SAGE 2609.36043 配对检验+等预算 /
   AgentSLABench 2608.00805 SHA256 sealed+EASR / P4 曲线与面积+reuse rate)——**我们不必发明协议,
   只需首次把它们组装进一个免训练具身闭环**;④**窗口在关闭**(2610 一个月里 EmbodiedCLBench /
   EmbodiedSkillBench / AdaRSI / ReTrace / Scale-and-Selection 五篇同时落地),**故须尽快**。
3. **哪条路线更可能 work**:**免训练检索路线**——因为它**单实验极便宜**(不训策略网络,一次实验
   = 建库 + 跑 rollout),**这使我们负担得起领域说"缺"的那套严格测量**(P3 做同类测量花了
   **~6,200 A100-hours**,因其每轮要训练;我们不训练)。**这是本选题的结构性优势,不是叙事选择。**

**明确不做(边界)**:①不做真机实验(红色;且 P1 2610.18842 逐字:"**Simulation evidence alone
does not establish hardware safety**");②不主张"提出新协议"(通用件已发表,须显式引用为来源);
③不主张"第一套/首个基准"(**EmbodiedCLBench 已占 "first benchmark in embodied simulation" 措辞,
命名与主张必须避开**);④不做灵巧手/触觉变体(属真机依赖支,另议);⑤不训练策略网络
(免训练是本选题的前提,一旦引入训练即失去成本优势)。

### 1.2 可测量验收判据(逐条可测;底线三条)

**七个交付量(A1-A7),每条都给"怎么算、算到什么程度算过"**:

| # | 交付量 | 可测判据 | 口径与来源 |
|---|---|---|---|
| **A1** | **设计空间地图** | ≥**40** 个配置(4 个设计维度 × 每维 ≥3 水平,含基线),每配置在**固定预算**下测得 **m_blind**(headline)+ 95% bootstrap CI + ≥3 seeds;给出**每维的主效应与交互**(至少二阶) | 预算口径见 §7.2;统计口径见 §7.4 |
| **A2** | **算力 ↔ 专家演示兑换率** | 在 **(test-time 算力预算) × (每任务专家演示条数)** 的**配平网格**(≥3×3=9 格)上,拟合**等成功率曲线(isoquant)**;报告**兑换率的点估计 + 95% CI + 拟合优度**;并报告**兑换率是否随任务族变化** | **⚠️ 轴定义硬规则**:算力轴 = **测试期推理/搜索算力**(tokens + GPU-秒 + wall-clock),**不是训练算力**;数据轴 = **人类专家演示条数**,**不是自采经验/自采仿真数据/自身评测 rollout**(见 §8 划界 D2/D3/D6) |
| **A3** | **success-vs-interactions 曲线与面积** | 在**终身/累积交互**设置下,报告 **held-out 成功率 vs 累积交互数**的**曲线与其面积(AUC)**,**不得只报端点**;≥3 seeds + CI | P4 2608.01851 逐字:"report **the curve and its area, not a single endpoint**" |
| **A4** | **库复用率(reuse rate)** | 按 P4 的**确切定义**报告:"**fraction of new-task solutions that invoke at least one previously stored [demonstration/skill]**";分任务族给出;并区分"调用即成功"与"调用但失败" | P4 §6 Table 9 逐字定义;**⚠️ 不得用代理量替代**(gain-over-zero-shot / distinct 计数 / Used-trained 比 / FT-step 份额均**不是**该比率,见 §8 划界 D3/D4/D6) |
| **A5** | **多样性仪器读数** | 报告 **语义簇数 C_t**(Sentence-BERT `all-mpnet-base-v2` + HDBSCAN `min_cluster_size=5`)、**机制熵 H_t**(按 P3 §3.2 的 9 类机制分类法,**须先在本域重新推导分类法并报告覆盖率与标注一致性 κ**)、**语料相似度 V_t**;**判据:若在 ≥300 轮内 C_t 下降 ≥50% 或 H_t 下降 ≥0.3 nats,须显式报告"发生 mode collapse"并停止该支** | P3 2609.00077 §3.2(其在 ML 域:187 条日志推导、覆盖 96.4%、κ=0.84);**⚠️ P3 自陈其分类法"ML-centric and would need re-derivation"——本域重推导是本规格的一项工作,不是照搬** |
| **A6** | **忠实度比 ρ** | 报告 **ρ^audit = m_audit / m_opt** 与 **ρ^blind = m_blind / m_opt**(P3 定义);**判据:ρ^blind 必须作为 headline 报告,且若 ρ^blind < 0.6 须在结论首句显式声明"in-loop 增益的 ≥40% 未在盲评中实现"** | P3 实测参考值:Vanilla AR ρ^audit **0.38-0.49**、1000 轮降至 **0.31**;其缓解法 DAPS 提到 **0.79**(audit)/**0.74**(blind)——**⚠️ 完整口径:DAPS 也未达 1.0,且 in-loop 代价 0.983(归一化)、墙钟 +1.4%** |
| **A7** | **联合预算记账** | **每一条结果**都附:**wall-clock + GPU-hours + tokens(输入/输出分列,缓存命中单列)+ 推理预算 + 演示条数**;**判据:任何"我们更好"的主张,必须在同预算下成立,否则须改述为"在 X 倍预算下更好"** | 治 P2/P1 共同指认的 #8("无法区分方法更好与花得更多");**⚠️ SEAR 自陈只配平 wall-clock("Budgets are matched in wall-clock time, not compute")——我们须做得更严,这是可主张的增量** |

**三条底线(不可让步)**:
- **L1 · 盲评优先**:**m_blind 是 headline**;任何摘要/结论/图表标题不得以 m_opt 代替 m_blind。
  依据:P3 实测 in-loop 夸大 held-out **2.0~2.6 倍**;《What Stops RSI in Robotics?》(2609.31760)
  在机器人域已定性实证 "The agent **optimized exactly what the evaluator measured, including
  where it was wrong**"。
- **L2 · 统计严谨**:**≥3 seeds + 95% bootstrap CI + 置换检验**;**⚠️ 检验力告警(硬规则,承
  `lessons.md`)**:配对置换检验有理论 p 下限 **2/2ⁿ**,**n≤4 时最小 p ≥ 0.125,差异再一致也达不到
  0.05**——脚本须在 n≤4 时**自动打印检验力不足告警**,**不得据此判"无差异"当结论**。
  并采用 **SAGE(2609.36043)的 per-item 配对 + one-sided paired test + 否则弃权(abstain)**,
  **显式引用 SAGE 为方法来源,不主张首创**。
- **L3 · 配置口径不得跨迁(design-spec §4.1②)**:验收锚点**必须来自同配置口径**。
  **⚠️ 具体禁令**:**不得把 MT3 原文的 78.25%(seen)/68%(unseen) 当本平台的验收目标**——
  MT3 是**真机 Sawyer + 单 D415 + 自建 1,000 任务 + 每任务 2 trials**,与本平台(**仿真 +
  LIBERO/RoboTwin 任务集 + 每任务 ≥50 rollouts**)**配置口径完全不同**。
  **本平台的基线锚点由 P3 步骤(baseline run)实测标定**,MT3 数字**只能作技术依据引用**,
  且引用时须带完整口径(真机/Sawyer/单相机/2 trials per task)。

## 要件 2 · 系统构成与工作原理

### 2.1 四个组件(仿 autoresearch 的三文件分工,加一层测量层)

| 组件 | 文件 | 可改性 | 职责 |
|---|---|---|---|
| **① 冻结评测 harness** | `eval_harness.py` | **只读 + SHA256 校验** | 任务集加载、rollout 执行、成功判据、**三层指标计算(m_opt/m_audit/m_blind)**、**sealed judge**(持 held-out 初始状态、**无视策略自称的成功**)、预算记账 |
| **② 冻结数据/库构建** | `prepare.py` | **只读 + SHA256 校验** | 演示库构建、物体分割、几何嵌入预计算、固定常量(预算/序列长度/rollout 数) |
| **③ 可搜索的策略族** | `policy.py` | **agent 唯一可改文件** | MT3 式免训练检索策略,**把 4 个设计维度暴露为显式可调旋钮**(见 §2.3) |
| **④ agent 指令** | `program.md` | **人改** | 循环规程、keep/discard 规则、简洁性判据、NEVER STOP(见 §6.4) |
| **⑤ 测量与披露层** | `results.tsv` + `metrics/` + `disclosure/` | agent 只追加、不删改 | 实验账、多样性仪器、预算账、**机器可读披露契约** |

**为什么 harness 必须冻结 + 校验**:autoresearch 的设计洞察——`prepare.py` 只读、
"**Modify the evaluation harness**" 明列为 CANNOT do,`evaluate_bpb` 是 ground truth;
GitHub 业余实现层已普及此做法(`TatianaUshakova/StirBench` 逐字:"env.py(FROZEN,
**checksummed**)/ verifier.py(FROZEN, checksummed)/ policy.py(**the only file the research
agent edits**)")。**不冻结 = agent 可以通过改指标"作弊",这是 metric fixation 的一条通路。**

### 2.2 工作原理(为什么这样能 work)

**闭环**:agent 读当前 git 状态 → 改 `policy.py` 的一个设计旋钮 → git commit → 跑固定预算实验
(输出重定向到 `run.log`,**不 flood 上下文**)→ grep 出 **m_opt** → 记 `results.tsv` →
**若 m_opt 改进则 advance branch(keep),否则 git reset(discard)** → 每 **K=10** 轮由 gate
读一次 **m_audit**(只回滚 + 给**无值模板通知**,不透露数值)→ **每 run 只在最后评一次 m_blind**
(任何组件从不读取)。

**为什么免训练是关键**:MT3 式策略**不训练策略网络**——一次实验 = 建库(或复用已建库)+
跑 rollout。故单实验成本 ≈ rollout 时间,**可负担 ≥40 配置 × ≥3 seeds × ≥50 rollouts 的网格**,
以及三层指标 + sealed judge + 多样性仪器所需的**重复评测**。对比:P3 每轮要训练,
全量 sweep 花 **~6,200 A100-hours**;我们**不训练**,单张 4090 可做**子集**并显式降规模披露(A7)。

### 2.3 设计空间的 4 个维度(= 搜索对象;逐条对应 MT3 自陈局限)

| 维度 | 旋钮(示例水平) | 对应 MT3 自陈的什么 |
|---|---|---|
| **D1 检索度量** | 几何最近邻 / 位姿相似 / 光流相似(FlowRetrieval 2408.16944)/ 重要性加权(IWR 2509.01657)/ kNN 邻域(DARP 2606.09758)/ **位姿-几何解耦双通道(加权系数可扫)** | MT3 逐字:"geometry-based retrieval had to balance two competing objectives…**similar object pose** versus **similar object geometry**…This **fundamental tension**";检索是失败主因 **22.3%** |
| **D2 分解粒度** | 两段固定(MT3 原样)/ 变长相位(PHASE 2609.30889 式)/ 交互事件(ManiLong-Shot 2512.16302 式)/ 不分(单体) | MT3 逐字:"**decomposition prevented this beneficial representation sharing**"(分解的代价) |
| **D3 两阶段接口** | 首帧位姿(MT3 原样)/ 位姿+夹爪状态 / 位姿+接触约束 / 显式子目标 | MT3 的接口是 $T_{WE}^{Test}=T_\delta T_{WE}^{Demo}$,单一位姿 |
| **D4 库内搜索/插值** | top-1 回放(MT3 原样)/ top-k 加权 / **轨迹插值** / 带自我验证的搜索(SAIL 2603.08269 式 MCTS,**须划界**) | MT3 逐字:"retrieval…**fundamentally could not interpolate between demonstrated behaviours**" |

**⚠️ D4 与 SAIL 的划界(硬要求)**:SAIL(2603.08269,IROS 2026)已做"MCTS over 完整轨迹 +
检索档案 + VLM 打分"。**我们的 D4 必须限定为"在 MT3 式免训练原始演示库上做搜索/插值,
且不引入 VLM 生成新轨迹"**——SAIL 搜索的是 **VLM 生成/精化的轨迹**,检索档案只作上下文养料;
我们搜索的是**库内原始演示的组合与插值**。**若这条界划不清,D4 不成立,须放弃 D4 只做 D1-D3。**

## 要件 4 · 接口定义(软件;本项目无机械/电气接口)

### 4.1 文件接口(三文件分工 + 校验)

```
project/
├── prepare.py          # 冻结:常量/演示库构建/分割/嵌入预计算   ← SHA256 记录于 frozen.sha256
├── eval_harness.py     # 冻结:任务加载/rollout/成功判据/三层指标/sealed judge/预算账 ← SHA256
├── frozen.sha256       # 冻结文件的 SHA256 清单;每轮实验开始前校验,不符即 abort
├── policy.py           # ★ agent 唯一可改文件:检索策略族 + 4 维设计旋钮
├── program.md          # 人改:agent 指令(见 §6.4)
├── config_schema.yaml  # 设计空间的显式枚举(维度/水平/取值范围/默认值)
├── results.tsv         # 实验账(agent 只追加;不 commit)
├── metrics/            # A3 曲线 / A5 多样性仪器 / A6 ρ / A7 预算账
└── disclosure/         # 机器可读披露契约(见 §7.5)
```

### 4.2 `policy.py` 的接口契约(agent 只能在此范围内改)

```python
class RetrievalPolicy:
    def __init__(self, config: dict):
        """config 的键必须来自 config_schema.yaml;不得引入 schema 外的新键
        (若需新维度,须在 results.tsv 的 description 里说明并由人批准后改 schema)"""
    def build_library(self, demos) -> Library: ...      # 建库(免训练)
    def retrieve(self, obs, task_desc) -> Demonstration: ...   # D1 检索度量在此
    def decompose(self, demo) -> (Align, Interact): ...        # D2 分解粒度在此
    def interface(self, align_out) -> Interact_init: ...       # D3 两阶段接口在此
    def execute(self, obs) -> Action: ...                      # D4 库内搜索/插值在此
```

**⚠️ 契约硬规则**:`policy.py` **不得 import 或调用 `eval_harness.py` 的成功判据/指标函数**
(防止 agent 反向读取评测信号 = 泄漏);**不得读写 `m_audit`/`m_blind`**;
**不得修改 `frozen.sha256`**。harness 每轮校验这三条,违反即判 `crash` 并 revert。

### 4.3 `results.tsv` 模式(tab 分隔,**逗号会破描述**;不 commit)

```
commit  config_id  m_opt  m_audit  m_blind  seeds  sr_std  wall_clock_s  gpu_hours  tokens_in  tokens_out  demos_per_task  C_t  H_t  V_t  rho_audit  rho_blind  status  description
```
- `status` ∈ {`keep`, `discard`, `crash`};`crash` 时指标列填 `0.000000`
- `m_audit`/`m_blind` 在**非 gate/非终评轮**填 `NA`(**agent 不得填数,由 harness 写入**)

## 要件 6 · 实施步骤(每步带"做完的标志")

### 6.1 P0 · 环境与复现验证(真人执行)
1. 装依赖、下基准资产。**做完的标志**:`prepare.py` 跑通,演示库与嵌入缓存生成。
2. **复现 MT3 基线**(委托人已有的复现基础)在本平台/本任务集上跑通。
   **做完的标志**:`results.tsv` 有 **baseline 行**,且 **m_blind 与复现记录的偏差在 ±X 个百分点内**
   (**⚠️ X 待真人实测标定**——不得预设,不得引用 MT3 原文 78.25% 作为目标,见 L3)。
   **⚠️ autoresearch 硬规则**:"**Your very first run should always be to establish the baseline**"。

### 6.2 P1 · 冻结 harness 与校验
3. 定稿 `eval_harness.py` / `prepare.py`,计算 SHA256 写入 `frozen.sha256`。
   **做完的标志**:`sha256sum -c frozen.sha256` 全 OK;harness 的三条契约检查(§4.2)有单测且通过。

### 6.3 P2 · 显式定义设计空间
4. 写 `config_schema.yaml`,枚举 D1-D4 的维度、水平、取值范围、默认值。
   **做完的标志**:schema 可被 `policy.py` 加载并生成 ≥40 个合法配置(含基线);
   **D4 与 SAIL 的划界(§2.3 ⚠️)已写进 schema 注释**。

### 6.4 P3 · 自主搜索循环(agent 执行;`program.md` 规程)
5. 建分支 `search/<tag>`(tag 用日期;分支不得已存在)。**做完的标志**:分支存在、`results.tsv` 只有表头。
6. **LOOP**(承 autoresearch,逐条借其设计):
   a. 看 git 状态(当前分支/commit)
   b. 改 `policy.py` 的**一个**旋钮(一次只改一处,便于归因)
   c. `git commit`
   d. 跑实验:`python run.py > run.log 2>&1`(**重定向,禁 tee,不 flood 上下文**)
   e. 读结果:`grep "^m_opt:" run.log`
   f. grep 为空 = crash → `tail -n 50 run.log` 读栈;**小错(typo/缺 import)修了重跑;
      想法根本坏则记 `crash` 跳过**(autoresearch 原话:"If the idea itself is fundamentally
      broken, just skip it, log 'crash' as the status in the tsv, and move on")
   g. 记 `results.tsv`
   h. **m_opt 改进 → advance branch(keep commit);相等或更差 → git reset 回起点**
   i. **超时**:单实验预算见 §7.2;**超预算 2 倍即 kill 当 crash**
   j. **NEVER STOP**:不暂停问人;**没想法就 think harder**——读 `policy.py` 引的论文、
      重读 in-scope 文件、组合此前 near-miss、试更激进的设计维度组合
   **做完的标志**:`results.tsv` ≥**40 配置 × ≥3 seeds** 行,且 keep/discard 比例与 git 历史一致。
7. **每 K=10 轮**:gate 读 `m_audit`,**只回滚 + 给无值模板通知**(如"第 N 轮起 audit 未通过,
   已回滚至 commit X",**不透露数值**)。**做完的标志**:`metrics/audit_log` 有回滚记录,
   且回滚轮次的 `m_audit` 值**从未出现在 agent 可见的任何文件里**。
8. **每 run 结束评一次 m_blind**。**做完的标志**:`metrics/blind.tsv` 每 run 一行,**任何组件从不读取它**。

### 6.5 P4 · 兑换率网格(A2,独立于搜索循环)
9. 在 **(test-time 算力预算 3 水平) × (每任务专家演示 3 水平)** 的配平网格上,
   每格跑 ≥3 seeds × ≥50 rollouts。**做完的标志**:9 格 × ≥3 seeds 数据齐,
   等成功率曲线拟合完成并给出 CI 与拟合优度。

### 6.6 P5 · 测量提取与披露
10. 算 A3 曲线与面积、A4 复用率、A5 多样性仪器(**含本域机制分类法的重新推导 + 覆盖率 + κ**)、
    A6 ρ^audit/ρ^blind、A7 预算账。**做完的标志**:五个量各有图表 + CI + 机器可读 CSV。
11. 写 `disclosure/`(**机器可读披露契约**:seeds/traces/预算/prompt/context/harness 镜像 +

## 要件 7 · 验收测试方案(实验设计)

### 7.1 基准与任务集(择一为主、一为泛化验证)
- **主**:LIBERO / LIBERO-PRO(**理由**:近邻工作多用它,便于划界对比;ENCORE/RoboRSI/AdaRSI/
  EmbodiedSkillBench 均在其上报数)。
- **泛化验证**:RoboTwin 2.0(**理由**:SEAR/RoboRSI 亦用,可检验结论是否基准特异)。
- **⚠️ 口径禁令(design-spec §4.1②)**:**不同基准的数字不得并列**;LIBERO-Pro 存在
  "**五个数字至少四种设定**"(61 / 75.6 / 77.8·88.9 / 45.0 / 77.5,见透镜③分图 v1.1.1),
  **引用任何他人数字须带完整口径(基准 + 扰动类型 + 骨干 + 是否均值)**;
  **77.5 仍不作为数据引用、不与 61 并列**(委托人升级门选项 A 维持从严,`decisions.md` 2026-10-09)。

### 7.2 固定预算(承 autoresearch 的核心设计洞察)
- **单实验预算 = 固定墙钟 T 分钟**(**⚠️ T 待真人按 4090 实测标定**;autoresearch 用 5 分钟于 H100,
  4090 须重标)。
- **为什么固定墙钟而非固定步数**:autoresearch 逐字:"this makes experiments **directly
  comparable** regardless of what the agent changes (model size, batch size, architecture, etc)"。
- **超时**:超 **2T** 即 kill 当 crash(autoresearch 用 10 分钟对 5 分钟预算 = 2 倍)。
- **rollout 数**:每配置每 seed **≥50 rollouts**(**⚠️ 待真人按任务集标定**;对齐 MT3 受控实验的
  "three evaluations per task" 是**不够的**,因其 1,000 任务规模而我们只有 ≥40 配置)。

### 7.3 对照与混杂控制(逐条注明来源)
| 对照 | 内容 | 来源 |
|---|---|---|
| **C1 五种假学习对照** | more attempts / familiar tasks / privileged info / luck / larger budget,各配一个 control | SEAR 2610.18792 Table 2 |
| **C2 best-of-n 重采样对照** | 排除"多试几次"造成的表观提升 | SEAR |
| **C3 任务顺序打乱** | 排除"默认顺序构成**隐式课程**"这一隐藏前提 | Fragility of Self-Improving Agents 2608.18066 逐字:"**shuffling the tasks**…Prior works often adopt default orderings that impose an **implicit curriculum**, acting as a **hidden prerequisite for success**" |
| **C4 泛化 tier** | T1-T5 分级报告(近迁移→远迁移) | SEAR |
| **C5 基线臂** | MT3 原样配置(D1=几何最近邻/D2=两段/D3=首帧位姿/D4=top-1 回放) | 本平台 P0 实测 |
| **C6 单体对照** | 不分 D2(单体),用于检验"分解是否真有必要" | MT3 原文的 MT-ACT+ 对照逻辑(**⚠️ 但 MT3 的 MT-ACT+ 要训练;我们免训练,故本对照须改为"不分段的检索式单体",不可直接引 MT3 数字**) |

### 7.4 统计方案
- ≥3 seeds(**⚠️ 若资源允许 ≥5**)+ 95% bootstrap CI + 置换检验;
- **SAGE(2609.36043)式**:per-item **配对**比较 + **one-sided paired test** + **否则弃权(abstain)**;
  **显式引用 SAGE 为方法来源**;
- **⚠️ Optimizer's Curse(SAGE 逐字指认)**:"the best observed score on a finite and noisy
  validation set is **upward biased**" → **报告"最优配置"时必须给偏差校正或至少显式声明该偏倚**;
- **⚠️ 检验力告警(L2)**:n≤4 时置换检验 p 下限 **0.125**,脚本须自动打印告警。

### 7.5 披露与可复现(P2 §14)
机器可读披露契约须含:seeds / traces / 全部预算(wall-clock+GPU-hours+tokens+推理预算)/
prompts 与 context / harness 镜像 + SHA256 / **evaluator ≠ generator 的独立性声明** /
**假设预注册**(P2 §16:"**Preregistration for AI-generated hypotheses**")。

## 要件 8 · 失败模式表 + 残余不确定性 + 安全提示

### 8.1 失败模式表(症状 → 可能原因 → 排查动作;**多数来自领域已实证的失效模式**)

| 症状 | 可能原因 | 排查动作 |
|---|---|---|
| **m_opt 持续改进但 m_blind 平/降** | **metric fixation / in-loop≠held-out**(P3 实测夸大 2.0-2.6 倍;2609.31760 在机器人域已实证) | 看 ρ^audit/ρ^blind(A6);若 ρ^blind<0.6,**以 m_blind 为准重写结论**;检查是否 agent 摸到了 m_audit(违反 §4.2 契约) |
| **语义簇数 C_t 掉 ≥50% / 机制熵 H_t 掉 ≥0.3 nats** | **algorithmic mode collapse**(P3:表面编辑多样性稳定但语义/机制级坍缩) | **⚠️ 升温不是解药**(P3 否定结果:"Increased proposer entropy does not…translate to increased semantic diversity");改用 P3 的 DAPS 类缓解(类别覆盖重加权 + 持久编辑记忆 + 验证门),**但须知 DAPS 也只到 ρ≈0.79 非 1.0** |
| **有用改动比例随轮次下降(如 70%→43%)** | **confidence cliff**(《Rehearse》2607.27687:前 2 轮 70% → 第 6 轮后 43%;选择性准确率 82.8%→56.9%) | **预设停止判据**(如连续 M 轮无 m_blind 改进即停),**不假定收益恒定** |
| **只看表面编辑多样性,没报警** | **表面多样性是坏的预警信号**(P3 逐字:"**Surface diversity is a poor warning sign**…Any monitor that watched only S_t would have raised no flag") | 必须同时监控 C_t/H_t/V_t,**不得只看 diff 多样性** |
| **dev/validation 上变好、test 上变差** | **信息性 validation 被过拟合攻破**(AdaRSI 自陈:"adopt a change that looks better on a few development scenes but **hurts on the test scenes**…CuttingToolSelection…**halves success at test**") | **这正是我们"无值 audit 层"要治的**;若仍发生,检查 audit 是否泄漏数值(§6.4 步骤 7 的标志) |
| **基础设施频繁崩(agent 大量轮次耗在修环境)** | **infrastructure fragility**(ICDM 2026 2609.30541 归纳的五大失效模式之一) | 先固化环境快照;把 crash 率记入 A7,crash 率 >20% 时暂停搜索先修基建 |
| **agent 忘记此前试过的配置、重复试** | **agent memory decay**(同上五大失效模式) | `results.tsv` 作为唯一事实源;program.md 要求每轮先读 tsv 尾部 |
| **搜索方向停滞(反复微调同一旋钮)** | **search-direction stagnation**(同上) | program.md 的 "think harder" 条款:组合此前 near-miss、试更激进的维度组合 |
| **不同配置的实验耗时差异极大,比较失真** | **iteration-cost asymmetry**(同上) | 固定墙钟预算(§7.2)+ A7 记账;**不得用固定步数替代固定墙钟** |
| **harness 被改(指标被动过)** | agent 越界 | 每轮校验 `frozen.sha256`;不符即 abort 并 revert |
| **`policy.py` 反向读取评测信号** | 泄漏(违反 §4.2 契约) | harness 的契约单测;违反判 crash + revert |
| **仿真结论被误当真机结论** | **sim2real 越界**(P1 逐字:"**Simulation evidence alone does not establish hardware safety**") | 所有结论**限定"仿真内"**;真机部分只写"须真人另行验证",**不得外推** |
| **兑换率网格拟合不出曲线(格子太稀/方差太大)** | 样本量不足或轴定义错 | 检查是否误把"自采经验/自身 rollout"当"专家演示"(§8 划界 D2/D3/D6);加 seeds 或降网格分辨率并披露 |
