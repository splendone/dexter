### §3.3 三增

#### A1 · `journal/entries.tsv` —— K1 记账口（**本件第一件交付物**）

**为什么放 `journal/`**：`journal/` 是产出，**制度预算 0 行**（§3.1）。

**列（7 列，TSV）**：

```
entry_id  date  source  one_line  status  used_in  ref
```

| 列 | 取值 | 说明 |
|---|---|---|
| `entry_id` | `E-YYYYMMDD-nn` | 一条一行，**永不复用**（承 G 编号纪律） |
| `date` | `YYYY-MM-DD` | 报出日 |
| `source` | `雷达` / `精读` / `主张卡` / `争点表` / `规格` / `稿件` / `外部委托` | 七类，封闭集 |
| `one_line` | 一句话 | **必须是一句话主张或一个问题**，不是标题 |
| `status` | `报出` / `被拒` / `已用于立项` / `已用于稿件` / `已用于规格` | 封闭集 |
| `used_in` | 空，或 `P1` / `CP4` / `G2-v1.1` / `争点表#3` | **K1 分子的唯一依据** |
| `ref` | 文件路径或 DOI | 可回查 |

**K1 计算（一条命令，写死在此，防口径漂移）**：

```bash
awk -F'\t' 'NR>1 && $5!="被拒"{d++} NR>1 && $6!=""{n++} END{printf "K1 = %d/%d = %.1f%%\n", n, d, (d?100*n/d:0)}' journal/entries.tsv
```

**口径三条（必须写死）**：
1. **分母含"被拒"以外的全部**——即"报出"的那些。被拒的**不入分母**（契约原文"报出条数"），但**仍须逐条入账**，因为它是"判断力"的唯一度量（`residue.md` §二原话）。
2. **`used_in` 非空即计入分子，不设 30 天窗口判定**——30 天窗口在评估时按 `date` 回算，不由填表人判断。
3. **自引不计入分子**（**建账当天实测发现的漏洞**）：`used_in` 若指向**报出该条目的同一件产物**，不计；须指向**另一件**。
   > 实测过程：本件建立 `entries.tsv` 时，7 条全部被本件自己引用了一次，按朴素口径算出 **K1 = 7/7 = 100%**。
   > **这正是本所最该防的自证**——一个能被自己刷满的指标不是指标。故首日实际记 **0/7 = 0.0%**。
   > **这条口径不是设计时想到的，是跑出来才发现的**；如实登记，因为它是本件唯一一条"由执行反推设计"的修正。

**写入义务**：`radar` 落盘时逐条追加；`deep-read` 出主张卡时追加；`goal-loop` 立项时回填 `used_in`。
→ 技能改动 **+4 行**（radar +2 / deep-read +2），由 **P-032** 提案。
