## 2. 候选比较(原两候选 A / B)

**原候选**(`goals.md` G2 与分图③④ 附注):

- **候选 A(透镜③)**:「三股力量(端到端 / 结构化分解 / agentic 程序合成)**同基准对撞**」的**评测协议**;
- **候选 B(透镜④)**:「**真机 vs 合成 vs 混合**」的**数据配比评测协议**。

### 2.1 三轴比较(定题门指定轴 + 两项工程轴)

| 轴 | A(三股力量对撞) | B(真机-合成-翻新配比) |
|---|---|---|
| **能力缺口明确度** | 中——"三股力量"是**抽象分类**,对撞的**具体判据**需再定义 | **高**——账本二分歧 1 / 透镜④开放问题 1:同策略同预算的真机 vs 合成受控对比**完全缺失**,且**不需新方法** |
| **可测量性** | 高(同基准同预算成功率) | 高(配比-成功率曲线,第三方可复跑) |
| **是否需委托人资源** | 低—中(**纯算力**) | 中(**数据采集硬件** + 算力) |
| **工程可落地(八项要件)** | **低**——纯仿真对撞**无硬件 → 缺要件 3(BOM / 接口)** | **高**——采集平台**有硬件、接口、软件栈** |
| **语料厚度** | 24 篇 / 6 路线 | **30 篇 / 6 路线(最厚)** |
| **与 Dexter 使命契合** | 中(评测方法论) | **高**(数据引擎 = 操作与灵巧手的**核心基建**) |

### 2.2 一个必须先讲清的**分类问题**(判断)

两候选的字面形态都是「**评测协议**」——而 `goals.md` **G4** 的目标产出明确列有
「**评测协议草案**」,且 G4 有**前置门**(未达成)。**纯评测协议没有硬件,要件 3
(BOM / 接口)无法满足**;直接作 G2 题,会产出一份"不像规格书"的规格书。

**化解**(二者不矛盾,只是**产出层级不同**):

- **协议**(远期、G4 产出)= "**该怎么测**";
- **平台 / 系统**(现期、G2 产出)= "**为了能测,先把台子搭起来**"。

→ 把题从「协议」**重框为「平台」**,即满足 G2 八项要件;平台跑出的数据**将来喂 G4**。
本件按此重框后定题。

### 2.3 择优

**B 胜出**(缺口更明确、有硬件可落地、语料最厚、契合使命)。
**A 不废弃**:降格为 B 平台**实验设计里的一个对照维度**(见 §4「配比结论」),
其"协议"部分**挂 G4**,待 G4 前置门达成后另行立项。

## 3. 选题依据

### 3.1 能力缺口在哪(带出处)

1. **采集贵**(透镜④路线 A):真机遥操作靠"硬件 + 人力"换数据——DROID 用 **50 名采集员
   × 12 个月**采到 **76k 轨迹 / 350 小时**;AgiBot World **>100 万条**但需**标准化产线**。
   → **低成本单点复现**是缺口。
2. **坏数据被丢**(透镜④路线 E,**本窗口新发现**):失败 rollout / 低精度 / 错配数据
   **默认被弃**——Kintsugi-VLA 证明**失败轨迹可转恢复数据**(恢复成功率 34.6% / 38.4%),
   ε4P 证明低精度 / 错配数据翻新可使真机亚毫米级任务 **+31.7 个百分点**。
   → **"回收"这条路尚未进入常规工程管线**。
3. **配比无据**(账本二分歧 1 / 透镜④开放问题 1):**没有**同策略同预算下
   真机 vs 合成 vs 混合的受控对比——**"边际投入该给采集还是给合成"目前只能拍脑袋**。
   这是本方向**最大的现成缺口,且不需要新方法**。

### 3.2 为什么是现在

1. **语料够了**:透镜④ **30 篇 / 6 路线**已逐条核实(全部数字 2026-09-30 重开 abs 页
   原始 HTML 复核,独立复核 0 修正);G1 四图齐,认识**可辩护**;
2. **硬件成熟**:ALOHA / Mobile ALOHA(**低成本双臂遥操作**)、UMI / PolyUMI
   (**手持夹爪 + 视触听**)**均开源**——低成本采集不再是从零造;
3. **新路线成型**:路线 E(翻新)、路线 F(异构语料)是**本窗口才成型的路线**
   ——"回收 + 对齐"正好可进管线;
4. **闸口已开**:G1 关闭(2026-09-30)→ G2 定题门条件 1 / 2 满足 →
   **现在正是把认识落成工程方案的时候**。

### 3.3 哪条路线更可能 work(分歧裁决)

| 分歧(出处) | 裁决 | 理由 |
|---|---|---|
| **真机 vs 合成**(账本二分歧 1) | **不做二选一,做"配比"** | 合成可用(MimicGen ~200 条人演→**50K+**;DexMimicGen 60→**21K**),但 Real-to-Sim-to-Real 警告"**便宜不等于无损**"(函数保持);**最优解是配比问题,不是站队** |
| **人演示 vs 遥操作**(透镜④分歧 2) | **首版以真机遥操作为主** | 遥操作**可复现、可控、许可清晰**;人演示(18,561 h Ego2Robot / >20K h InternW0-Δ)价值在**预训练规模**,留作**扩展模块** |
| **保真度必要否**(透镜④分歧 4) | **视任务而定** | 接触富集 / 软体 / 动态任务需**物理保真**(PhyVisGen 用 IPC);语言条件 / 长程可放宽到"**可行 + 校验**"(DREAM 用 TAMP) |
| **人-机对齐程度**(透镜④分歧 3) | **取最低成本对齐** | 若要人演示,先做**时序重定时**(EgoSpeedUp **+25 个百分点**)与**视觉对齐**,**不追全对齐**(全对齐要造配对管线,贵) |

### 3.4 与四透镜 / 使命的关系

- **主用透镜④**(数据采集与合成,30 篇)——本题的**主干**;
- **扩展模块用透镜②**(触觉):PolyUMI(视触听采集)/ UVTA(视触动捕)/ VisTacAlign
  (人-机逐模态对齐)/ 触觉 WAM 系(把触觉做进世界预测);
- **验收对标透镜①**(数据效率):ALOHA "**10 分钟演示 80–90%**";
- **策略基线用透镜③**(π0.5 锚点 / Diffusion Policy / VLA)。

## 4. 定题(决定)

> ### 题目
> **《桌面操作数据引擎实施规格——"真机采集 + 失败翻新 + 仿真合成"混合管线,及其配比验证》**
>
> ### 一句话
> 在**可控预算**下,搭一条**低成本桌面级操作数据生产线**(真机遥操作采集 → 失败数据
> 翻新 → 仿真合成增强),训练出**可部署的模仿学习策略**,并给出「**真机 : 合成 : 翻新**」
> **配比的可复现选择依据**。
>
> ### 能力问题
> 一台**低成本双臂(或手持夹爪)平台**,如何在**给定预算**内,用**混合数据管线**
> 学会**一组桌面精细操作任务**,并达到**可测的成功率**?
>
> ### 产出
> `designs/桌面操作数据引擎-规格书-v0.x.md`(八项要件)+ 附件
> (采集 rig 接口图 / 采购表 / 配比实验方案)。
>
> ### 核心 / 扩展
> **核心** = 低成本双臂夹爪采集 + 混合管线;**扩展模块(变体 B)** = **灵巧手 + 视触觉**
> (接透镜②,**契合 Dexter 使命**)。

### 4.1 验收判据草案(可测量;**目标值待与委托人校准**)

| 指标 | 定义 | 目标(草案) | 测量方式 | 锚点出处 |
|---|---|---|---|---|
| **策略成功率** | K 个桌面任务上的平均成功率 | 对标 ALOHA 口径(6 任务 **80–90%** @ 10 分钟演示) | 固定任务集 × 每任务 **50 回合** | ALOHA·ACT(2304.13705) |
| **数据效率** | 达到目标成功率所需真机演示数 | 每任务 **≤ 50 条**(对标 Mobile ALOHA) | 演示数-成功率曲线 | Mobile ALOHA(2401.02117) |
| **翻新增益** | "加翻新数据" vs "只用成功数据"的成功率差 | 等量数据下**不降**(理想为正;锚点 **+31.7 个百分点**) | 消融对照 | ε4P(2609.26672) |
| **配比结论** | 真机 : 合成 : 翻新 扫描曲线 | 给出"**边际投入方向**"的**可复跑曲线** | 固定策略 / 任务 / 预算扫配比 | 账本二缺口二 |
| **平台成本** | 采集 rig 硬件总价 | **待询价**(不得估数冒充) | 采购表 | design-spec §4 |
| **数据格式** | 与主流格式兼容 | 符合 **LeRobot / OXE** 标准格式 | 格式校验 | OXE(2310.08864) |
| **采集节拍** | 每小时有效轨迹条数 | **待实测** | 计时 | — |

**底线(不达标即失败)**:①策略成功率**不得低于同任务纯视觉 DP3 / DP 基线**;
②成本**不得超预算上限**(待委托人给上限);③数据格式**不兼容主流 → 直接不合格**。

## 5. 范围与不做(边界)

- **做**:平台构成、硬件选型 + BOM、接口、软件栈、实施步骤、验收判据、失败模式、
  安全提示、配比实验设计。
- **不做(硬边界)**:不采购、不付款、不动手制作、不跑真机实验、不投稿——**这些是真人执行**;
- **暂不做**:人演示规模化预训练(留扩展)、灵巧手全栈(留变体 B)、触觉仿真
  (透镜②开放问题 3,系领域空白)。
