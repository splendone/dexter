# 滚动重审规程(活文档纪律)

> 制度依据:委托人 2026-09-28 授权——黄色产物由 Dexter **自审签发**。
> 因无第二人会签,准确性靠**自我迭代**维持,而非一次性把关。
> 推论:**签发不是终点,是版本 1.0。**
> (2026-09-28 补:重审触发线细化为"按需为主 + 证据触发为辅",见 §1。)

## 1. 何时触发重审(两条触发线,按需为主)

**主触发线——按需(委托人设计)**:凡**实际要用到**某件结论时(写进新报告、
交给委托人、作为判断依据),先核一遍核心数字——**用到即核**。理由:本地
知识库随时间变丰富,后一次核查的证据基础强于前一次,"用到时再核"往往比
"当时核"更准。

**辅触发线——证据**:

| 触发 | 例 |
|---|---|
| 新证据同题 | 新论文/新基准数字直接对撞本件结论 |
| 原文更正 | 本件引用的论文出新版本(v2+)、勘误、撤稿 |
| 后续精读推翻 | 深读某篇后发现本件转述有误或口径不符 |
| 口径漂移 | 基准/数据集定义变化,使本件数字失去可比性 |
| 定期体检 | 每周五复盘:抽 1 件已签发产物做"证据是否仍成立"抽查 |

## 2. 重审动作(五步)

1. **定位**:打开本件 + 其引用的原始出处(abs 页/全文/官方页),**不凭记忆**;
2. **逐条比对**:只比**事实性断言**(数字、作者、机构、结论口径);判断另算;
3. **定级**:结论仍成立 / 需降置信度 / 需修正数字 / 需撤回结论;
4. **落笔**:改正文 → 升版本(v1.0→v1.1)→ 文末"重审记录"追加一节
   (日期 / 触发原因 / 改了什么 / 未解决什么);
5. **回流**:若触及 `knowledge/` 或争论账本,同步更新并注明"由 X 重审引起"。

## 3. 硬约束

- **外部交叉源硬规则(防自我确认循环)**:本地知识库**会被自己的错误污染**。
  若一件错误产物已进 `knowledge/`,后来的重审可能拿它当"已知事实"互证,
  形成**自我确认循环**。→ **任何重审的交叉源必须包含至少一个外部/原始来源**
  (原文 abs 或全文、官方页),**不得只靠本地库互证**。

  - **具体抓取法(2026-10-09 增,由 arXiv WebFetch 超时实况引起)**:
    WebFetch 对 `arxiv.org/abs/*` 常超时;**超时 ≠「无法核实」**,必须换路径实抓。
    默认命令:`curl -sL -o /tmp/abs-<id>.html -w "%{http_code} %{size_download}\n" https://arxiv.org/abs/<id>`,
    从原始 HTML 解析 title / authors / abstract **逐句核对**。
    **成功判据**(记入重审记录):HTTP 200 + 非空 body(arXiv abs 典型 40 KB+),
    记录字节数作为实抓证据。同一回退模式适用于仓库 README / LICENSE /
    datasheet / 官方页——**curl -sL 先行,WebFetch 兜底,Browser 处理 JS 渲染**。

  - **本地雷达记录不算外部交叉源(硬判据)**:子任务的雷达记录 / radar 输出 /
    当日 journal / `knowledge/` 卡片 / 文献地图 / `review-ledger.md` 条目——
    **都算「本地库」,即使内容是几分钟前从 arXiv 抓的**。理由:自我确认循环的
    关键不是"新旧",而是"是否**在本次重审的语境下独立取到**"——旧抓取可能
    已被同一错误污染(例:雷达记录已把「outperforms by 4.2pp」误抄成「4.2pp 成绩」,
    重审时拿它互证 = 循环)。**硬判据**:外部交叉源必须是**为本次重审独立发起的
    抓取**,URL + 时间戳 + HTTP 状态 + 字节数记入重审记录。

- **溯源可回指(2026-09-28 增,由 TP-Flow 溯源缺口引起)**:已签发产物内的每个
  事实性数字,必须能**回指到某条核实记录**(当日 journal / `knowledge/` 卡片 /
  账本条目)。产物声明的"语料边界"(如"22 篇已核实")必须可**逐条回指**——总图/
  分图类产物应配"**语料清单 / 回指表**"。凡列数字而查不到出处者,**视同"未证实"**,
  须补核或降级处理;**"报了却查不到出处"与"报错"对名誉是同类风险**。
- **不得静默修改**:任何改动必须在"重审记录"留下可追溯条目;
- **不得删除旧结论**:错的写在记录里(错在哪、为什么错),正文改对;
- 重审发现的是**自己的错** → 按宪法录 `honor.md`;
- 若错已随 `final/` 外流 → **必须**在记录首行标"⚠️ 已外流版本更正",
  并提请委托人注意(红色备料);
- **升级门**:若重审结论会**推翻已签发产物**(尤其可能已外流)、或属"影响
  巨大/高风险锚点数字/与委托人已有认知冲突/低置信度×高影响"→ **不自行
  定论**,列成"待委托人裁决"清单,附证据、选项与倾向。

## 4. 重审账本

维护 `knowledge/maps/review-ledger.md`:每件已签发产物的
版本 / 签发日 / 上次重审日 / 下次体检窗口 / 已知脆弱点。

## 5. 与验收测试的关系

本规程是"溯源测试"的延伸:一次把关只能证明"当时对",
滚动重审才能证明"**一直对**"。

## 6. 会签前自查复核(签发前;与重审互为表里)

> 重审管"签发之后",本节管"**签发之前**"。设计稿 / 分图 / 教程 / 规格书在
> **自审签发 v1.0 之前**必须过这一关(design-spec §6 的"独立子任务 + 外部交叉源")。

**两道,缺一不可**:

1. **独立子任务复核**(派一个**未参与起草**的子任务;不可自审自):
   - 给它①**待复核件** + ②**源真值清单**(本件数字应来自哪些文件:分图 / 卡片 /
     账本 / 许可核查表);
   - 令其:①**逐条比对全部量化数字**(转录核对);②**专查四类错误**——
     **数字-结论错配 / 不同轴并列 / 归属错 / 无源数字**;③**实抓入口 URL / 许可页**
     (外部原始来源);
   - 硬约束:明确告知它"**你未参与起草,不得信任草稿,只报你实际打开来源核到的**",
     且**不许改文件、不许重写**,只出发现清单。
2. **外部交叉源**(不得只靠本地库互证):至少一个**外部/原始来源**——
   仓库页 / 许可文件 / abs 页 / datasheet。
   **实抓方法与判据同 §3**(curl -sL 先行,WebFetch 兜底;超时必须换路径不得放弃;
   子任务雷达记录 / 本地 journal / knowledge 卡片**不算外部交叉源**,
   须为本次复核独立抓取,URL + 时间戳 + HTTP 状态 + 字节数记入复核记录)。

**收口**:发现的修正**并入** → 才可签发 **v1.0**;文末加"**复核记录**"节
(方法 + 结论 + 保留项),并登记 `knowledge/maps/review-ledger.md`。

**经验值**:独立复核若**报"0 实质错误"**,本身即一次检验(说明起草已内化
历史教训);但**仍要如实列出"保留项 / 待核项"**,不得把"没查到"说成"没问题"。
