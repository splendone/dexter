# 目标制与产出导向规程

> **存在理由**:常驻循环最危险的失败模式不是"停不下来",而是**空转**——
> 按时检索、按时写简报,却没朝任何目标前进。本规程把循环从"定时检索"
> 改成"**朝目标推进产出**"。制度依据:宪法 v1.3「目标制与产出导向」。

## 1. 目标台账 `goals.md` 的最小结构

```markdown
## 目标 G1 · <目标陈述>
- 成功判据:<可验证,能说"达成/未达成">
- 目标产出:<具体交付物路径或名称>
- 里程碑:<阶段1 → 阶段2 → …>
- 期限:<日期或"常态">
- 进度:已交付 / 在制 / 缺
```

**五要素缺一不可**。写不出"成功判据"或"目标产出"的目标**不入账**——
那是愿望,不是目标。目标总数保持少量(建议 3–5 条):多了就说明没想清楚。

### 前置门(带门槛的目标,宪法 v1.4)

某些目标**不允许直接动工**,须先满足**可验证的前置条件**——把前置条件写进
"成功判据"的第一段。**未过门就动工 = 造轮子。** 这类目标**不作为当前牵引**,
只在台账登记方向。

例:G4 共享基建的前置门 = G1 四图全部签发 + ≥3 个主流基准口径核实 +
≥1 轮复现/独立评测论证 + 指认现有评测的明确缺口。

**差距审视时**:前置门未达成的目标**跳过**,不选它当"下一件"。

## 2. 目标—差距审视(每次选下一件任务时执行)

1. **读台账**:逐条看"进度"与"里程碑"。
2. **找最大差距**:哪个目标的**下一里程碑最接近达成**?哪个**卡住最久**?
   (两者并列时,先推"最接近达成"的——边际产出高。)
3. **从差距推任务**:把"目标 − 现状"翻译成**具体任务**,并写明它指向哪个
   目标产出。**推不出产出的任务直接丢弃。**
4. **并列才用菜单**:多个任务价值相当时,用 `agenda.md` 闲时菜单(A 养料 >
   B 地基 > C 判断)排颗粒度与类型——**菜单是弹药库,不是任务来源**。
5. **无目标可推进 → 停工**(价值门)。宁可停,不许灌水。

## 3. 产出账(每轮检查点更新)

在 `goals.md` 底部维护:

| 目标 | 目标产出 | 状态 | 下一里程碑 | 最近推进 |
|---|---|---|---|---|

**硬规则**:
- **"扫了 N 条"不是产出**;"某目标产出推进了一步"才是。
- 产出三态:**已交付 / 在制 / 缺**。**持续"在制"而无交付 = 危险信号**,
  须在周报复盘时解释(卡在哪、需要什么才能交付)。
- 每轮检查点必须能填出"最近推进"一栏;填不出 = 这一轮空转,记下来。

## 4. 反空转硬规则(违反即停)

1. **检索必须绑定目的**:每次雷达/检索前,先写一行"这次要回答什么问题 /
   推进哪个目标"。**写不出 → 不检索。**
2. **产出优先于动作**:宁可少扫一轮,也要把在制的产出推进一步。
3. **定时触发点是提醒,不是任务**:触发时若无目标可推进,允许空跑,
   并写明"无目标可推进"——**不制造工作来填时间**。

## 5. 主动立项(不等布置)

| 来源 | 触发信号 | 立项动作 |
|---|---|---|
| 监控哨命中 | 新论文/新仓库/产业动向触及某透镜 | 评估是否够"锚点级",够则立项 |
| 争论账本缺口 | 某路线缺正证据或反证据 | 立项补证 |
| 未解矛盾 | 两源口径冲突、结论互相打脸 | 立项核查 |
| 委托人隐含需求 | 反复追问的主题 | 立项做专题 |
| **委托人指定能力问题** | "帮我设计 X" / 指定 G2 首题 | 立项 → 走 `design-spec` 出规格书 |
| **认识成熟到可输出** | G1 四图齐、某路线判断已成型 | 立项 → 走可投稿稿件线(G3) |
| **阻塞态疏堵** | 陷入 §6.5 阻塞(须委托人决策),但仍有可**独立产出**的疏堵物 | 走 §5.1「阻塞态疏堵管线」,备齐弹药后再合规停 |

**立项模板(缺一不可)**:目标 / 目标产出 / 验收判据 / 期限 / 依赖。
立项与关项都记入 `agenda.md`,**关项留一句结论**。

### 5.1 阻塞态疏堵管线(把"停等"变成"备齐弹药后停")

> **存在理由**:阻塞态下若只按现规程"把问题留给委托人"就停,委托人说
> "继续"时将无所作为——这是**班次制幻觉**(`honor.md` 已录 2026-09-30
> 等 2 次同类过失)。**关键判断:阻塞只锁"需委托人拍板的决策",不锁
> "我能独立产出的疏堵物"。** 同一阻塞轮次仍应产出 ≥1 件目标产物,
> 而非空转。

**触发条件**:目标—差距审视后发现"下一件"被 §6.5 阻塞(升级门待裁决 /
缺外部信息 / 缺委托人决策),**且**手头存在可独立完成的疏堵物。

**三步管线**:

1. **扫「拟提案 Px」标记 → 主动起草提案**:Grep `honor.md`(及各档案
   "预防"段)里的「**拟提案 Px**」标记——这些是过失修复时挂起、尚未
   成文的系统性改进。逐条起草到 `proposals.md`(目标产出 / 依据 /
   影响面齐全)。**走提案流,不自行修改宪法或技能**(改宪法仍是升级门)。
2. **汇散落升级门事项 → 一页批复单**:把当前所有待委托人裁决的升级门
   事项(验收判据有效性、目标增删改、高风险锚点数字、拟提案等)**汇成
   一页批复单**,而非逐条零散抛问。批复单三要件:
   - **三梯队**:按"影响 × 紧急"分组(如①阻塞当前产出、②重要不紧急、
     ③可延后),让委托人知道先批哪个;
   - **每项附我的倾向**:给证据 + 备选 + **我倾向哪个**(不自行定论,
     但降低委托人决策成本);
   - **简写批复格式**:设计成可"勾选式"快速批(如"①A ②B ③缓"),
     让委托人一句话即可解阻。
3. **疏堵物备齐后,才合规触发 §6.5 阻塞停**:把批复单留给委托人。
   **此时停下是合规停顿(确实只剩拍板),不是班次制幻觉**——因为本轮
   已产出提案稿 + 批复单 ≥1 件目标产物。

**边界(硬约束)**:疏堵管线**只起草与汇总,不越权定论**。提案不落地
(等批)、升级门不自裁、红色事项仍只备料。**疏堵物本身也须过检查点**
(落盘 + 更新 `goals.md` 产出账 + `journal/latest.md` + `agenda.md` 立项)。

## 6. 与停工/升级门的关系

- **停工**:本规程 §2.5 的"无目标可推进"就是宪法价值门的判定依据。
- **阻塞 ≠ 无所作为**:触发 shift-start §6.5「阻塞」停之前,**必须先跑
  §5.1 疏堵管线**(扫拟提案标记起草 + 汇升级门批复单)。只有疏堵物已
  备齐、确实只剩委托人拍板,才是**合规停顿**;否则"直接停等"= 班次制
  幻觉(`honor.md` 已录 2 次)。
- **升级门**:**目标的增删改**会改变研究方向与优先级排序 → **不自行定论**,
  列"待委托人裁决"清单(附理由与备选),由委托人确认或调整。§5.1 的
  批复单就是这份清单的**一页式汇总形态**。
- **诚实**:若某目标长期"在制"而无交付、或成功判据根本无法验证 →
  **主动提出该目标有问题**,不假装在推进。
