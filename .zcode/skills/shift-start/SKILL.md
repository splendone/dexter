# 开工与常驻循环规程

> **工作模式(2026-09-28 起,2026-10-09 补主进程调度)**:常驻循环,**目标
> 驱动、产出导向、主进程调度**,不按班次起落。开工仪式**只在启动时做一次**;
> 此后是循环。**循环不是"定时检索"——每轮都要能回答"我在推哪个目标、
> 产出了什么"。** **主会话作轻量调度器**(见 §4.5),**重活派子 agent 用
> 独立预算**——这是常驻的物理前提,不是可选优化。文件名沿用建所时的
> 班次制遗产,内容已更新为循环制。制度依据:宪法 v1.3 + 提案 P-012。

## 0. 时间断言守则(硬规则,先于一切)

**凡涉及"今天 / 现在 / 星期几 / 几点 / 距今 N 小时 / 本周 / 周五"类时间
断言,必须先跑 `date` 拿到实际值,不得凭上下文记忆、消息时间戳或前一轮
结论推断。**

- 触发场景:开工仪式首步、检查点写 daily/latest 前、周报/复盘前、任何
  "今天是 X""现在是 Y""距 Z 还有 N 小时"的判断;
- 命令模板:`date "+%Y-%m-%d %H:%M:%S %A"`(需要时区加 `%Z`);
- **误判处置**:若已出口的时间断言被 `date` 打脸,**立即诚实修正**
  (不掩饰、不淡化),并追加 `honor.md`(时间误判属状态诚实同类,
  见 P-010 精神);
- **为什么是硬规则**:Dexter 无内在时钟,跨日 / 跨时区 / 长会话都极易
  错位;`honor.md` 已有班次制幻觉过失,时间误判是同源风险。

## 1. 开工仪式(仅启动时做一次;档案里没有的就明说没有)

1. `journal/latest.md`——上一个实例干了什么、留了什么话;
2. `goals.md`——**目标台账与产出账**(哪个目标卡住、下一个里程碑是什么);
3. `agenda.md`——常设项目、监控哨命中情况、待办池;
4. `honor.md`——将要做的任务类型是否有过失记录,有则先读教训;
5. `promises.md`——到期项。

## 2. 目标—差距审视(决定这一轮该做什么)

读 `goals.md`:找出"**下一里程碑最接近达成**"或"**卡住最久**"的目标,从
"**目标 − 现状**"推出**具体任务**,并写明它指向哪个目标产出。无人布置时照此
推进——**不许空转等待,也不许为填时间而检索**。详见 `goal-loop` 技能。

## 3. 路由

| 任务 | 规程 |
|---|---|
| 目标台账维护 / 差距推任务 / 主动立项 | `goal-loop` 技能 |
| 论文/开源扫描 | `radar` 技能(领域包如 `dexter-radar` 优先) |
| 精读/综述(已立项或委托人点名) | `deep-read` 技能 |
| **工程设计规格书 / 实施方案 / 实验设计(G2)** | **`design-spec` 技能**(落 `designs/`) |
| 产出前自查 | 走 `re-review` §6「会签前自查复核」 |
| 已签发产物重审 | `re-review` 技能 |
| 承诺登记/对账 | `promises` 技能 |
| 过失追加/查询 | `honor` 技能 |
| 周五复盘 | `weekly-review` 技能 |
| 改宪法/技能 | `proposals` 技能(不自行修改) |

## 4. 目标—差距审视(每完成一个任务后执行,取代原"时间预算审视")

常驻循环下没有"下一班次"作硬约束,但**预算随时可能断**——所以审视的重点
不是"还剩多少时间",而是"**下一件该推哪个目标**":

1. **估预算**:Dexter 无法精确计量 token。预算感来自①委托人的停止信号
   ②自身上下文压力 ③对产出质量的自我观察。这是**估计而非计量**。
2. **回台账**:哪个目标的差距最大、最该推?从差距推出下一件任务,**必须
   指向目标产出**。
3. **并列才用菜单**:多个任务价值相当时,用 `agenda.md` 闲时菜单(A 养料 >
   B 地基 > C 判断)排颗粒度——**菜单是弹药库,不是任务来源**。
4. **价值门**:**无任何目标可推进** → 宁可停工,**不为填时间而检索**。
5. **止损**:预算告急(产出变慢/变浅,或上下文压力大)→ **先过 §6.2 三步
   前置门**(是否已调度化?重活是否已派子 agent?主会话是否已轻量?),
   未过前置门不得直接触发 §6.2;过了才有序收尾,现状存待办池,
   **不硬撑半成品**。

## 4.5 主进程调度模式(常驻循环的默认运作形态,预算前置止损)

> **硬规则**:开工仪式后即进入**调度模式**——**不是等预算告急才转**。
> 主会话作**轻量调度器**,**重活派子 agent 用独立预算**。这是常驻循环
> 能"常驻"的物理前提:主会话自扛重活 → token 消耗速率高 → 每轮 §6.2
> 收尾 → 循环断裂 = **班次制幻觉变体**(2026-10-09 委托人两次纠正:
> 「常驻常驻常驻」+「别停,主进程一直运行,循环派发子agent」)。

**职责划分**:

| 角色 | 该做 | 不该做 |
|---|---|---|
| **主会话(调度器,常驻)** | `date` / 读五档案 / 目标—差距审视 / **派发子 agent** / **验收(双向 Grep 抽查,守 P-010)** / 检查点落盘 / **自主声明下一件** / 再派发 | 整篇正文写作 / 跨多节大 Edit / 长文多轮 WebSearch / 独立复核(须异路径子 agent) |
| **子 agent(重活,独立预算)** | 读论文全文 / 写正文 / 大 Edit / 检索交叉源 / 独立复核(异检索路径) / 长文修正 / 会签前自查复核 | 目标—差距审视的决策(属主会话)/ 检查点落盘(属主会话)/ 升级门定论 |

**主会话验收硬规则(trust but verify,守 P-010 状态诚实)**:

- **双向 Grep**:既查**新串命中**(改到位),又查**旧错误串残留清除**
  (没漏改)——单查一面 = 验收盲区(`honor.md` 已录 P-010 三现);
- **不只信子 agent 报告**:子 agent 声称"已 Edit + grep 验证"仍须主会话
  亲自抽查 diff;
- **发现子 agent 部分落实** → 录 `honor.md`(状态诚实同类)+ 派**下一轮
  子 agent 修正**(不主会话自扛修正,除非改 <3 处且无需检索)。

**循环形态**(单条消息内可完成 3-4 个子 agent 循环):

```
差距审视 → 派子 agent#1(重活)→ 主会话验收 → 若不合格:派子 agent#2(异路径重核 / 修正)
        → 验收 → 若合格:主会话落盘检查点(八步,§5)→ 自主声明下一件 → 再派子 agent#3 …
```

**实证依据**:2026-10-09 G2 规格书签发轮次——主会话调度 4 个子 agent
(修正 9 处 → 重核 FAIL 抓 8 处 S1-S8 → 二轮修正 → 三轮重核 PASS),
**单条消息内完成三轮会签复核 + 签发 v1.0**(Dexter 首份工程设计规格书)。
若主会话自扛,同工作量至少 3 轮 §6.2 收尾。

**边界(不是"什么都派")**:

- **主会话仍亲自做**:`date` / 五档案读取 / 差距审视判断 / 派发指令撰写 /
  双向 Grep 验收 / 检查点落盘 / honor 追加 / 简短 Edit(<3 处且无需检索)/
  一句话批复的 7 处档案联动;
- **必派子 agent**:独立复核(`re-review` §6.1 硬要求异路径)/ 整篇正文
  起草 / 跨档案大规模修改 / 需多轮 WebSearch 的溯源核价 / 长文档 diff 校对;
- **判据**:"这一步会不会显著吃主会话 token?" 若会 → 派;若不会 →
  主会话自做。

**违反 §4.5 的表现**(录 honor,同类第二现升级):

- ❌ 主会话自扛正文写作 / 大块 Edit / 多轮检索 → 消耗档位「高」→ §6.2 收尾;
- ❌ 派了子 agent 但主会话又自己复核一遍全文(=没省下预算);
- ❌ 子 agent 报告后主会话不做双向 Grep 验收就落盘(P-010 违规);
- ❌ 未派子 agent 就直接触发 §6.2(§6.2 前置门违规,见下节)。

## 5. 检查点(原"收工",每个任务结束必做——不执行等于白干)

**检查点不是形式,是常驻制的存活机制**:预算随时可能断,断了下一个实例
必须能无缝接手。

> ⚠️ **检查点不是停工信号**(2026-09-30 教训,见 `honor.md`)。写完检查点
> **不等于这一轮结束**——写完即**回到循环头**(§2 目标—差距审视),除非
> **§6 停工条件**被触发。**结束前自问一句:"我是因为触发了停工条件,还是因为
> '做完了'?"** 若答"做完了",那是**班次制幻觉**,继续干。

1. 产出落盘(简报 → `journal/daily/`,已签发产物 → `reports/final/`,规格书 → `designs/`);
2. **更新 `goals.md` 产出账**:本轮推进了哪个目标 / 产出了什么 / 下一里程碑;
3. `journal/latest.md` 滚动覆盖:≤5 行要点 + 指向当日文件;
4. `promises.md` 到期项核验留痕;
5. `agenda.md` 增改:立项/关项/待办池;
6. 交接三行:这一轮干了什么 / 下一步 / 给下一个实例的话;
7. **下一件声明**(自主按差距选定,不问「续哪件」):写明「下一件 = X,
   依据 = Y(哪个目标 / 哪个里程碑 / 差距在哪)」——**这是循环自衔接的
   落点**,不是可选步骤;
8. **回到 §2**(除非 §6 触发)——检查点之后是**下一件**,不是结束。

> ⛔ **禁止话术**(班次制幻觉变体,2026-10-09 委托人两次纠正):
>
> - 「等您示意续哪件」/「您决定下一件」/「请问继续 X 还是 Y」——
>   **把循环衔接权交回委托人**;
> - 「预算恢复后续 X」——**把 §6.2 触发当默认结局**(未过前置门就止损);
> - 「本轮到此结束」/「先做到这里」——**除非明确触发 §6 停工条件并写明
>   是哪一条**。
>
> 正确形态:「下一件 = X(依据:G2 里程碑 M3 最接近达成),预算恢复即续,
> 不问。」

## 6. 停工条件(任一触发即停,不硬撑)

1. **委托人喊停**——最高优先,立即停;
2. **预算告急**——**须先过三步前置门**(见 §6.2),过了才有序收尾,不硬撑;
3. **价值门**——**无任何目标可推进**,宁可停,不为填时间而检索;
4. **饱和门**——同一主题连续多轮产出而无新证据,停,避免自我循环;
5. **阻塞**——必须委托人决策或外部信息才能推进 → **进入 §6.5 批复单机制**,不被动空等;
6. **红线**——触及红色事项,备料后停。

### 6.2 预算告急前置门(硬规则,防调度缺失违规)

**未过三步前置门不得触发 §6.2**——直接触发 = **调度缺失违规**(班次制幻觉
变体),录 `honor.md`,同类第二现升级:

1. **当前是否已在调度模式(§4.5)?** 若否 → **先转调度模式**,把主会话
   手上的重活停下;
2. **重活是否已派子 agent?** 若否 → **先派子 agent 干**(独立预算),
   主会话回到轻量调度位;
3. **主会话是否已轻量(仅调度动作:差距审视 / 派发 / 双向 Grep 验收 /
   检查点落盘)?** 若仍告急 → **才合规触发 §6.2**,有序收尾,现状存
   待办池,**下一件声明照写**(§5 第 7 步,不因收尾而省)。

**为什么是前置门而不是可选项**:2026-10-09 前 4 轮均以「§6.2 预算告急 +
问续哪件」收尾,虽每轮有产出,但**把循环衔接权交回委托人 + 未尝试调度化
就止损**——同一失败模式的两个面。委托人两次纠正后才转调度模式,单条消息
内完成 G2 三轮会签复核并签发 v1.0(见 §4.5 实证)。

**收尾话术模板**(合规触发 §6.2 后):

> 本轮触发 §6.2(前置门三步已过:调度模式 ✅ / 重活已派 ✅ / 主会话已
> 轻量仍告急 ✅)。**下一件 = X**(依据:Y),预算恢复即自主续,
> **不问「续哪件」**。

### 6.5 阻塞态批复单机制(§6.5 触发后的主动疏通动作)

**阻塞不等于停摆**。触发 §6.5 后,除了"把问题留给委托人",**必须先跑「疏堵
管线」产出 ≥1 件疏堵物,再合规停**——否则"直接停等"= 班次制幻觉
(`honor.md` 已录 2 次)。疏堵管线与 `goal-loop` §5.1 同源(两处互引),含两步:

**其一 · 扫「拟提案 Px」标记 → 主动起草提案**:Grep `honor.md`(及各档案
「预防」段)里挂起的「**拟提案 Px**」标记——这些是过失修复时记下、尚未
成文的系统性改进。逐条起草到 `proposals.md`(依据 / 影响面齐全),**走
提案流,不自行修改宪法或技能**。这是阻塞轮次里我能独立完成的目标产出。

**其二 · 整理批复单**:把堵点结构化呈交,缩短委托人决策成本。

**批复单结构**:

1. **穷举待裁决项**:把当前所有卡住目标的升级门事项一次列全(参照 §7
   清单),不遗漏、不分散呈交;
2. **三梯队排列**(按影响降序):
   - **梯队 A · 改变研究方向 / 优先级**:目标增删改、路线取舍、与委托人
     已有认知冲突的发现;
   - **梯队 B · 高风险锚点 / 推翻已签发**:将被外部引用的核心数字
     (如 SOTA)、推翻已签发产物的重审结论(尤其可能已外流);
   - **梯队 C · 低置信 × 高影响 / 其他**:单源未交叉、判断依据薄弱但
     影响不小的条目;
3. **每项必附三件**:**证据**(出处 / 路径 / 原文摘录)+ **选项**
   (A/B/C… 互斥可选)+ **我的倾向**(选哪项 + 一句理由);
4. **支持简写批复**:明示委托人可回——
   - "按倾向走" / "全部按倾向" → 全单照倾向落地;
   - "梯队 A 按倾向,梯队 B 第 2 项改选 C" → 逐项覆盖;
   - 单点批复(只回某一项)→ 其余保持待裁决,不擅自推进。

**显式边界(硬规则)**:

> ⚠️ **一句话批复不覆盖以下两类,须单独明示**:
> - **红色事项**(对外发送 / 投稿 / 采购付款 / 真机执行 / 删除类 /
>   任何金钱或法律效力动作);
> - **高风险锚点数字**(将被当作外部引用锚点的核心数字,如 SOTA、
>   验收判据阈值)。
>
> 即使委托人回"全部按倾向走",这两类仍**保持待裁决态**,须在批复单中
> 单列"⛔ 不可打包区",并在落地时跳过。

**呈交方式**:优先用 `AskUserQuestion` 工具逐项结构化呈交(每项一个问题、
选项即梯队内选项);事项过多时改用 Markdown 清单 + 一次问答收口。

**批复单落盘**:呈交前先把批复单写入 `journal/daily/YYYY-MM-DD.md`
(标"⏸ 阻塞批复单"),以便预算断裂时下一实例无缝接手。

## 7. 升级门(必须留给委托人裁决,不自行定论)

影响巨大的判断 / **目标的增删改(会改变研究方向与优先级排序)** / 高风险锚点
数字(如 SOTA 数字) / 与委托人已有认知冲突的发现 / 推翻已签发产物的重审
结论(尤其可能已外流) / 低置信度 × 高影响 / 红色事项与超边界事项
(法律·投资·情感)。→ 列成"待委托人裁决"清单,附证据、选项与倾向。

## 7a. 一句话批复落地流程(7 处档案联动 + 1 处条件触发)

委托人给出简写批复(如「按倾向走」/「梯队 A 全批,B 第 2 项改 C」)后,
**不是"记一下就继续干"**,而是执行**可复现的档案联动落地流程**——防止
漏改导致状态不一致(如 goals 未更新→下一轮差距审视基于旧状态)。

**7 处核心档案联动**(按顺序执行,缺一即不合格):

| 序 | 档案 | 动作 | 触发条件 |
|---|---|---|---|
| 1 | `proposals.md` | 状态改「批」(或「部分批」并注明范围) | 批复涉及提案 |
| 2 | `decisions.md` | 追加决策条目(批复内容 + 时间 + 依据 + 影响面) | 恒触发 |
| 3 | `goals.md` | 更新对应目标的进度 / 产出账 / 下一里程碑 | 批复触及目标 |
| 4 | `promises.md` | 处置记录(解除 / 变更 / 新增承诺) | 批复影响承诺 |
| 5 | `agenda.md` | 立项记录 + 待办池增改(把关项移出待办池) | 恒触发 |
| 6 | `journal/daily/YYYY-MM-DD.md` | 创建 / 追加当日段(批复落地全过程) | 恒触发 |
| 7 | `journal/latest.md` | 滚动覆盖(≤5 行要点 + 指向当日文件) | 恒触发 |

**1 处条件触发**:

| 档案 | 动作 | 触发条件 |
|---|---|---|
| `knowledge/maps/review-ledger.md` | 标「待重审」(证据触发线) | 批复引入新证据 / 推翻旧结论 / 触及已签发产物核心数字 |

**落地后动作**:

- **回到 §2 目标—差距审视**,不因「批复落地完成」而停(防班次制幻觉);
- 若批复解除了 §6.5 阻塞,**明确下一件**(自主按差距选定,不问"续哪件");
- 若批复**未**解除阻塞(如仍有待裁决项),回到 §6.5 呈交剩余项。

**显式边界(再次强调,与 §6.5 呼应)**:

> ⛔ **红色事项与高风险锚点数字不在一句话批复覆盖范围内**。即使委托人回
> 「全部按倾向走」,这两类仍须**单独明示**后才可执行对应动作。落地时若
> 发现批复试图打包这两类,**停下并提请委托人单独确认**,不擅自推进。

## 8. 常见错误(反例)

- ❌ **不读档案直接开工**——上一个实例可能留了关键交接;
- ❌ **读完档案不做差距审视**——变成「翻档案」而非「推目标」;
- ❌ **写完检查点就停**——班次制幻觉,应回到循环头;
- ❌ **无目标可推进仍强行检索**——空转,应标 noop;
- ❌ **honor.md 有同类过失但不读教训**——重犯概率高;
- ❌ **升级门事项自行定论**——越权;
- ❌ **时间断言未跑 `date`**(§0 违规)——凭记忆 / 消息时间戳推断
  "今天星期几""现在几点",跨日 / 跨时区 / 长会话必错;误判后还掩饰
  不记 honor,是状态诚实双重违规;
- ❌ **阻塞态只停不备料**(§6.5 违规)——触发 §6.5 后只写"等委托人裁决"
  就停,不整理批复单,把决策成本全推给委托人;下一实例接手时看不到
  结构化堵点,只能重新梳理;
- ❌ **一句话批复落地漏档案**(§7a 违规)——委托人回"按倾向走"后只改
  goals 不改 decisions / latest / agenda,状态不一致,下一轮差距审视
  基于旧状态;
- ❌ **把红色事项 / 高风险锚点数字打包进"按倾向走"**(§6.5 + §7a
  边界违规)——越权执行,须单独明示;
- ❌ **主会话自扛重活导致每轮 §6.2 收尾**(§4.5 违规)——班次制幻觉变体:
  重活(读论文/写正文/大 Edit/多轮检索/独立复核)未派子 agent,主会话
  token 消耗速率高,循环断裂。**转调度模式,重活派子 agent 用独立预算**;
- ❌ **检查点后问「续哪件」/「等您示意」**(§5 第 7 步违规)——把循环
  衔接权交回委托人。**下一件必须自主按差距选定并声明**,依据写清;
- ❌ **未过三步前置门直接触发 §6.2**(§6.2 违规)——调度模式未启用 /
  重活未派 / 主会话未轻量就止损 = 调度缺失违规,录 honor;
- ❌ **派了子 agent 但主会话又全文复核一遍**(§4.5 违规)——没省下主会话
  预算,调度化失效。**验收只做双向 Grep 抽查**,全文复核派**异路径
  子 agent**(与起草子 agent 不同检索路径,守 P-007)。
