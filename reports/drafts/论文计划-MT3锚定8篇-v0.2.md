## 0. 一句话结论

**硬件清单解锁了"真机实验"这条路,但只解锁了三条半,不是四条。**
八篇全部锚定 MT3、全部是实验型,在 14 天内**物理上做不到**——除非四篇不依赖新真机数据。
所以本计划的结构是:

> **4 篇零新真机数据(写作 + 仿真)+ 4 篇真机实验(Sawyer + 3 相机,Realman 不参与)**
> = 8 篇;两波投出(10-24 三篇 / 10-31 五篇)。

**四条 MT3 自陈缺口,本月覆盖三条,触觉那条缺硬件、跨本体那条只有 1 台 Realman——
这两条必须写在论文的 limitation 里,不能用"视觉闭环"冒充触觉。**

## 1. 硬件清单改变了什么

| 资源 | 数量 | **解锁了什么** | **没解锁什么(必须写进 limitation)** |
|---|---|---|---|
| **Sawyer** | 2 台 | MT3 的**原生平台**(MT3 就是 Sawyer),复现**零适配**;双臂可并行跑试验 | 无。这是本计划最大的底气 |
| **Realman** | **1 台** | 跨本体(路径 1A)可做**单目标迁移** | **跨本体"泛化"做不了**——n=1 目标本体,只能声称"可行性 + 误差归因",不能声称"泛化到新本体"。**原方案按 2 台规划,现降级** |
| **RealSense** | 3 个 | 多视角消融(路径新增 P6)、**视觉闭环**(替代触觉做执行监测) | 视觉**看不到力/滑移/接触状态**——"形变物体、高精度插入"这两类失败**视觉救不了** |
| **触觉传感器** | **0** | — | **透镜② 全线下线**:2A(触觉闭环)/2B(阶段级触觉消融)/2C(触觉进检索度量)**本月全部不做**,亦不进八篇 |
| **4090 + 算力** | 有 | 仿真对撞(P3/P4)可与真机实验**并行**,不抢机械臂 | 无 |

### 1.1 三条硬结论

1. **触觉不是"晚点做",是"没有就不做"。** 缺触觉硬件时硬写触觉论文 = 编造。
   本计划用 **P5(视觉闭环)** 攻"开环无纠错"这条缺口,并在文中**明写**:
   "本文提供的是视觉闭环,不回答触觉的边际价值问题。"——**不许冒充**。
2. **Realman 只有 1 台,跨本体那篇的主张必须缩小。** 从"跨本体泛化"缩到
   "**单一目标本体上的零样本迁移可行性**"。审稿人一定会问 n=1,与其被问,不如自陈。
3. **MT3 是免训练检索,这是 14 天能出真机数据的唯一原因。** 没有策略训练,
   单次试验 = 位姿估计 + 检索 + 回放,约 1–2 分钟。**400 试次/臂/2 天**是可行的;
   若换成 VLA 微调,同样实验量要 3 周。**本计划的可行性完全建立在"免训练"上。**

## 3. 架构:一次母实验 M0,八个独立 treatment

**这是本计划能否成立的关键,也是唯一能同时做到"8 篇"和"不切香肠"的办法。**

### 3.1 为什么必须共享 M0

八篇若各建各的任务集、各采各的演示、各用各的评分协议,则:
① 结论不可比(这正是本所综述指认的"对撞缺席"病);
② 实验量 ×8,14 天绝对做不完;
③ 每篇都要重复"基线是多少",浪费篇幅。

**共享 M0 是标准的实验室测试床做法,不是切香肠。**

### 3.2 M0 的内容(10-18 ~ 10-20,三天)

| 项 | 内容 | 冻结后 |
|---|---|---|
| 任务集 | **20 个日常操作任务**(从 MT3 的 1,000 任务里按可复现性 + 失败率分层抽) | **不得中途增删** |
| 演示 | 每任务 **1 条**成功演示(MT3 的 1-shot 设定),Sawyer 双臂各采一遍 | 不得重采(重采须记录并重跑全部) |
| 评分 | 二值成功 + 阶段级(alignment 成功/ interaction 成功)+ 失败归因 7 类 | 不得事后改判据 |
| 标定 | 3 个 RealSense 的内外参 + 工作空间手眼标定 | 一次标定,全程复用 |
| 基线 | MT3 原版检索(单通道几何 + 解析式 alignment) | 作为**所有篇目的共同对照** |

### 3.3 八篇的数据边界(硬规则,写进每篇的独立性声明)

> **共享 M0 合法;共享 treatment 数据非法。**

| 篇 | 用的是 | **不得使用** |
|---|---|---|
| P1 | 只有 M0 | 任何 treatment 数据 |
| P2 | M0 + treatment A(双通道检索) | B / C 的试次 |
| P5 | M0 + treatment B(视觉闭环) | A / C 的试次 |
| P6 | M0 + treatment C(多视角配置) | A / B 的试次 |
| P3 | 公开数据 + 仿真,**完全不用 M0** | M0 与任何 treatment |
| P4 | 纯仿真,**完全不用 M0** | M0 与任何 treatment |
| P7 | M0 的**协议层**(不分析 treatment) | treatment 结果 |
| P8 | 文献 + M0 的设定描述 | treatment 结果 |

**P1 是唯一"只吃 M0"的篇**——它测的是基线本身。这也是它能最早投出的原因。

## 9. 诚实清单(我不建议做的事)

1. **不建议把触觉写成"视觉触觉"或"准触觉"。** 没有力/滑移信号就是没有。P5 是视觉闭环,
   文中必须写明它不回答触觉问题。
2. **不建议用 1 台 Realman 声称"跨本体泛化"。** n=1 只能叫"单目标迁移可行性"。
   写大了,审稿人一问就崩,且属证据纪律问题。
3. **不建议八篇同时投、且都在摘要里强调"基于 MT3"。** 应错开投出时间,并在每篇
   显式声明系列关系(G7)。**透明比隐藏安全**:被审稿人发现"同批八篇同源"而作者未声明,
   比主动声明严重得多。
4. **不建议为了凑 8 篇把 treatment 数据跨篇复用。** §3.3 的表是硬规则,不是建议。
5. **不建议本月承诺"录用"。** 只承诺"投出"。

## 10. 自我评估

- **确定性**:P1/P7/P8(波一)**高**——它们不依赖 treatment 数据;P3/P4(仿真)**中高**;
  P2/P5/P6(真机)**中低**,全部押在"harness 通 + 实验排得开"两件事上。
- **最大风险不是写作,是 §8-①**。若 MT3 harness 不存在,本计划的真机部分**整体失效**,
  不是延期,是换题。
- **本计划相对 v0.1 的真实改进**:主线统一(MT3 四条改造线)、硬件用上了、
