## 1. 表述（G\*）

### 1.1 陈述

> 在给定的任务分布 **D** 与本体集合 **E** 上，使
>
> **G\* = lim ( 人类投入 / 新增可用任务数 ) → 0**
>
> 约束 ①：新增任务成功率 ≥ **τ**（τ 由部署场景给定，不是论文自定）
> 约束 ②：失败必须**可归因**（给定同一失败，能指出是哪一段、哪一类原因）

**"可用任务"的定义**：在 D 中抽样、由第三方按预先登记的协议评定为成功、且**不依赖该任务的专属人类介入**的任务。

### 1.2 为什么每条都必要（缺一条就被钻空子）

| 缺哪条 | 会退化成什么 | 领域里的现成例子 |
|---|---|---|
| 缺"人类投入"作分子 | 变成"能力水平"目标 → 规模买断，边际成本不变 | 数据一多分数就涨，但每个新任务仍要一条演示 |
| 缺"新增任务数"作分母 | 变成"总能力"目标 → 报绝对数，不可比 | 各报各的任务数（RoboDojo 已出现 7 倍口径分裂） |
| 缺约束①（成功率下限） | **最优解是"什么都不做"**——边际成本为 0 | 退化任务的"一万个小任务" |
| 缺约束②（可归因） | 靠"随机成功"降成本，不可控、不可修 | 只报成功率、不报失败结构 |
| 缺定义域 D / E | 任何数字都不可比 | "跨本体"在 n=1 时也被写成泛化 |

### 1.3 反例检验（这个定义会不会把好东西判成坏东西）

- **超人类精度/力/速度**（0.01 mm 拧紧、50 kg 搬运）：D 由部署场景定义，**不受"人类能做"限制** → 不被排除。✅
- **危险环境、非人形本体**（飞行、水下、多臂）：E 显式给出 → 不被排除。✅
- **纯理论工作**（无新任务、无人类投入）：G\* 对它**不适用**（不是判它坏，是判它不属于这条线）。⚠️ 这是本定义的边界，须写明。
- **一次性的高价值任务**（如航天装配，只做一次）：G\* 的"新增任务数"≈1，无意义 → 该场景用另一套判据（可靠性/代价）。⚠️ 同上。

> **所以 G\* 不是"唯一目标"，是"可规模化的那条线上的目标"。** 把它当唯一目标会误伤单件高价值场景——这一点必须写在引用它的每一篇论文里。

## 2. 为什么"无歧义"这么难：四种常见表述的歧义在哪

| 常见表述 | 歧义点 | 性质 |
|---|---|---|
| "让机器人像人一样做任何事" | 宾语无边界（"任何事"）；"像人"指**形态**还是**能力**未定 | 口号 |
| "实现 AGI 的物理载体" | 借用了一个**本身未被定义**的术语，不可测 | 借词 |
| "让机器人替代人类劳动" | 经济目标（成本/就业），与能力目标混谈 | 错层 |
| "用一条示范学会新任务" | **手段冒充目的**——这是 MT3 的目标，不是领域的目标 | 降格 |

**判据**：一个表述若**说不出"什么情况下它没达成"**，它就是口号，不是目标。
用这一条筛，上面四条全不过：**它们都没有失效条件**。

**G\* 的失效条件（可反驳性）**：若存在某个方向，使 G\* 最大化却导致领域公认的坏结果（例：库无限膨胀导致检索退化、或成本降到零但系统完全不可维护），则 G\* 需修（加约束③：维护成本上限）。**目前我未找到这样的反例，但这不等于不存在。**

## 3. 怎么得到这个目标（方法，以及方法的边界）

### 3.1 三步法

| 步 | 做什么 | 产出 | 证据强度 |
|---|---|---|---|
| **S1 宣称层** | 系统抽样"目标陈述"类文本：综述的 intro/结语、position paper、benchmark 的 motivation、国家级项目指南 | "领域说自己要什么"的**主题编码表** | 中（文本明说） |
| **S2 激励层** | 不看它说什么，看它**奖励什么**：基准的评分函数、leaderboard 排序键、审稿接受标准、开源项目的 roadmap | "领域实际买什么"的**激励清单** | **高（这是唯一的硬证据）** |
| **S3 矛盾层** | 求 S1 与 S2 的差集 | "口头要 A、实际买 B"的**缺口表** | 中高（差集可复核） |

**S2 为什么比 S1 硬**：宣称可以随便写，评分函数不能。**一个领域的真实目标写在它的评价函数里，不写在它的摘要里。**
这也是本所"数字凭什么算数"那条线的同一个判断。

### 3.2 方法的边界（必须声明，否则是冒充）

**不能从论文"推导"出最终目标。** 这是休谟问题（is–ought）：文献只能告诉你"大家在做什么、奖励什么"，
**不能告诉你"应该追求什么"**。

所以：
- G\* 是**规范性主张**，不是**实证发现**。它的正当性不来自"文献支持"，而来自两点：
  ①它把领域内**互相冲突的四个诉求**（通用/效率/可靠/自主）统一成一个**可算的量**；
  ②它**能解释现有失败模式**（规模买能力、刷分、口径分裂、失败不沉淀）。
- 它**可以被反驳**：给出一个反例（§2 末），或证明存在更简且覆盖同样现象的表述。
- **任何把它写成"研究表明，具身智能的最终目标是…"的句子，都是错用。** 正确写法："本文主张…（判断）"。

### 4.1 现状

| 项 | 实数 | 说明 |
|---|---|---|

| 基准 motivation 段 | **0 个系统核** | RoboDojo/LIBERO-Pro 等只核了数字，没核它"为什么做这个基准" |
| 项目级指南文本 | **0** | 完全没碰 |

### 4.2 量化门槛（不到这个数，主题编码不稳）

- **宣称层**：≥ **30 条独立文本**。理由：<30 条时，2 条不同文本就能翻转一个主题的频次排序，编码结果不可复现。
- **激励层**：≥ **8 个基准的评分函数**逐条核（RoboDojo / LIBERO-Pro / RoboCasa365 / BiGym 2.0 / RoboTwin-Phys / OpenVLA 系 / ManiSkill / RLBench）。
- **矛盾层**：差集条目 ≥ 5 条才算"有结构"，否则是噪声。

**当前进度：宣称层 0/30，激励层 3/8（只有 RoboDojo、LIBERO-Pro、RoboCasa365 的部分数字），矛盾层 0/5。**
→ **G\* 目前是 v0，置信度中。它不是结论。**

### 4.3 补法（可执行，约 3 天，零硬件）

1. **S1**：定 6 条检索式（`survey` / `position paper` / `open challenges` / `grand challenge` / `roadmap` / `benchmark motivation`），
   在 arXiv cs.RO + OpenReview + Crossref 三路跑，纳入 2023-2026，取 30-40 篇，只读 intro 末段 + 结语 + 摘要。
2. **S2**：对 8 个基准，逐条抄它的**评分函数与排序键**（不是它宣称的维度）。
3. **S3**：做差集表，逐条标"宣称 / 实际 / 差在哪"。
4. **落点**：这正好是 **P8 综述的第一节「领域的自我描述」**——不是额外工作，是 P8 的必需件。

## 5. 这个定义能干什么、不能干什么

**能**：①给八篇一个共同的判据（P3 的库覆盖率、P7 的 MDE、P8 的三次转向都能挂到 G\* 上）；②让"进步"可算；③让不同路线可在同一把尺上比。

**不能**：①不能替代具体场景的成功率要求（τ 是场景给的）；②不能评价单件高价值任务（§1.3）；③**不能当作"领域共识"引用**——它是我方主张。
