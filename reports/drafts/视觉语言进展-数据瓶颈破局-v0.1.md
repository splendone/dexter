## TL;DR

- **数据瓶颈的本质(重新框定)**:瓶颈不是"数据少",而是"**带动作的物理交互数据**"稀缺昂贵
  (每条都要真机采,无法从互联网爬取);而视觉/语言 ML 的成功靠的是"**海量被动数据**"
  (互联网图像/视频/文本,无动作标签)。**破局 = 把 abundant 被动数据转成机器人可用能力,
  或减少对稀缺带动作数据的依赖。**
- **三个泄压阀(本件的分析框架)**:
  1. **借数据**(borrow):把互联网被动数据(视频/图像/文本)转成机器人先验——视频世界模型、
     被动视频学动力学、VLM 预训练迁移、自监督表征。
  2. **造数据**(make):廉价制造数据——生成式仿真、视频生成当数据引擎、神经渲染 real2sim、
     程序化/生成式增广、LLM 造任务环境。
  3. **少要数据**(need less):每份数据榨出更多能力——数据策展、检索/in-context 适应、
     **test-time compute(用推理换数据)**、LLM 生成奖励(移除奖励标注)。
- **已被具身领域充分借鉴(增量收窄)**:VLM 基础模型迁移(RT-2/OpenVLA/π0)、自监督表征
  (R3M/MVP/VC-1)、视频生成数据引擎(DreamGen/Cosmos)、生成式增广(MimicGen/RoboGen)、
  VLM-as-reward(VIP/LIV)、in-context(Gato/VIMA)。
- **视觉/语言侧已成熟、具身侧尚未充分借鉴的最大机会(本件核心结论)**:
  1. **★ test-time compute / 推理式适应迁到操作**(语言侧 o1/o3 式推理扩展 + TTA 极成熟;
     机器人侧 2026 才零星出现,"用推理/搜索换数据"几乎空白)——**与 MT3 天然衔接**
     (MT3 是 test-time 检索,o1 式是 test-time 推理/搜索)。
  2. **★ 数据中心策展(influence functions / data pruning / dataset cartography)迁到机器人演示**
     (视觉侧高度成熟并工业化;机器人演示策展仅 Data Quality in IL 2023 + QoQ 2026 寥寥数件)。
  3. **3DGS + 可微物理做接触丰富/灵巧操作的 real2sim**(3DGS 视觉侧成熟两年;机器人接触丰富
     real2sim 到 D-REX ICLR 2026 才起步)——**契合本所灵巧手主线**。
  4. **Self-Instruct 式"自生成+过滤"数据飞轮 + AI-Scientist 式自主实验闭环**迁到机器人
     数据/课程采集(RoboGen/Holodeck 是雏形,缺"自生成-过滤-评审"科研级闭环)。

  绝不编造**;并区分"纯 ML 进展(还没用到机器人=潜在机会)"vs"已被机器人借鉴"。
- **子 agent 自纠错(证据纪律生效)**:视觉侧子 agent 报告**自己记忆里 3 个 ID 是错的**

  张冠李戴事故**。这印证"未核即写"教训(已录 honor 2026-10-13)。

## §1 重新框定数据瓶颈:从"数据少"到"带动作数据少 + 三个泄压阀"

**承领域级图谱 L2**:数据瓶颈 = 数据驱动 ML 范式(胃口是数据)× 具身性要求(物理交互
数据无法爬取)的碰撞。**碰撞的精确位置**:ML 范式要的是"海量(输入, 输出)对",
视觉/语言的输出标签(类别/文本)可从互联网免费获得或弱标注;**而操作的输出是"动作",
动作标签只能由机器人物理执行产生**——这是瓶颈的根。

**因此破局有三条逻辑路径(三个泄压阀)**:

| 泄压阀 | 逻辑 | 对应操作支七路线 |
|---|---|---|
| **①借数据** | 把互联网**被动数据**(无动作标签)转成机器人先验/能力 | 路线①(VLM 迁移)、③(人类视频)、④(检索用预训练表征) |
| **②造数据** | 用仿真/生成模型**廉价制造**带动作数据 | 路线②(合成)、⑥(翻新)、⑤(LLM 造任务环境) |
| **③少要数据** | 每份带动作数据**榨出更多能力**,或干脆**不用梯度数据** | 路线④(检索/免训练)、⑤(agentic 资产)、⑥(策展) |

**关键观察**:视觉/语言 ML 的最新进展,**绝大多数落在阀①和阀②**(借被动数据、造数据),
且**已被具身领域快速借鉴**;**真正"视觉/语言侧成熟、具身侧还没充分借鉴"的机会,
集中在阀③(少要数据)**——尤其 **test-time compute(用推理换数据)与数据策展(挑对的数据)**。
**这是因为阀③需要"把 ML 侧的方法论(推理扩展/数据科学)迁到物理交互场景",迁移成本更高,
但一旦迁成,对"每条数据都贵"的操作场景性价比最高。**

## §5 最大的未充分借鉴机会(排序 + 与本所资产/MT3 的衔接)

**机会 #1(最强)· test-time compute / 推理式适应迁到操作**
- **是什么**:语言侧 o1/o3 式"部署时长链推理 + 搜索 + 自我验证"+ TTA(Tent/TTT)极成熟;
  机器人侧直到 2026 才零星出现(SALT/TTA-VLN),**"用推理/搜索换数据"缓解真机数据稀缺几乎空白**。
- **为什么是数据瓶颈的解**:部署时在线推理适应 = **免再采数据、免再训练**——直接命中阀③。
- **与 MT3 的天然衔接(关键)**:**MT3 本身就是 test-time 方法(测试时检索)**;
  o1 式是**测试时推理/搜索**。**把 MT3 的"test-time 检索"升级为"test-time 推理+搜索+自我验证
  over 检索库"**,是一条自然的、有新意的延伸——这正好落在领域级图谱分支②(认知)×
  操作支路线④⑤的交界,且是**语言侧最成熟、具身最空白**的错配点。
- **与本所资产**:4090 单卡可跑(推理为主,不训大模型);MT3 复现基础直接可用。
- **风险**:test-time 推理的延迟 vs 实时控制(操作要 ≥10-50Hz,o1 式推理慢)——
  须解决"推理时延"与"控制实时性"的矛盾(可能走"慢推理规划 + 快检索执行"双系统,
  接 LiMA/Rolling-WAM 分层路线)。

**机会 #2 · 数据中心策展(influence functions / data pruning / dataset cartography)迁到机器人演示**
- **是什么**:视觉侧数据选择/质量度量/influence functions 高度成熟并工业化;
  机器人演示策展仅 Data Quality in IL(NeurIPS 2023)+ QoQ(ICRA 2026)寥寥数件。
- **为什么是数据瓶颈的解**:真机数据"每条都贵",**"从有限数据挑最有用样本"的性价比
  理论上远高于视觉侧**(视觉数据便宜,策展收益小;操作数据贵,策展收益大)——却几乎未被系统开发。
- **与 MT3/操作支衔接**:MT3 检索库只存成功演示;**用 influence functions 给检索库做策展/
  加权**(哪些演示对哪些任务最有价值),接操作支路线⑥(翻新)与路线④(检索度量改进)。
- **与本所资产**:纯计算(4090 可跑),不依赖新硬件。
- **风险**:influence functions 在机器人轨迹(序列/接触)上的定义与计算(视觉侧是 i.i.d. 样本,
  机器人是时序轨迹)——须解决"轨迹级 influence"的度量。

**机会 #3 · 3DGS + 可微物理做接触丰富/灵巧操作 real2sim**
- **是什么**:3DGS(SIGGRAPH 2023)视觉侧成熟两年;机器人接触丰富 real2sim 到 D-REX
  (ICLR 2026)才起步。
- **为什么是数据瓶颈的解**:从少量真实图像重建照片级+物理可微仿真,廉价造接触丰富数据(阀②)。
- **与本所资产衔接**:**契合灵巧手主线**(变体 B);3 RealSense 可采真实场景做 3DGS 重建;
  接操作支路线②(合成)与透镜②(触觉,若仿真接触物理)。
- **风险**:3DGS 的接触物理保真度(可微物理辨识质量)——D-REX 也只在灵巧抓取上初步验证。

**机会 #4 · Self-Instruct 数据飞轮 + AI-Scientist 自主实验闭环迁到机器人数据/课程采集**
- **是什么**:Self-Instruct(ACL 2023)自举造数据 + AI Scientist 自主跑实验闭环;
  机器人侧 RoboGen/Holodeck 是雏形,缺"自生成-过滤-评审"科研级闭环。
- **为什么是数据瓶颈的解**:自动造任务/环境/课程/数据,省人工(阀②)。
- **风险**:自动化闭环的"质量过滤"在物理任务上比文本难(文本可自动判优劣,物理任务要执行验证)。
