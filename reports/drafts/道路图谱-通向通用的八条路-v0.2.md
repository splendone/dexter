## 0. 一句话

**八条路不是八个技术选择，是四个互不相同的"通用性来源假设"。**
所以它们**不可比**——不是实验没做好，是**它们各自把"通用"定义成了不同的东西**。

> 这直接解释了上一轮的发现：**138/160 个基准是 model-agnostic、只有 11 个建显式对照**（2609.29669 全文核）。
> 不是大家不想比，是**没有一个共同的"通用"可拿来比**。

## 1. 四条假设（本件的分析骨架）

| 假设 | 一句话 | 如果它对，"通用"长什么样 |
|---|---|---|
| **H1 覆盖** | 通用 = **见过的分布足够宽** | 一条随数据量上升、永不饱和的曲线 |
| **H2 组合** | 通用 = **有限单元 × 无限组合** | 组合数爆炸，而单元数很小 |
| **H3 语义** | 通用 = **语言与世界知识可迁移** | 没见过的指令/物体也能对 |
| **H4 时间** | 通用 = **部署中累积** | 同任务的第 N 次比第 1 次好 |

**关键**：四条假设**不是互斥的，但判据互不通用**。H1 的分数不能判 H2 的路，反之亦然。
→ **这就是"通用"至今没有统一判据的结构原因。**

## 3. 每条路的三句话（机制 / 2026 进展 / 死结在哪）

### R1 规模（端到端 VLA）
**机制**：把"感知-语言-动作"压进一个网络，用数据覆盖换泛化。
**2026 进展**：动作头分岔（flow-matching / diffusion / 双系统）已收敛为工程问题；瓶颈从"模型"移到"数据"。
**死结**：**它优化的是水平，不是导数。** 数据一多分数就涨，但"新增一个任务"的成本不变——这正是本所"投入复利"判据要抓的东西。

### R2 数据引擎
**机制**：不换模型，换数据生产方式（遥操作 / UMI / 人类视频 / 仿真合成 / 世界模型生成）。
**2026 进展**：Data Pyramid 综述把生态组织成五层（真机 / UMI 式 / 自我-外中心视频 / 仿真 / 通用视觉语言）。
**死结**：**"覆盖度"没有指标。** 于是所有人都在报"小时数/轨迹数"，没人能说"这个库够不够"。

### R3 结构先验（分解/分层/技能）
**机制**：把长程任务切成可复用的段，让"单元少、组合多"。
**2026 进展**：MT3 把两段式推到 1,000 任务/17 小时；STRAP 把粒度下移到子轨迹；PHASE 用触觉定义变长相位。
**死结**：**分解有代价**——MT3 逐字承认「decomposition prevented this beneficial representation sharing」。**代价何时超过收益，无人测**（→ 八篇之 P4）。

### R4 检索与非参数
**机制**：不改参数，改"能查到什么"。策略 = 库 + 检索规则。
**2026 进展**：度量之争（光流 / 密度比 / kNN 重参数化）+ 闭环化（BPC 75 Hz、RTCF 修冻结 VLA）+ 库资产化（Retrieve-Don't-Retrain：新任务 = 索引）。
**死结**：**不能插值**（MT3 逐字）+ **库无质量门**。这两条正是 R²SI 外层要补的。

### R5 语义迁移
**机制**：借互联网级语义先验，让"没见过的指令/物体"也能对。
**2026 进展**：VLA 综述已成规模（效率、数据、解剖学多支），开放词汇从"识别"走向"指令改写鲁棒"。
**死结**：**语义对不等于接触对。** 说得出"把盖子拧开"，不等于拧得开。

### R6 世界模型
**机制**：预测后果 → 在想象里规划 → 执行。
**2026 进展**：从"视觉逼真"转向"可控、可用"（2609.16697 的三段论：plausible → controllable → actionable）。
**死结**：**闭环证据缺失**。2609.29669 编目 160 个基准后判定：这个问题"目前无法用领域已建的基准回答"。

### R7 agentic
**机制**：LLM 当大脑，技能当工具，harness 负责编排与纠错。
**2026 进展**：从"agent 直接控机器人"转向"**agent 生产可复用资产**"（技能库 / 工具接口 / 程序 / playbook）；R²SI 把外层做成"改 Skill + 测试门 + 版本管理"。
**死结**：**底层动作仍靠策略**——agent 不解决"手怎么动"，只解决"下一步做什么"。所以它天然依赖 R1/R3/R4。

### R8 自进化
**机制**：把执行经验沉淀成下次的能力。
**2026 进展**：fleet-scale 离线转在线（LWD）、持续 steering 防遗忘（D2R）、外层递归（R²SI）。
**死结**：**依赖可靠自评**。没有测试门的自进化 = 自我确认循环（本所 2026-09 踩过：错误产物进库后被当"已知事实"互证）。

## 4. 判断：哪条最可能通向"通用"

**这是判断，置信度中，理由三条：**

1. **R1+R2 通向的是"更多任务"，不是"更便宜的通用"。** 它们优化水平（H1），而 H1 的曲线永不饱和也永不便宜。
   → 所以它们会一直是主流，也一直不解决"通用"的判据问题。
2. **只有 R3+R4 在动"导数"**：单元复用、库复用，都是让"新增一件事更便宜"。
   但两者各自有硬死结（分解切断共享 / 检索不能插值），**单靠任一条都走不到**。
3. **R7+R8 提供的是"外层"，不是"能力"**：它们能修 R3/R4 修不了的东西（R²SI 的递归正好长在 MT3 的"不能插值"上），
   但**没有底层动作就无从修起**。

**最可能的形状（判断）**：**R3×R4（复用）× R5（语义）× R8（带测试门的沉淀）**——
即"分解检索 + 语义先验 + 外层递归 + 测试门"。**这恰好是 R²SI 的形状**，也恰好是 MT3 缺的那一半。

## 7. 诚实清单

1. **本件是重组，不是新检索**。证据来自：本轮 9 篇 abs 逐字（MT3/STRAP/FlowRetrieval/IWR/DARP/BPC/RTCF/Retrieve-Don't-Retrain/PHASE）+ 109–140 篇池的标题/摘要 + v0.1 的既有七路 + 2 篇全文核。**没有为"道路"这件事重新做穷尽检索。**
2. **RT-1/RT-2/CLIPort/SayCan 本轮未重核**（v0.1 已核，本件沿用），引用前须回原文。
3. **R²SI 是媒体转述，不是论文**（上一轮已声明），本件用它只作"存在这种形状"的证据，不引数字。
4. **"哪条最可能"是判断，不是发现。** 反方最强论证：H1 的曲线可能在某点突变（scaling 涌现），那时 R1 会一次性解决 R3/R4 想解决的问题。**我没有证据排除这一点。**
5. **八条路的划分本身是选择**：换一种切法（按"数据从哪来"或按"谁做决策"）会得到不同的路数。**本件的切法服务于一个目的——让"通用性判据"的差异显形。**
