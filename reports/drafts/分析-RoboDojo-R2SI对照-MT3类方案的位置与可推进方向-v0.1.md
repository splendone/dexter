# 分析 · RoboDojo / R²SI 对照：MT3 类方案站在哪、能推进什么

> **本档管什么**：在 RoboDojo 这一"操作能力实践评价基准"上，**R²SI（agentic 侧）与 MT3 类免训练检索（策略侧）到底是什么关系**，
> 以及由此推出的**五个可落地研究方向**（每条带判定实验与"落到八篇的哪一篇"）。
> **不归本档**：八篇的完整选题论证 → `选题论证-MT3锚定8篇-从进展综述到创新点-v0.3.md`；
> 基准事实卡 → `knowledge/maps/controversies.md` §对撞、`benchmarks.md`。
> **性质**：流转件，不签发。**本件含判断，判断均标"这是判断"。**

**起草**：Dexter ｜ **日期**：2026-10-18 09:1x ｜ **判类**：**B 类（领域）**，落 `Dexter/reports/drafts/`
**委托人问**：①在 RoboDojo 上，MT3 这一类方案的效果与最新方案比如何；②有哪些方向能推进共同的研究落地；③MT3 的方案/方向上的改进，对操作评价基准有没有提升帮助。

## 0. 一句话结论

**MT3 与 R²SI 不是同一层的两个选手，是同前提（免微调、一次示范）下的两种"改进对象"。**

> R²SI 改进的是 **Skill / Harness（外层递归修订）**；MT3 改进的是 **什么都不改**——它从固定库里检索并回放。
> 所以"MT3 vs R²SI 谁在榜上高"这个问题**在类型上不成立**；但"MT3 类方案对**基准本身**有没有用"成立，**且答案是有用的，只是用处不在分数上**。

**三条硬判断**：

1. **R²SI 补上了本所 2026-10-13 判定的"缺席腿"**。那次逐字结论是「真正缺席的是 **agentic ↔ 策略** 在共享榜上」——
   R²SI 是 agentic 侧的强条目，**但策略侧仍然没有一条同榜的免训练检索基线**。**这个空位现在更值钱了，不是更不值钱。**
2. **MT3 直接搬到 RoboDojo 会输在结构上，不是输在方法上**：RoboDojo 用**原生动作步数预算**卡进度，而 MT3 是**定长回放**——
   步数由演示决定，不是由任务决定。**这是可预测、可量化的失配，不是调参能救的。**
3. **最有落地价值的一条不是"让 MT3 上榜"，是"让 R²SI 的外层去修 MT3 修不了的东西"**：
   MT3 自己逐字承认检索"**fundamentally could not interpolate between demonstrated behaviours**"，
   而 R²SI 外层做的恰恰是"改 Skill 并测试后发布"。**二者正交，可组合。**

## 2. 结构判断：同前提，不同改进对象

**这是全件最重要的一张表。**

| 维度 | **MT3（策略侧）** | **R²SI（agentic 侧）** |
|---|---|---|
| 前提 | 免训练、**1 条演示/任务** | 免后训练、**1 条人类示范/任务**（ICL） |
| 学新任务的载体 | **往库里加演示**（索引即能力） | **上下文**（示范进 prompt）+ 外层改 Skill |
| 执行期谁在决策 | 无决策：检索 → 回放 | Robot Agent 每步决策，WSP 只是一个可调用的 Skill |
| 有没有外层 | **没有**。失败不沉淀 | **有**：复盘 → 改 Skill → 测试 → 发布 → 版本管理 |
| 失败的性质 | **系统性且持续**（项目页逐字："even when failing, retrieval-based methods might incorrectly approach the object, but their motions stay **loyal to the demonstrated behaviour**"） | **可被外层定位并修订**（push_T 三处具体修改） |
| 能否插值 | **不能**（逐字："fundamentally **could not interpolate** between demonstrated behaviours"） | 能：Skill 是代码/参数，可改可组合 |
| 记忆 / 长程 | 无（单任务两段式） | 有（视觉记忆 + 事件记忆 + 回合记忆） |
| 效率指标 | 步数 ≈ 演示步数（**定长**） | 步数**可被外层优化**（723 → 596 → 389） |

> **结论（判断）**：**R²SI 的"递归"正好长在 MT3 的"不能插值"上。**
> MT3 的失败是**忠于演示的失败**——动作对、目标偏；R²SI 的外层是**改动作、保目标**。
> 二者不是竞争关系，是**互补的两层**：检索给"可信的运动先验"，递归给"先验之外的修正"。

## 3. MT3 类方案在 RoboDojo 上站在哪（逐维对照）

RoboDojo 的五个维度，MT3 类方案的实际覆盖：

| RoboDojo 维度 | MT3 类能否覆盖 | 依据 | 判断 |
|---|---|---|---|
| **双臂操作** | 🟡 部分 | MT3 是 Sawyer 单臂；本所有 2 台 Sawyer（可双机并行，但**不是双臂协同**） | 单臂任务可，双臂协同不可 |
| **长程任务** | ❌ 不能 | MT3 是"单任务两段式"，无跨任务进度记忆 | 结构性缺失 |
| **记忆** | ❌ 不能 | 无 episode memory；检索只看当前观测 | 结构性缺失 |
| **泛化** | ✅ 能（有限） | MT3 自报"generalising to novel object instances"（物体实例级） | **这是 MT3 唯一强项**，但只在物体实例级，不含指令改写/环境变化 |
| **精细操作** | ❌ 不能 | 无触觉（本所 = 0），MT3 亦无接触反馈 | 结构性缺失 |
| **步数预算** | ❌ 结构性失配 | 回放定长；演示 400 步就 400 步，与任务预算无关 | **最硬的一条** |

> **判断**：MT3 类方案在 RoboDojo 五维里**只稳拿"泛化（物体实例级）"这一维**，其余四维结构性缺失。
> 所以"MT3 类方案效果与最新方案比较"——**在总分上必然大幅落后，且这个落后不携带方法学信息**（比的是覆盖面，不是方法优劣）。

**但**：把 MT3 类方案放到榜上仍有一个**别的方案给不了**的东西——**确定性**。
LLM/agent 侧分数随模型版本漂移（Astra 一次升级就从 14% 级别跳到另一档），而检索策略**同一库同一观测 → 同一动作**，
分数可复算。**这是"噪声地板"**。

## 4. 直接回答：MT3 的改进对"评价基准"有没有帮助

**有，但用处不在刷分。三条具体用处 + 三条帮不上。**

### 4.1 三条用处

| # | 用处 | 机制 | 落到哪篇 |
|---|---|---|---|
| **U1** | **提供确定性下限（噪声地板）** | 检索策略无随机性、无 LLM 版本漂移 → 同一配置可复算同一分数。任何 agentic 条目的"提升 X 分"都能对照这条地板判断是否超出复算误差 | **P7（MDE 表）** + **P1（复现）** |
| **U2** | **提供"可归因的失败"** | 检索失败是**系统性**的（忠于演示但目标偏），可逐段归因；LLM agent 失败常混"决策错"与"执行错" | **P1（阶段级失败解剖）**、**P5（归因×干预匹配）** |
| **U3** | **把"库"变成可版本化资产** | R²SI 的 Skill 有测试门 + 版本管理；MT3 的库**没有任何质量门**。补上"库的覆盖率 / 版本 / 回滚"就是资产级指标 | **P3（库 vs 训练集）**、**P8（第三次转向）** |

### 4.2 三条帮不上（必须说清，否则是吹）

1. **帮不上总分**：五维缺四维（§3），总分必然低，且低得不携带信息。
2. **帮不上长程与记忆**：检索范式**结构上**没有"跨回合记忆"这一项，加记忆就不是 MT3 了。
3. **帮不上精细操作**：无触觉就是无触觉（本所硬件 = 0；PHASE 已占触觉相位检索的方法位）。

## 5. 五个可推进方向（每条：争点 → 判定实验 → 可支付 → 落到哪篇）

> 排序依据：**能同时服务"共同落地"与本所八篇**的排前面，不是按新颖度排。

### D1 · 给 agentic 榜补一条"策略腿"：免训练检索作为非 LLM 下限基线 ★最高落地价值
- **争点**：agentic 条目的分数里，有多少来自"语言/记忆/递归"，有多少来自"底层动作本身好"？
- **判定实验**：在 RoboDojo 的**同任务子集**（取单臂、非长程、非精细的那些）上跑 MT3 类检索基线；对照同子集上的 agentic 条目。
  **若检索基线在子集上已接近 agentic 条目 → 说明 agentic 增益主要来自"覆盖维度"而非"单步决策质量"**；反之则 agentic 的决策确实值钱。
- **可支付**：✅ 2 台 Sawyer + 免训练（单次试验 1–2 min）。
- **落地**：**P1 + P7**；并直接回答 2026-10-13 留下的"agentic ↔ 策略缺席"。
- **⚠️ 前提**：RoboDojo 任务定义是否公开可复跑（**未确认**）；不公开则只能做"自建同构子集"，**必须在文中声明不是官方榜**。

### D2 · 步数预算是一等指标：定长回放 vs 可优化步数
- **争点**：RoboDojo 用**原生动作步数预算**评分，而检索范式**步数由演示决定**——这是范式缺陷还是评价缺陷？
- **判定实验**：测检索策略的**步数分布 vs 任务预算**的匹配率；再做"演示裁剪"（把演示压到 80%/60% 步数）看成功率如何塌。
  **若压缩 20% 步数即显著掉点 → 说明"步数效率"在这类方法里是硬约束，基准应把它单列**；若不掉 → 说明预算设得太松。
- **可支付**：✅ 纯分析 + 真机小规模。
- **落地**：**P2（top-k 插值部分）+ 新争点**；可写成"效率-成功率联合曲线"，中文核心很吃这个。

### D3 · 外层递归 × 内层检索：让 R²SI 修 MT3 修不了的东西 ★最高科学价值
- **争点**：R²SI 外层改的是 **Skill（代码/参数）**；MT3 的失败是**轨迹级**的（不能插值）。**外层能不能直接修"检索结果"而不是"Skill"？**
- **判定实验**：三种外层干预 —— ①改 Skill 文本（R²SI 原样）②改**检索度量权重**（P2 的双通道）③改**演示库**（加/删/裁剪演示）。
  比"达到预算内满分所需轮次"。**若②③的收敛轮次显著少于① → 说明对检索式系统，"改库/改度量"比"改代码"更有效**——这是能直接给 R²SI 这类系统提改进的一句结论。
- **可支付**：✅ 不需要新硬件；但需要**外层 agent 的工程实现**（本所只能出规格，实现由真人）。
- **落地**：**P2 + P5**；这条最可能变成"给业界系统提改进"的引用点。
- **⚠️ 边界**：本所**不做 agent 系统集成**（那是产品），只做"哪种干预更有效"的受控比较。

### D4 · 库/Skill 的资产级指标：覆盖率、版本、回滚
- **争点**：R²SI 有"测试门 + 版本管理"，MT3 的库**零质量门**。**库该用什么指标评价？**
- **判定实验**：定义并测 **库覆盖率**（库中与目标任务子轨迹距离 < ε 的比例），检验它能否预测"新任务零样本成功率"。
- **可支付**：✅ 仿真 + 公开数据。
- **落地**：**P3**（这正是 P3 的核心自变量）；也是 P8"第三次转向"的实证支撑。

### D5 · 口径护栏：任何跨方案比较先过"同日同口径"门
- **争点**：RoboDojo 已出现 **7 倍口径分裂**（62.00% vs 8.80%）。R²SI 登顶后，"MT3 vs R²SI"的二手比较必然出现。
- **判定实验**：不是实验，是**报告规范**：任何引用必须带（日期 / 赛道 / 任务子集 / 试次 / 步数预算 / 是否用 Python 工具）。
- **可支付**：✅ 零硬件。
- **落地**：**P7**（MDE + 口径表）。**这条是护栏，不是贡献**——但没有它，前四条都会被二手数字污染。

## 6. 诚实清单

1. **R²SI 的具体分数本件没拿到**。所有"超过 GPT-6-Astra"都是媒体表述，**没有分项、没有试次、没有统计口径**。→ 本件不做任何算术比较。
2. **R²SI 的信息全部来自媒体转述**（机器之心系 + 转载），**不是论文、不是官方技术报告**。凡引用须标"媒体转述"。
3. **RoboDojo 的任务定义是否公开可复跑，本件未确认**。→ D1 可能只能做"自建同构子集"，**绝不能自称官方榜成绩**。
4. **"MT3 五维只稳拿一维"是判断**，依据是 MT3 原文的能力描述与本所硬件实况，**不是**在 RoboDojo 上实测的结果。
5. **D3 的"改库比改代码更有效"是待检验假设**，不是结论。它成立与否取决于外层 agent 的实现质量——而本所不做 agent 工程。
6. **本件没有改变八篇任何一篇的选题**，只是给 P1/P2/P3/P5/P7/P8 补了**外部对照物**（R²SI 与 RoboDojo 口径）。
