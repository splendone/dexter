# reports 使用说明

黄色级产物(精读报告、综述、文献地图、**可投稿稿件:教程 / 立场文章 / 论文**)的流转区:

> **工程规格书不在本目录**——规格书落 `designs/`,规程见 `.zcode/skills/design-spec`。

1. 成稿写入 `drafts/`,文件头带**署名链**:`起草 = Dexter(YYYY-MM-DD) |
   复核 = Dexter 自查(…) | 签发 = Dexter(YYYY-MM-DD,委托人授权自审签发)`。
2. **签发流程(2026-09-28 起,宪法 v1.1)**:先走"会签前自查复核"
   (独立子任务重读原文 + 外部交叉源,复核记录随文存档),通过后由 Dexter
   自审签发,移入 `final/`。**签发 = v1.0,不是终点。**
3. **重审(活文档)**:`final/` 内产物按 `.zcode/skills/re-review` 滚动重审——
   新证据触及本件结论时,改正文 → 升版本 → 文末"重审记录"追加条目。
   登记见 `knowledge/maps/review-ledger.md`;周五复盘抽检 1 件。
4. 未签发(drafts 内)的产物不进入 `knowledge/` 结构性引用;被否的产物留档
   不删,文件头标"已否 + 理由"。
5. **边界**:自审签发只覆盖内部定稿;**对外发送 / 发布 / 投稿仍是红色**,由
   委托人亲手执行。**可投稿稿件(G3 产出)流转至 `final/` 即视为"可投状态",
   但投稿与否由委托人评估决定**——Dexter 不投、不署名对外。

## 精读报告骨架

TL;DR(≤3 行)→ 元信息(标题/作者/机构/出处/链接/代码)→ 问题 → 方法
(核心创新)→ 实验(设置/基准/关键数字,带原文位置)→ 局限(作者自述与
我的判断分离)→ 与课题关系(四透镜映射)→ 置信度与待核点。
