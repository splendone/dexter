## 透镜定义

**语言条件长程操作**:把**自然语言指令**转成**跨多阶段、多子任务的连续行为**——包括
指令接地(instruction grounding)、长程任务规划(task planning)、跨阶段的**状态跟踪与
记忆**,以及执行中的**重规划与失败恢复**。

- **本透镜的问句**:**"语言在哪一层被消费?"**——这是四条透镜里**三股力量正面相遇**
  的一条(透镜②里触觉与三股力量正交,这里不是)。
- **与透镜①的分工**:透镜①问"多少数据",透镜③问"**指令如何驱动时间上延展的行为**"。
- **"长程"的口径警告**:**本领域尚无统一的"长"的定义**——步数、子任务数、时间跨度、
  记忆依赖深度被混用。跨论文比较数字前,必须先确认它测的是哪一种(见开放问题 2)。

## 一、路线对比(六条路线)

### 路线 A · 端到端 VLA(把语言压进策略权重)

**逻辑**:语言直接作为策略的输入条件,动作以 token 形式输出——**不设显式规划器**,
长程能力来自规模与数据。

| OpenVLA(2406.09246) | **7B** 开源 VLA,**970k** 真机演示;Llama 2 语言模型 + 视觉编码器融合;重点补上"开源"与"高效微调"两个缺口 | abs 页 |

解耦——语言/意图留在慢系统,运动控制留给快系统。

## 二、分歧

### 分歧 1:长程能力从哪里来(本透镜的核心争议)

- **端到端派**:规模与数据本身即路径(OXE 的跨本体聚合;π0.5 的异质共训练)。
- **分层派**:架构必须解耦——慢系统管意图、快系统管执行(LiMA 的 45.8% 延迟下降
  与 70.8% 成功率;Rolling-WAM 的 4.5× 重规划提速)。
- **Agentic 派**:长程不该学,该**写出来**(WAA 75.6% SOTA;K1 88.9%;编码代理在
  TAMP 上 56–95% vs 手写规划器 47%)。
- **这是判断(置信度中→高,承接账本一 观察 v2)**:三派**同基准、未对撞**——

### 分歧 2:语言在哪一层被消费

- **token 级**(路线 A):动作即文本 token(RT-2),语言与动作在同一序列。
- **意图级**(路线 B):语言停在慢系统,产出的是稀疏时空意图(LiMA)。
- **代码/工具级**(路线 C):语言外化为程序、API 调用、技能选择。
- **这是判断(置信度中)**:三者的**失败模式不同**——token 级受限于上下文与动作粒度;
  意图级受限于意图-执行对齐(这正是 LiMA 用 Schrödinger Bridge 解决的问题);
  代码级受限于**基元与验证器的覆盖**(DexAgent 的"现造新技能"正是补这一环)。
  **"哪层更好"是错问题;"什么任务该在哪层"才是问题。**

## 三、开放问题

1. **三股力量的受控对撞缺失**(账本一 观察 v2):同基准、同预算、同骨干下比较
   端到端 / 分层 / agentic——**无人做**。这是本透镜**最大的现成缺口**,
   且**不需要新方法,只需要一个诚实的实验**。
2. **"长程"没有统一口径**:步数 / 子任务数 / 时间跨度 / 记忆依赖深度混用
   (本分图已尽量逐条标注,但原始论文自身不统一)。
3. **记忆更新规则无选择准则**:ReCAT 报告 additive 在计数/计时最好、delta-rule 在
   空间回忆最好,但**没有"给定任务该选哪种"的判据**。
4. **失效下的长程鲁棒性刚起步**:MAIL-Bench(视觉中断)是本窗口**新出现**的基准;
   传感器失效、执行偏差累积下的长程表现几乎空白。
5. **agentic 的"资产"没有评测口径**:路线 C 观察到的技能库 / 工具接口 / playbook
   等**可复用资产**,目前**只有个别任务的成败数字,没有"资产质量"的度量**
   (如复用率、跨任务迁移率)。这是新提出的问题。
6. **语言条件的数据侧未被分离**:DexRoam 证明人演示可提升 VLA,但**"语言"在其中
   起多大作用未被单独测**(其对齐阶段含 action-semantic,可能混入语言收益)。
