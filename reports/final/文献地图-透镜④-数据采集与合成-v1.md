## 透镜定义

**数据采集与合成**:机器人训练数据**怎么被造出来**——采集(遥操作 / 动捕 / 自中心
人类视频)与合成(仿真引擎 / 生成模型 / 任务规划)的**手段、规模、保真度、成本与合法性**。

- **本透镜的问句**:**"要拿到 X 规模、Y 形态的机器人数据,该走哪条管线,代价与合法性
  边界在哪?"**——它是四条透镜里最"工程"、也最"钱"的一条(数据成本直接决定方法能否被复现)。
- **与透镜①的分工**:**透镜①问"要泛化到 X,最少需要多少数据"(效率);透镜④问
  "这些数据怎么造出来"(生产)**。二者共用同一批数据集,但视角相反:①把数据当**分母**,
  ④把数据当**产品**。**与透镜②的分工**:②问"触觉有没有用",④问"触觉数据怎么采"。
- **口径警告**:本领域"数据量"的度量**不统一**——轨迹数 / 小时数 / 任务数 / 场景数 /
  本体数被混用。**跨论文比较规模前,必须先确认它数的是哪一种**(见开放问题 6)。

## 二、分歧

### 分歧 1:真机数据 vs 合成数据(账本二的核心争议,承接)

- **合成派**:MimicGen/DexMimicGen 用 <200 / 60 条人演生成 50K+ / 21K 演示,长程高精度
  任务可比甚至优于追加人演;PhyVisGen 纯合成数据在 5 项真机任务 **65–95%**;DynaForge
  把动态演示生成成功率从 **41.30%** 提到 **78.37%**。
- **真机派/限定**:Real-to-Sim-to-Real 明说标准形状增广会**破坏任务关键几何界面**
  致下游失效;合成不是免费午餐,必须"**函数保持**"。
- **这是判断(置信度中→高)**:焦点已从"能不能生成"移向"**分布覆盖与接触物理差距**";
  缺的仍是**同策略同预算下真机 vs 合成的受控对比**(账本二 缺口二)。**新增维度**:
  路线 E 显示"**坏数据**"也含信息——这使"真机 vs 合成"的二分会更复杂(合成失败轨迹
  本身可回收)。

### 分歧 2:人演示该"按任务够用"还是"必须规模化"

- **per-task 够用派**:Praxis **每技能仅一条**人类演示;UMR **每任务 ~10 分钟**人演示、
  无机器人演示即达 91.7%;DexRoam **一半机器人演示**即匹配纯机器人训练。
- **规模化派**:Ego2Robot 做 **18,561 小时 / 15 本体**;InternW0-Δ 做 **>20K 小时**异构语料
  ——认为人演示的价值在**预训练规模**,而非单任务。
- **这是判断(置信度中)**:两者不矛盾——**per-task 证明"人演示可替代遥操作",
  规模化证明"人演示可喂强 VLA 骨干"**。真正的争论点是:**预训练规模的人演示,
  其收益是来自"数据量"还是"数据多样性"**?——UMR 的 DES 与 Ego2Robot 的扰动轴
  都在往"多样性"上押注。

### 分歧 3:人-机器人差距要"对齐到什么程度"

- **全对齐派**:VisTacAlign 消融显示**触觉输入与视觉对齐都必要**;DexRoam 三阶段
  **每阶段都必要**(消融确认);DexWeave 两阶段重定向保交互一致性。
- **绕开派对**:P2P-T **完全绕开人-机器人配对数据**(只用 object-centric 世界模型 + 位姿先验);
  KnowDemo 用 VLM 提知识、**不靠动作重定向**。
- **这是判断(置信度中)**:分歧的本质是"**对齐的成本 vs 绕开的损失**"——全对齐
  保真度高但要造配对管线;绕开省管线但依赖中间表示(位姿 / 知识)的覆盖。
  **"哪条更省"取决于任务族是否已有可靠中间表示**(工具操作有,精细力控未必有)。

### 分歧 4:合成保真度是必要条件还是可放宽

- **高保真派**:PhyVisGen 用 IPC 做**物理保真** + 路径追踪做**视觉保真**,换纯合成零样本;
  DEXTERA 强调视觉保真与 3D 几何重建优于生成基线。
- **低保真/抽象派**:DynaForge 用**规划 + 残差**在动态任务上绕开高保真需求;
  DREAM 用 TAMP 生成可行轨迹 + 判据校验,不追求渲染级保真。
- **这是判断(置信度中)**:**保真度的"必要程度"随任务而定**——接触富集 / 软体 /
  动态任务需要物理保真(PhyVisGen / Real-to-Sim-to-Real);语言条件 / 长程规划类
  任务可放宽到"可行 + 校验"(DREAM / DynaForge)。

## 三、开放问题

1. **合成-真机混合配比的系统消融缺失**(账本二 缺口二,承接):**没有**同策略同预算下
   真机 vs 合成 vs 混合的受控对比。这是本透镜**最大的现成缺口**,且**不需要新方法**。
2. **视频(非动捕)人演的重定向仍开放**:Praxis / KnowDemo / Ego2Robot 已部分回应
   (自中心视频 → 机器人),但**"视频保真度损失如何影响下游"未被单独测**。
3. **触觉数据引擎**:触觉×合成仍近乎空白(SBLR 主动绕开触觉仿真,见账本三);
   但 **VisTacAlign / UVTA 证明"人触觉数据"可采可迁**——**"触觉×合成"与
   "触觉×人演示"是两条不同的空白**,后者本窗口已被正面填补。
4. **数据"翻新"的质量度量缺失**(路线 E 新提出):Kintsugi / ε4P 用"恢复成功率 /
   替换损失"间接度量,但**没有"一段坏数据的信息量"的通用度量**(如可恢复性谱、
   噪声级-任务相关性曲线)。
5. **异构语料的"统一表示"是否无损**:UMR(World Flow + Ego Trajectory)、WB-WAM
   (共享物理动作空间)、InternW0-Δ(统一 state-action)各用**不同的统一表示**;
   **没有工作比较"哪种统一表示丢的信息更少"**。这是路线 F 的**新提出的缺口**。
6. **"数据量"无统一口径**:轨迹 / 小时 / 任务 / 场景 / 本体混用,跨论文规模不可比。
7. **许可与合规**:AgiBot World(CC BY-NC-SA)、RH20T(双许可)等使"数据可商用性"
   成为工程选型的一等约束——**许可矩阵见 `knowledge/datasets/`**,但**"许可 × 可复现性
   × 透镜适用"的三维选型表仍未做**。
   → **✅ 已建(2026-09-30)**:`knowledge/maps/dataset-selection-matrix.md`
   (12 数据集 × 许可 × 可复现性 × 透镜适用;分 A 宽松 / B 有坑 / C 禁商用 / D 待核 四档)。

## 四、与三股力量的对位小结(一句话版)

- **端到端规模化**:路线 A + F——**把数据当工业品**(产业遥操 + 异构语料)。
- **结构化分解**:路线 B + C + D——**把数据当可造的中间物**(人演示转机器人 + 引擎扩增 + 资产化)。
- **Agentic/程序合成**:路线 D 的 DREAM + 路线 E——**把数据当可推理、可回收的信号**
  (LLM/TAMP 生成 + 坏数据翻新)。
- **一句话对位**:**端到端 = 采更多;结构化 = 造更多;agentic = 推理出来、回收回来**。
- **对委托人的直接含义**:本透镜的**最大增量不在采数据,而在设计"混合配比"的对撞实验**
  (开放问题 1)——它同时是 G2 的强候选题目之一。
