## §0 摘要

**一句话**:这一族的**外部尺子**比这一族本身更有价值——综述 arXiv:2608.05179 给的
**L0–L5 五轴自主性分级**与 **「外部验证的在环 oracle」判据**,第一次让本所能够**精确说出自己
是什么、以及最深的结构性缺口在哪**;而结论是反直觉的:**本所不缺自主性,缺的是「验证发生的位置」**。

**三件实质产出**:

1. **本所自定位(§1.3,本件最重要的智力产出)**:Dexter = **L4-m(机械环)**,
   与综述语料中**全部 LLM 时代系统一样没有外部验证的在环 oracle**;但 Dexter 有一个
   它们**大多没有**的东西——一个**外部验证的按需环**(重审交叉源须含外部原始来源)。
   → 因此本所最该做的不是"更自主",而是**把外部 oracle 从「按需」前移到「在环」**(P-024)。
2. **诊断得到机制(§1.4)**:10-15 已诊断出「连续三次找方法缺口被抢跑 = 方法错不是运气差」,
   但**只诊断未给机制**。co-scientist 的 Proximity agent(假设聚类以保探索多样性)补上了
   这个机制位 → **多样性哨**(P-027)。
3. **一套可直接套用的披露模板(§1.2)**:综述的**七审计维度**中,本所最缺的是
   **结果选择披露**(试了几次、报的是哪次)——而本所"持续在制而无交付"恰恰**就是这个缺口的
   产物表现**。本件已首次按七维披露(见文首),并立 P-025 制度化。

**甲档 2 项已落地(绿色)**:A1 产物审计披露七维入 `heartbeat.md`;A2 立项记录增列
「建立在哪件之上 / 卡在哪 / 缺什么才能交付」入 `agenda.md`。
**乙档 5 提案待批**:P-024 ~ P-028。**待立 3 条**(#6 / #9 / #10,本轮不立提案,
逐条给**触发条件**,§3)。**并入 1 条**(#4,三个子机制分别并入 P-016 / P-025 / P-028)。
**丙档 5 条不采纳**(N1 ~ N5),理由逐条写明。

**诚实前置**:本件**未主张任何机制为全领域首创**;本件提出的四条机制**效果未实测**
(无 A/B 环境),§2 的判定是**判断非测量**。

### §1.2 综述给的三把尺子

**(a) 自主性五轴 + L0–L5(逐字)**

> 「we code each on **five axes**: *initiative* (who selects the problem or next action),
> *judgment* (who decides novelty, validity, and sufficiency of evidence), *execution*
> (whether the system runs tools and experiments without per-step approval), *iteration*
> (whether it revises hypotheses in response to results), and *accountability* (whether
> traces, seeds, prompts, and human interventions are disclosed). These induce levels:
> **L0** assistive; **L1** tool-augmented; **L2** stage-local; **L3** pipeline;
> **L4** closed-loop, a system whose results are fed back to condition the next step.」

> 「We split L4 by *what* the feedback achieves: **L4-m (mechanical)** re-runs or re-fits on
> an internal metric or constant, while **L4-v (validated)** revises a scientific hypothesis
> against an outside oracle (a physical measurement or independent checker). Finally
> **L5** open-ended, treated as aspirational and excluded from the populated map.」

**L4-m / L4-v 的编码规则(逐字)**:

> 「We code a closed loop as *externally validated* **only when an outside oracle
> (a physical measurement or an independent checker), not the system's own score,
> decides whether a result revises the next hypothesis**; otherwise the loop is *mechanical*.」

**边界例(逐字,用于防误用)**:「MASTER… optimizes a computational task-success metric and
adds a human-expert read *after* the run; **the physical world never gates its next hypothesis**,
so by our rule it is mechanical, not validated. ChatBattery does close against a wet-lab
synthesis, but the experiment confirms a *final* nominated candidate rather than driving each
iteration… **the wet-lab is a terminal check, not an in-loop oracle**.」

**该综述的量化结论(逐字,本件最重要的外部事实)**:

> 「In the 24 runnable systems, **83 percent release code**, while **38 percent release seeds
> or execution traces** and **38 percent report any novelty-verification method**. Among
> **nine closed-loop L4 systems, seven are mechanical reruns and one is author-claimed without
> an external check**; **no LLM-era system in the corpus demonstrates an externally validated
> in-loop oracle under our coding rule**.」

> 「…a system can automate research *tasks* (L2–L3) **without automating scientific *judgment***,
> and that difference is exactly what verification must check.」

> 「the field's central bottleneck is **no longer only whether agents can complete research
> tasks, but whether reviewers can verify the claims those agents produce**.」

**(b) 七个审计维度(逐字)**

> 「**lifecycle stage, autonomy level, evaluation method, released artifacts,
> human-in-the-loop points, novelty-verification method, and result-selection disclosure.**」

Codebook 逐条定义(逐字):

- **Stage**:lifecycle stages the system executes autonomously.
- **Autonomy**:highest level reached, with **"(c)" for author-claimed levels lacking an external check**.
- **Eval**:how outputs are judged(automated LLM reviewer / human expert / task success / benchmark / workshop).
- **Artifacts**:released for re-execution(code, prompts, seeds, traces).
- **HITL**:human entry points(seed/topic, template, baseline, per-step approval).
- **Novelty**:method used to check novelty of outputs(automated literature check / against a literature graph / human / **or none**).
- **Selection**:**whether the number of attempts and the result-selection policy are disclosed**.

**(c) 面向评审者的报告清单(Table 10 / §14)**:⚠️ **起草路径未取得,复核路径已确认其存在**。
该清单在原文被多次引用;起草路径(`WebFetch`)抓到的 HTML 在 §5.3 处截断,**未取得表体**。
**复核路径(独立子任务 `curl` 原始 HTML,1,456,951 字节)已取得其标题逐字**:

### §1.3 【核心】本所的自主性自定位

> **这是本件最重要的产出。** 用 §1.2 的尺子量自己,不是为了评优,是为了**定位缺口在哪一格**。

#### 五轴逐轴

| 轴 | 本所的值 | 依据 |
|---|---|---|
| **initiative** | **高** | 目标台账由 Dexter 主动提出;差距驱动选任务;主动立项;禁止"等您示意续哪件" |
| **judgment** | **高,但部分外置** | 判定由自己做出,**但**黄色产物签发前须过独立子任务复核;**重审交叉源硬规则要求至少一个外部原始来源** ← **这一条是本所相对该族大多数系统的结构性优势** |
| **execution** | **高(绿黄域内)** | 绿色自动执行、黄色自审签发;红色须委托人 |
| **iteration** | **有,但驱动信号是自评** | 检查点 → 差距审视 → 下一件;产出账三态。**回灌信号 = 自己写的产出账** |
| **accountability** | **⚠️ 最弱一环** | 有署名链、溯源、轮次账、重审账;**但没有统一披露块**,尤其**没有"结果选择披露"** |

#### 级别判定

1. **形式上 L4**:本所的**确实**把结果回灌去决定下一步(检查点 → 目标—差距审视)。按
   「a system whose results are fed back to condition the next step」,成立。
2. **实质上 L4-m(机械)**:回灌的**信号**是本所自评的产出账与"下一里程碑最近/卡最久",
   **不是**外部 oracle。按综述编码规则——「**not the system's own score**」——判为**机械环**。
3. **本所另有一个「按需外部环」**:结论正确性由**外部原文/官方页**裁决(重审硬规则),
   且已有实证其**能打破本地自我确认循环**(2026-10-09 的 77.5 轴标误读:扩散 5 件产物、
   潜伏 10 天、期间任何本地互证只会互相确认,**只有外部原文级体检能打破**)。
4. **但它不在环**:该外部环是**按需触发 / 证据触发 / 定期体检**,**不参与每一次迭代**。
   按 §1.2 的边界例,它的性质更接近 **「terminal check」而非「in-loop oracle」**。

> **一句话定位**:
> **本所是 L4-m,与综述语料中全部 LLM 时代系统一样没有外部验证的在环 oracle;
> 但本所有一个它们大多没有的东西——一个外部验证的「按需环」。**
> **本所真正的缺口不在"更自主",而在"验证发生的位置"。**

#### 这个定位为什么重要

- 它把本所相对该族的位置从"落后"改成"**偏科**":自主性不突出,**可问责性与按需外部验证
  明显高于中位**(综述:仅 38% 报告任何新颖性核查方法;83% 放码但仅 38% 放种子/痕迹)。
- 它给 **G2 规格书线**一个**新的、可验证的价值论证**:G2 的"真人试制 + 实测反馈"
  **正是**在造一个外部 oracle。而综述说**语料中无一系统做出外部验证的在环 oracle**——
  **若本所把 G2 的实测反馈回路接进"下一件"的判定,G2 就从"交付一份规格"升级为
  "建立本所第一个 L4-v 环"**。这为 G2 的优先级提供了本所此前未写出的理由。
- 它给"**持续在制而无交付**"一个**结构解释**:这不是纪律松懈,是**结果选择披露缺失**
  (七维之 #7)在台账上的投影——没有"试了几次、报的是哪次"的披露义务,在制就可以无限期悬置。

### §1.4 Google Co-Scientist:六智能体 + 锦标赛 + 验证预算占比

**来源**:Google DeepMind 官方博客《Co-Scientist: A multi-agent AI partner to accelerate
research》(2026-05-19),原文指向 *Nature* `s41586-026-10644-y`。**⚠️ Nature 正文未核**
(只核了博客;**Nature 论文本体未打开**)。

**三阶段六智能体 + 主管(逐条摘录博客原文)**:

- **Generate**:「**Generation agent** - Proposes initial focus areas and novel hypotheses
  grounded in scientific literature and data.」「**Proximity agent** - **Maps and clusters
  generated hypotheses to help ensure a diverse, comprehensive exploration of the research
  space.**」
- **Debate**:「**Reflection agent** - Acts as a "**virtual peer reviewer**", critically
  evaluating hypotheses for correctness, quality, and novelty.」「**Ranking agent** -
  Orchestrates an "**idea tournament**", using **pairwise comparisons and simulated
  scientific debates** to prioritize the most promising paths and hypotheses.」
- **Evolve**:「**Evolution agent** - Continuously refines, combines, and builds upon the
  top-ranked hypotheses…」「**Meta-review agent** - **Synthesizes insights from the debates
  and idea tournament to continuously optimize the system** and generates the final research
  proposal for the scientist to review.」
- **主管**:「a **supervisor agent** acting as an **adaptive planner**… breaks down high-level
  research goals into executable steps, coordinating agents to run in parallel」

**两条本件要用的原则(逐字)**:

> 「To push the boundaries of novelty while ensuring the hypotheses are robust and testable,
> **the majority of the system's computation is dedicated to *verifying* these hypotheses.**」

> 「The idea tournament is iteratively ranking hypotheses via an **Elo-based tournament**…」

**本件的读法(重要,防误用)**:co-scientist 的 Elo 锦标赛**按 §1.2 的判据属 L4-m**——
驱动它的是**系统自己的分数**,不是外部 oracle。**故本件采纳其"排序"用途,禁止其充当
"结论为真"的依据**(见 §3 丙档 N2)。

### §1.5 Sakana AI Scientist-v2:探索预算参数化 + 强制披露

**来源**:`github.com/SakanaAI/AI-Scientist-v2` 仓库页(README)。**许可 = "The AI Scientist
Source Code License"(Responsible AI License 的衍生),不是 MIT**。

**可迁移的机制**:

1. **探索预算被参数化**(`bfts_config.yaml`):`agent.num_workers`(并行探索路径数)/

5. **沙箱强制**:代码执行 LLM 写的代码,"Must be run in a **controlled sandbox**"。

6. **成本口径公开**:ideation 数美元 / 主实验 ~$15–20 / 写作 ~$5。

### §1.6 AgentRxiv:共享中间层与实测增益

**来源**:arXiv:2503.18102《AgentRxiv: Towards Collaborative Autonomous Research》
(Schmidgall & Moor,2025-03-23)。**摘要逐字**:

> 「we introduce AgentRxiv—a framework that lets LLM agent laboratories **upload and retrieve
> reports from a shared preprint server** in order to collaborate, share insights, and
> **iteratively build on each other's research**. We task agent laboratories to develop new
> reasoning and prompting techniques and find that agents with access to their **prior
> research achieve higher performance improvements compared to agents operating in isolation
> (11.4% relative improvement over baseline on MATH-500)**. We find that the best performing
> strategy **generalizes to benchmarks in other domains (improving on average by 3.3%)**.
> Multiple agent laboratories sharing research through AgentRxiv are able to work together
> towards a common goal, progressing more rapidly than isolated laboratories, achieving
> higher overall accuracy (**13.7% relative improvement** over baseline on MATH-500).」

**本件的读法**:本所是"一人事务所",**没有第二个实验室**,故**跨实验室协作**那一半
不适用。但**可检索的中间层**那一半**直接适用**——本所 `reports/drafts/` 现存
**17 个 `.md`**(**口径:含本件;不含本件为 16 件**,另有 2 个 `.mermaid`),其中
**图谱系列 9 件长期在制**(**口径**:取自 `agenda.md` 立项记录与
`journal/daily/2026-10-15.md`「共 9 drafts」的既有计数;可复现构成 = **文件名含
「图谱」的 `.md` 6 件 + `.mermaid` 2 件 +《视觉语言进展-数据瓶颈破局-v0.1》1 件 = 9**;
⚠️ **若只按"文件名含图谱"计则为 8 件**,差额即该件——**本件沿用台账口径并写明构成,
以便日后重核**),而本所**已被自己的证据打过脸**:
2026-10-15 的**并发碰撞**事件中,两个实例**重复劳动**,根因之一就是中间层(latest.md / 在制件)
**未及时更新、不可被可靠检索**。
→ **可迁移结论**:在制件必须**可被下一轮检索到**,且新立项必须**显式声明"建立在哪件之上"**。

### §1.7 EvoScientist:类型化记忆边 + 技能蒸馏

**来源**:`github.com/EvoScientist/EvoScientist` 仓库页。**许可 = Apache-2.0**。
技术报告 arXiv:2603.08127(**未核**)。

**自述机制(逐条摘录)**:

- 「**Self-Evolving Memory** — Auto-distilled each turn, **self-linking into a knowledge graph
  that grows across sessions**.」
- 自链接的记忆边**有显式关系类型**:「(**complements / contradicts / supersedes**)」。
- 「**AutoSkills** — Distills recurring patterns from its own memory into reusable skills
  **on a schedule** — **proposed for your review** via `/autoskills`.」
- 「**Memory Retrieval** — agents run a **per-task preflight** over stored observations,
  using `search_observations`(ranked keyword search)和 `read_memory`。」
- 范式自述:从 **human-in-the-loop** 转向 **human-on-the-loop**。

**可迁移的三条**:

1. **记忆边类型化**(complements / contradicts / supersedes)。本所有 `controversies.md`
   (争论账本)与 `assumptions.md`(假设账本),但**知识卡片之间无类型化边**。
   → `contradicts` 边尤其有价值:**两件产物互相打脸**目前只能靠人读出来。
2. **每任务检索前哨**(per-task preflight)。本所的**开工仪式只在启动时读一次**五档案,
   之后每一件任务**不重新检索记忆**。→ 与 `honor.md` 的"同类过失先查"部分重叠,
   但覆盖不到 `knowledge/` 与 `drafts/`。
3. **AutoSkills 的"定期蒸馏 + 交人审阅"**。本所的对应物是**提案流**(`proposals.md`),
   但它是**反应式**的(由过失/复盘触发),**不是定期的**。→ 半采纳,见 §3 N5。

**⚠️ 未证实项**:该仓库页**未描述任何"避免重复失败方向"的机制**——本件**不主张**
它有(其 `supersedes` 边是否用于此,**未说明**)。
