## §0 结论先行

**这份 DSH 方案的核心判断是对的,而且它是对的这件事本身值得记一笔**:它说"治理不能写在自然语言的提醒里,必须上移到可执行层"——本所 2026-10-16 从另一条路(arXiv:2608.05179 的自主性五轴)独立得出了同构结论:「**本所的真缺口不在'更自主',而在'验证发生的位置'**」。**两条互不相干的路径收敛到同一句,提高了这句的置信度。**

但作为一份**落地方案**,它有四个结构性缺陷,其中一个会让整套门禁在最关键处失效:

1. **门禁的判定对象可能是它自己人写的账本**(§3.1)——G0/G1/G3 若判定"文献库里的引文是否被核验过",而库可被模型写入,则门可被伪造;若库只能被工具写入,则这三道门**恒真**,是冗余。**原方案没写"账本存在哪、谁能写"**——而这正是本所最熟的那个病(自我确认循环)在工程层的复现。
2. **把"人类终审"列进 Gate 表**(§3.2)——前五道"阻断推进",第六道"人类签字",混在一张表里制造伪完备感。人的否决权若作用在**成品**上,人已无力重算;正确位置是**证据计划**。
3. **"确定性"被滥用**(§3.3)——真正的确定性只覆盖"**有没有**",不覆盖"**够不够/对不对**"。方案没区分**存在性判定**与**充分性判定**,两者都叫"确定性",会产出"门全绿但论文很差"的绿灯幻觉。
4. **没有成本档位**(§3.4)——18 Phase × 7 Gate × 3 评审 subagent 对每篇都跑,成本会把人赶回"不用治理"那一侧。**治理方案若成本高于它防的损失,就会被绕过。**

另有一层**事实层问题**(§1):方案点名的 6 个插件/工具在精选列表与检索中**找不到**,而**真正最贴合它自己论点的 4 个插件被漏掉了**——其中 `dsh-context-guard` 几乎是它 §三 想要的 G5 的现成实现。这不影响方案的方向,但**照它去买插件会买不到**。

**WorkBuddy 侧的结论(§5)更重要,且与 DSH 不同**:WorkBuddy **没有可编程 Gate**——无 hooks 文档、`settings.json` 无 hooks 键、权限模型只有两档 + 路径级 `allow/ask`,**没有按工具名 deny 的持久配置**(§5.1 实测)。所以 DSH 方案的核心公式「**教 → 拦 → 证明**」在 WorkBuddy 上**缺了"拦"这一层的插座**,必须改成:

> **教 → 产证 → 重算 → 人裁**

差别不是措辞:DSH 能保证"**错必被拦**";WorkBuddy 只能保证"**错必留痕、痕必可重算**"。**说清这一点比画六道门有用**——因为本所已有实证(10-09 77.5 轴标误读潜伏 10 天、扩散 5 件产物):**唯一打破过自我确认循环的从来不是前置门,而是外部原文级重算**。前置门防"已知的错",可重算的留痕抓"没想到的错"。

**WorkBuddy 侧还捡到两件现成的**:①**哈希链式 append-only 审计日志原生已有**(`~/.workbuddy-ai/audit-log/`,实测 `sequence=4057`、`lastHash`、`closedSegments`),DSH 方案里"需要自制的 `ai-usage-audit` 插件"在本所**不必自制**,只需读取并投影;②**只读 subagent 的工具集是声明式的**(Plan/Explore 无 `Write`/`Edit`),所以"**评审者不得改稿**"在 WorkBuddy 上**能真做到机制化**——这是本所 P-022 的同构物,可直接用。

**最有实操价值的一条副产品(§5.2)**:本所 `AGENTS.md` **325 行 / 23,673 字节**,而本次会话注入的常驻层**在「档案结构」表处被 `[...too long, omitted...]` 截断**——被截掉的正好是文末「修订史」,**也就是 10-17 刚挂上去的「已批未并(v1.5 在制)」块**。**本所最重要的"未销账"挂账,恰好落在常驻层的截断区。** 这不是理论风险,是本次会话可复现的实测。

## §3 判定(二):四个结构性缺陷

### §3.1 【致命】门禁的判定对象,可能是它自己人写的账本

方案的 G0 是"文献库中每条引文是否经确定性工具检索验证",G1 是"每章至少 N 条证据注册",G3 是"正文引用的每个 ID 是否在文献库中存在"。三道门**都指向同一个东西:一个"文献库"**。

但方案**从未回答:这个库存在哪、谁有权写**。于是只有两种可能,两种都让门失效:

- **若库只能由工具写入**(`academic_search` 返回即入库):那么"未经核验的引用"在**类型上不可能存在**——引用只能从库里取。此时 **G0 恒真,G1/G3 是库的一次查询,不是门**。方案把它们画成三道门,是**把类型约束误当运行时检查**。
- **若模型可以写库**(在上下文里维护、或写进可写文件):那么门禁判定的是**模型自己填的表**,伪造成本为零。此时门的存在只制造安全感。

**→ 正确的做法不是加门,是收紧"引用的唯一生成路径"**:让 `section_writer` 的 `evidence_ids` 参数**只能取库内 id**(参数校验在工具签名上),库**只由工具 append 写入**。这是**类型系统**问题,不是门禁问题。**方案把顺序搞反了**:它 §二 说"前置约束"、§三 说 Gate,但**整篇重心在 Gate**,而真正的确定性在**数据源**——`dsh-lit-search` 之所以可信,不是因为有人检查它,是因为**检索路径唯一且数据源外部**(Crossref + OpenAlex)。

**一句话**:门禁防的是"绕过路径",而**消除路径比守住路径便宜一个数量级**。

### §3.2 【结构】把"人类终审"列进 Gate 表,制造伪完备

表里 G0–G4 的失败后果是"阻断/退回",G5 是"人类操作,不可自动化"。**六行并排,读起来像六道同等强度的门**,实际是五道自动 + 一道人。而人的那道**是唯一不可绕过的**,所以它的**输入质量决定整套治理的上限**——方案对"给人类看什么"只有一句"逐项签字"。

人在成品阶段**无力重算**:一篇 8,000 字稿件 + 40 条引文,人无法在合理时间内验完。所以**人的否决权必须前移**。`dsh-context-guard` 的做法更对,而且可以直接抄:

> **分两次审**:先审"agent 认为自己被要求做什么"(意图/契约),再单独审"agent 打算如何证明完成"(证据计划)。**人的否决作用在证明计划上,而不是在成品上。**

`dsh-spec-collab` 的同一条:AI 只能提交 Review Item 与候选 Patch,**人确认并保存**。`dsh-plannotator` 更进一步:draft 隔离、版本绑定、**stale-plan 拒绝**。

**→ 建议把 G5 从 Gate 表里移出**,单列为"**人裁点**",并规定每个裁点必须有**结构化输入**(契约 / 证据计划 / 披露事实表),不接受"看一遍稿子"。

### §3.3 【概念】"确定性"被滥用:存在性 ≠ 充分性

方案说 G0/G1/G3"判定逻辑应当是纯确定性代码,不经过 LLM"。这话对一半:

- **能确定性判定的只有"有没有"**:这条引文在不在库里、这个字段在不在、ID 对不对得上。
- **不能确定性判定的有"够不够、对不对"**:N 条证据是否**足以**支撑该章?评审意见被"回应"了,回应**是否成立**?

方案把两类都叫"确定性",于是产生一个具体风险:**七道门全绿,论文依然很差**——因为所有门都只检查了"存在"。这不是苛求,本所 P-020(复核强度分档)的核心就是"**这一档保证什么、不保证什么**"必须写在档上。

**→ 每道门必须随判定一起输出两个字段**:`guarantees`(保证什么)/ `not_guarantees`(不保证什么)。**没有这两个字段的门,不得写"阻断"。**

### §3.4 【工程】没有成本档位,治理会被自己的成本绕过

方案要求:18 Phase × 7 Gate × 3 个独立评审 subagent × 逐段 claim-evidence 结构化输出。**对每一篇都跑**。方案全文**没有一处成本估算**。

它自己引的 Co-Scientist 是"大部分算力用于验证"——但那是 Google 的算力。对个人研究者,这套流程的 token 成本很可能是常规写作的 5–10 倍(**估计,非测量**)。**制度设计的常识:治理方案若成本高于它防的损失,它会被绕过,而不是被遵守。** 本所对此有直接经验——P-006 成本闸、noop 折叠、连续 3 轮 noop 降频,全是"给治理装刹车"。

**→ 必须分档**(§6.1 给三档)。

### §3.5 【附带】subagent 的"独立上下文"不等于"独立评审"

方案说三 subagent 并行评审可避免"伪独立评审"。**这只解决了一半**:独立**上下文** ≠ 独立**模型** ≠ 独立**证据路径**。三个 subagent 若用同一模型、读同一份草稿,**它们的意见高度相关**——这正是本所 10-17 审批单自认的病(16 条提案自己审自己)。

**→ 真正的独立性只能靠换证据路径**:让评审 subagent 去**查原文**(它自己调检索工具),而不是让它**重读我的草稿**。方案里 `dsh-raven-research` 的"来源锚定 + sentence-per-line 最小 diff"其实提供了更好的机制,但方案没用上。

### §3.6 【自指】方案批评了"写在文档里的约束",自己却写了一条

§七 第 4 条说"未发表稿件的保密风险……**不要在插件中默认开启对外部 API 的自动传输**"。这是一句**提示**,不是**契约**。方案自己在 §一 刚说过"合规性要求必须落到 Plugin 的工具契约或 Gate 中"。

**→ 正确落法**:工具签名**不接受自由文本**,只接受已注册的 `material_id`;外发 API 只传 DOI / 标题 / 结构化字段,**摘要全文不出本机**;这条由 `dsh-plugin-writing-guard` 的"zero network"属性天然满足(方案漏了这件)。

## §4 更好的 DSH 落地方案(修订版)

把「**六道门**」换成「**一条唯一路径 + 两个账本 + 一个重算器 + 三个裁点**」:

| 原方案 | 修订后 | 改的理由 |
|---|---|---|
| G0 引文核验门 | **取消**。改为:引用只能由 `lit_search`/`academic_search` 返回的 `ref_id` 生成,**库只由工具 append 写入** | 消除路径优于守路径(§3.1) |

| G5 人类终审 | **移出 Gate 表**,改称"人裁点",且必须有结构化输入 | 不制造伪完备(§3.2) |

| (无) | **新增:三档成本** | 防被绕过(§3.4) |
| 自制 `ai-usage-audit` | **改用 `dsh-science-workbench` 的 Manifest + 输入输出哈希** | 已有现成载体 |

**一句话概括修订版**:
> **判定的权威性不来自"它是代码",而来自"它可被第三方独立重算"。** 所以设计的重心不是"加门",是**让每一道门的输入变成一份别人能拿去重跑的账本**。

## §5 WorkBuddy 落地方案

### §5.1 先量能力边界:WorkBuddy 与 DSH 不是同一个插座

> 全部为本机实测(2026-10-17 21:5x~22:0x),命令与路径见 §9。

| 层 | DSH | WorkBuddy 实况 | 后果 |
|---|---|---|---|
| **教** | Skill(`SKILL.md`,按需) | **同构**。用户级 `~/.workbuddy-ai/skills/`(**实测 22 个**)、项目级 `.workbuddy-ai/skills/`(本所实际用 `.zcode/skills/`,**6 个**),frontmatter = `name` + `description` | **可平移**,原方案的 Skill 设计建议直接可用 |
| **常驻** | `AGENTS.md` / 系统提示 | **`AGENTS.md` 每轮自动注入,但会被截断**。本所 `AGENTS.md` **325 行 / 23,673 字节**,本次会话注入在「档案结构」表处出现 `[...too long, omitted...]` | **常驻层有硬预算,尾部条款等于不存在**(§5.2) |
| **拦** | **Plugin(代码,可阻断工具调用)** | **未找到**。①官方文档导航**无 Hooks 页**;②`settings.json` 顶层键实测为 `sandbox` / `claw` / `enabledPlugins` / `pluginConfigs` / 两个修复标记,**无 `hooks`**;③权限模型官方口径只有两档:**Default Permissions / Full Access**,**无用户可写的 allowlist,无按工具名 deny 的持久配置**(**⚠️ "未找到"≠"不存在",见 §8.2**) | **无法做机制性阻断** —— 这是全部差异的根源 |
| **确定性** | Plugin 工具 | **三样可用**:①**MCP server**(`~/.workbuddy-ai/mcp.json` 的 `mcpServers`,自己的代码)②**脚本 + 退出码**(Skill 里规定 `exit≠0 → 停`)③**subagent 工具集声明式限制**(Plan/Explore **无 `Write`/`Edit`**) | 能做确定性,**但只能"可重算",不能"可阻断"** |
| **审计** | 需自制插件 | **原生已有,且是哈希链**:`~/.workbuddy-ai/audit-log/YYYY-MM-DD.jsonl` + `state.json`(`sequence` / `lastHash` / `closedSegments`,**实测 sequence=4057**,10-16 单日 468 条);另有 `changes-index/`、`changes-detail/`、`file-history/` | **不必自制**,只需**读取并投影成披露文本** |
| **调度** | Workflow | **Automations**(`rrule`),可建一次性与周期任务 | 可平移 |
| **产物呈现** | — | `present_files`(自动开预览 + 产物卡) | 本所"签发 → 交付"的天然出口 |

**三条由实测得出的硬结论**:

1. **能力边界可以机制化,行为规范不能。** "评审者不得改稿"在 WorkBuddy 上**能真做到**——用只读 subagent(声明式,是机制);"主 agent 不得引用未核验文献"**做不到机制化**——只能靠"引用只能从账本取"这一条**流程约束 + 事后重算**。**这条区分必须写进方案,否则会画出六道实际不存在的门。**
2. **"拦"没有插座,但"留痕"是原生强项。** 所以 WorkBuddy 版的重心必须从"**防止模型做错**"移到"**让做错留下可被外部发现并重算的痕迹**"。这不是降级:本所唯一一次打破自我确认循环(77.5 轴标误读,潜伏 10 天、扩散 5 件),靠的就是**外部原文级重算**,不是任何前置门。
3. **`AGENTS.md` 是唯一准常驻通道,但它是稀缺资源。** 见 §5.2。

### §5.2 一条实测发现:本所最重要的挂账,恰好落在截断区

`AGENTS.md` = 325 行。本次会话注入的常驻文本在**第 246 行「档案结构」表**处被截断。被截掉的是 **第 265–325 行的「修订史」**——**也就是 2026-10-17 刚挂上去的「已批未并(v1.5 在制,期限 2026-11-16)」块**(本所 P-019 的首次自我应用:已批未并 = 未销账,故写在宪法首页)。

**推论(不是理论风险,是可复现的实测)**:

> **凡"必须每轮都看见"的条款,不得写在 `AGENTS.md` 的尾部。** 而本所现行的做法恰恰是把最重要的挂账放在最后(修订史)。**位置即优先级,而截断把位置变成了否决权。**

**修正建议(三步,不改宪法条文,只改组织方式)**:

1. **常驻层瘦身**:`AGENTS.md` 压到 **≤120 行**,只放**六条不可妥协句**(行动分类红线 / 证据纪律"给不出处就写未证实" / 自审签发须复核 / 升级门 / 停工条件 / 七维披露不得留空)+ **指向全文的指针**。
2. **全文另置**:325 行完整版移入 `docs/constitution-full.md`(宪法全文,保留修订史),由技能 `constitution-kb` 按需加载——**该技能已存在,职责正好对上**。
3. **挂账前移**:「已批未并」块从修订史**移到文件头部**(第 2 屏内),并在 `heartbeat.md` 检查点第 6 步(未销账核对)直接引用。

> ⚠️ **本建议触及宪法结构,属升级门**:第 1 步改 `AGENTS.md` 篇幅与组织,须委托人批准。**本件只提方案,不动宪法。**

### §5.3 四层架构:教 → 产证 → 重算 → 人裁

```
L0 常驻层   AGENTS.md(≤120 行,六条红线 + 指针)          ← 稀缺,只放"忘了就完蛋"的
L1 规程层   Skills(一个 Skill 一个写作决策 + checks/ 脚本) ← 按需,不承担判定
L2 机制层   MCP server + 4 个脚本 + 只读 subagent          ← 唯一"硬"的地方
L3 人裁层   3 个裁点,每个必须有结构化输入                  ← 不签成品
```

#### L0 常驻层(≤120 行)

只放六条 + 指针。判据:**"如果这条被忽略,后果是不可逆的吗?"** 是 → 进 L0;否 → 进 L1 或 `heartbeat.md`。

#### L1 规程层(Skills)

沿用原方案的正确判断:**一个 Skill 只回答一个写作决策**(引言如何陈述贡献 / 讨论如何限定推广范围 / 相关工作如何划界),不写"大而全"的写作指南。**但加一条硬约束**:

> **每个写作 Skill 必须带 `checks/` 目录,里面是可执行脚本。Skill 正文只负责"何时跑哪个脚本",不负责"跑完算不算通过"。**

理由:Sskill 正文是**指令**,模型可以忽略;脚本退出码是**事实**,忽略不了——除非整个跳过,而跳过会留下"脚本未运行"的空白(可被 `disclose.py` 发现,§5.4)。

#### L2 机制层(这是替代 DSH Plugin 的东西)

**四个脚本 + 一个 MCP 封装 + 只读评审 subagent**。全部**只依赖标准库 + HTTP**,无模型参与。

| 件 | 输入 | 输出 | 判定 |
|---|---|---|---|
| `refs_verify.py` | 标题 / DOI / arXiv ID 列表 | `refs.jsonl`(append-only,`ref_id` / `doi` / `arxiv_id` / `title` / `year` / `source` / `verified_at` / `raw_hash`) | 三源交叉:Crossref + OpenAlex + arXiv。**任一源命中即入账,全不命中则 `status:"unverified"` 并拒绝分配 `ref_id`** |
| `claims_check.py` | `claims.jsonl` + `refs.jsonl` | FAIL 码列表 | 每个 `evidence_id` 必须在 `refs.jsonl` 存在且 `verified_at` 在 **N 天**内(N=90,可调);`support=="none"` 的 claim 必须带 `weakened:true` |
| `gate.py` | 两账本 + 稿件 | `{gate, verdict, codes, guarantees, not_guarantees}`,`exit 1` = FAIL | **必须输出 `guarantees`/`not_guarantees`**(§3.3 的修正) |
| `disclose.py` | `audit-log/*.jsonl` + 两账本 + 版本记录 | 七维披露表草稿 | 从审计日志统计工具类别与次数 → 第 3/4/5 维;从 `refs.jsonl` 来源分布 → 第 6 维;从版本记录 → **第 7 维(试了几版、报的哪版)** |

**`gate.py` 的关键设计(与 DSH 方案的分歧点)**:

```python
# 判定权威性来自"可被第三方独立重跑",不来自"它是代码"
OUT = {
  "gate": "G-cite",
  "verdict": "FAIL",
  "codes": ["REF_NOT_IN_LEDGER:R-007", "CLAIM_UNSUPPORTED:C-012"],
  "guarantees":   ["引文存在性", "引文与账本一致性", "claim 结构完整性"],
  "not_guarantees": ["论证充分性", "新颖性", "引文与 claim 的语义匹配"],
  "ledger_hashes": {"refs": "sha256:...", "claims": "sha256:..."},
  "rerun": "python3 checks/gate.py --manuscript draft.md"
}
```

`ledger_hashes` + `rerun` 两行是核心:**任何人拿到这两个哈希和一行命令,都能独立重算这个 FAIL**。这就是 WorkBuddy 上"机制"的全部含义——**不是拦得住,是赖不掉**。

**只读评审 subagent(WorkBuddy 的真机制)**:

| subagent | 工具集 | 干什么 | 机制保证 |
|---|---|---|---|
| 方法论评审 | **只读 + 检索** | 研究设计 / 统计推断 / 因果主张 | **无 `Write`/`Edit`,声明式,不可改稿** |
| 领域定位评审 | **只读 + 检索** | 文献覆盖 / 新颖性定位 / 与已有工作区分度 | 同上 |
| 魔鬼代言人 | **只读 + 检索** | 论证漏洞 / 过度概括 / 未讨论的替代解释 | 同上 |

**三者的独立性来自"各自去查原文",不来自"独立上下文"**(§3.5)。要求每个 subagent 的每条意见附**它自己检索到的外部来源**,否则该条意见不计入回应表。

#### L3 人裁层(三个裁点,不签成品)

| 裁点 | 何时 | 结构化输入(不给成品) | 不可让渡的判断 |
|---|---|---|---|
| **A 选题** | 动笔前 | 意图规格(要回答什么 / 不回答什么)+ 新颖性核查记录 + **离群候选 ≥1 个**(本所 P-027 多样性哨) | 这个空白是否值得填 |
| **B 证据计划** | 分节写之前 | 每章的 `claims.jsonl` 骨架 + `refs.jsonl` 命中率 + `gate.py` 的 `not_guarantees` 清单 | 这些证据是否**足以**支撑该章 |
| **C 披露** | 定稿后 | `disclose.py` 产出的七维表 + 审计日志摘要 + 未核实项清单 | 披露是否完整、措辞是否合规 |

**顺序不可换**:A → B → C。**B 是原方案最缺的一环**——它把人的否决权放在了还能改的时候。

### §5.4 为什么"脚本 + 只读 subagent"能部分替代 DSH 的 Plugin

诚实说清边界:

| 想防的错 | DSH 能做的 | WorkBuddy 能做的 | 差额 |
|---|---|---|---|
| 引用不存在的文献 | Gate 拒绝调用 | **引用只能从 `refs.jsonl` 取**;`gate.py` 事后重算;`disclose.py` 报"未核验条数" | 不能拦在调用前,**但能保证漏不掉** |
| 评审者偷改稿 | Plugin 权限 | **只读 subagent(声明式)** | **无差额**,这是真机制 |
| 跳过检查 | Plugin 强制 | `disclose.py` 发现"脚本未运行"→ 披露表留空 → 不得签发 | 不能强制跑,**但能发现没跑** |
| 声称"已完成" | Gate 查证据 | `gate.py` 的 `verdict` 是唯一完成凭证;**模型自述不构成完成** | 无差额(只要"完成"定义为"有 verdict 文件") |
| 未发表材料外传 | 工具契约 | MCP 工具**只接受 `material_id`,不接受自由文本**;检索只传 DOI/标题 | 无差额(契约在 MCP 侧) |

**结论句**:WorkBuddy 上"拦"缺位造成的净损失只有**一条**:不能在**调用前**阻止。其余四条都能用"**账本 + 重算 + 只读 subagent + 披露**"补上。**而这唯一一条损失,恰好是最不重要的那条**——因为调用前阻止防的是"已知的错",而本所的实证是:**真正造成扩散的错,都是当时没想到的错**(77.5 轴标误读:当时没有任何门能想到要查它)。

## §6 分档与最小可跑件

### §6.1 三档成本(原方案缺的)

| 档 | 触发 | 跑什么 | 相对成本 |
|---|---|---|---|
| **草稿档** | 日常写作、内部讨论 | `refs_verify` + `claims_check` | **1×** |
| **投稿档** | 准备外发(投稿仍为红色,由委托人执行) | + `gate.py` 全门 + **2 个只读评审 subagent**(方法论 / 领域)+ 回应表 | **2–3×**(估计) |
| **审计档** | 委托人要核 / 已有外流风险 / 重审触发 | + **3 个评审** + 逐条回应表 + **外部原文抽验 ≥3 条** + `disclose.py` | **4–6×**(估计) |

**降档规则(硬)**:预算不足时**降档而不是跳步**——草稿档允许不跑评审,但**不允许跳过 `refs_verify`**。理由:引文幻觉是唯一"事后无法补救"的错(已外流的假引文无法撤回)。

### §6.2 最小可跑件(建议作为下一件任务)

| 件 | 工作量 | 验收判据 |
|---|---|---|
| `checks/refs_verify.py` | 小 | 给定 5 条已知 DOI,4 条命中、1 条故意造假被标 `unverified`;`refs.jsonl` 追加不覆盖 |
| `checks/gate.py` | 小 | 构造 3 个用例(全绿 / 缺引文 / claim 无证据),退出码分别为 0 / 1 / 1;输出含 `guarantees`/`not_guarantees`/`ledger_hashes`/`rerun` |
| Skill `paper-cite-gate` | 小 | 正文只写"何时跑哪个脚本 + `exit≠0` 必须停";不含任何判定逻辑 |
| `checks/disclose.py` | 中 | 从 `audit-log` 真实数据生成七维表,第 3/4/5 维有实际计数,第 7 维读版本记录 |

**最小闭环**:`refs_verify` → `gate` → `disclose` 三件串起来,就能把本所现有的**手工七维披露**变成**机器生成的初稿**。这是本件最直接的落地收益,且**不依赖任何外部插件**。

## §7 明确不采纳的三条

1. **18 Phase / 7 Gate 的完整流水线照搬** —— 对单篇论文是过度工程。本所 G3 的产出是"可投稿级稿件",不是"顶会投稿流水线";照搬会把成本推到被绕过的那一侧(§3.4)。
2. **"AI 痕迹检测"作为任何形式的 Gate** —— 同意原方案"不作自动拒绝",但**理由要补全**:中文 AI 痕迹模式库是**经验性的、无公开标注基准**,假阳/假阴都不可控。按本所 P-020 的分档逻辑:**低置信判据只能进"提示档",不能进"阻断档"**。可用 `dsh-plugin-writing-guard`(本地、零网络、零 LLM)作自检,**不进 Gate**。
3. **把 subagent 的"独立上下文"当"独立评审"** —— 必须换**证据路径**(让它查原文),否则三个 subagent 的意见高度相关,只是把"伪独立"从串行搬到并行(§3.5)。

## §8 残余不确定性(诚实)

1. **本机无 DSH 环境**:§1 的插件能力全部来自**页面核读**,未实际安装运行。插件行为可能与描述不符(且 DSH 仍在 developer preview,兼容性随宿主漂移)。
2. **§5.1 的"无 hooks"是"未找到"而非"不存在"**:官方文档导航无 Hooks 页、`settings.json` 无 `hooks` 键。**可能存在未文档化的机制**。若存在,§5 的架构可简化(但"账本 + 重算"仍然必要,因为它防的是"没想到的错")。
3. **成本倍数是估计**:1× / 2–3× / 4–6× 无实测依据,只用于表达档位关系,**不可当预算数字用**。
4. **§5.2 的截断位置依赖本次注入**:不同会话/不同版本客户端的截断阈值可能不同。**结论("尾部条款不可靠")稳健,具体行号不稳健。**
5. **未做真实写作跑测**:四层架构与三档成本**没有在真实稿件上跑过**,§5.4 的"净损失只有一条"是**判断,非测量**。
6. **§5.2 第 1 步触及宪法结构**(改 `AGENTS.md` 篇幅与组织),**属升级门,须委托人批准**。
