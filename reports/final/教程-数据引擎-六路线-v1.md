## 0. 导言:为什么"数据引擎"是一等瓶颈

操作(manipulation)研究里,**数据成本直接决定方法能否被复现**。透镜④的问句是:
"**要拿到 X 规模、Y 形态的机器人数据,该走哪条管线,代价与合法性边界在哪?**"
——它是四条透镜里最"工程"、也最"钱"的一条。

三股力量对数据有**三种态度**(这是判断):

- **端到端规模化**:把数据当**工业品**——采更多(产业遥操作 + 异构语料);
- **结构化分解**:把数据当**可造的中间物**——造更多(人演示转机器人 + 引擎扩增);
- **Agentic / 程序合成**:把数据当**可推理、可回收的信号**——推理出来、回收回来。

**本教程解决一个问题**:给定一个操作任务,**数据该从哪来、怎么选、怎么复现、许可能不能用**。

## 1. 六条路线速览 + 选型决策树

| 路线 | 逻辑 | 代表(已核实) |
|---|---|---|
| **A 真机遥操作规模化** | 硬件 + 人力换数据 | ALOHA·ACT / DROID / OXE / AgiBot World / MATE / GAE |
| **B 人演示 → 机器人** | 用最便宜最多样的人演示 | Morphometric / DexRoam / UMR / Praxis / KnowDemo / Ego2Robot / VisTacAlign / UVTA / EgoSpeedUp |
| **C 程序化仿真合成** | 引擎扩增演示 | MimicGen / DexMimicGen / DynaForge / PhyVisGen / SynthDemo-RL |
| **D Real2Sim2Real 资产化** | 现实重建 → 仿真造数 → 零样本迁回 | Real-to-Sim-to-Real / DEXTERA / ZeroBot / DREAM |
| **E 数据"翻新"与复用** | 回收被丢弃的数据 | Kintsugi-VLA / ε4P |
| **F 异构语料工程** | 异构源对齐到统一表示 | InternW0-Δ / WB-WAM |

**选型决策树(这是判断)**:

```
有真机 + 预算 + 人手?           → 路线 A(最稳,可复现性最高)
想省掉昂贵遥操作?               → 路线 B(人演示,但要造对齐管线)
有仿真资产 / 物理模型?          → 路线 C(引擎扩增)
只有单张图 / 单视图?            → 路线 D(资产化,门槛已骤降)
已有失败 / 低质数据在手上?      → 路线 E(翻新,零新增采集)
多源数据要对齐成一个库?         → 路线 F(异构语料)
```

**⚠️ 关键认知**:六条路线**不是互斥的**——**真问题不是"选哪条",而是"按什么配比混"**(见 §8)。

## 2. 路线 A · 真机遥操作规模化

**逻辑**:建标准化采集管线 + 分布式采集网络,把"真机演示"当工业品生产。

**代表与口径(全部 abs 页已核实)**:

- **ALOHA / ACT**(2304.13705):自研**低成本遥操作接口**直接采真机演示;**6 项精细任务
  80–90% 成功**,**仅 10 分钟演示**;
- **DROID**(2403.12945):**76k** 轨迹 / **350 小时** / **564 场景** / **84**(abs 口径;
  正文与官方页为 **86**)任务 / **50** 采集员 / 12 个月;
- **OXE / RT-X**(2310.08864):**22** 机器人 / **21** 机构 / **527** skills / **160,266** tasks;
  **标准化数据格式**使跨本体聚合成为可能;
- **AgiBot World**(2503.06669):**>100 万条**轨迹 / **217** 任务;可从夹爪扩展到灵巧手与视触觉;
- **MATE**(2609.26520):多智能体**虚拟**遥操作平台;**24.1 小时**协作行为 / **2,500** 联合回合。

**复现步骤(以 ALOHA 范式为例)**:

1. **硬件**:按 ALOHA 开源硬件搭双臂主从遥操作 rig(**代码/硬件 MIT**);
2. **采集**:操作员遥操作采演示 → 存为标准格式(**符合 OXE / LeRobot 格式**);
3. **训练**:ACT / Diffusion Policy(动作分块);
4. **评**:固定任务集 × 每任务 50 回合。

**许可**:ALOHA / Mobile ALOHA = **MIT**(宽松,硬件软件均可自由复用);
⚠️ **DROID 官方代码无许可文件 → 实际不可复用**(数据 CC BY 4.0 可用)。

**踩坑**:①**采集节拍**是瓶颈(每小时有效轨迹数,待实测);②**环境重置成本**高;
③**力反馈缺失**(手持夹爪范式)会影响精细力控任务。

## 3. 路线 B · 人演示 → 机器人(免遥操作)

**逻辑**:**人**是最大、最便宜、最多样的演示源;把人的动作搬到机器人上,绕开昂贵遥操作。

**代表与口径(已核实)**:

- **Morphometric Imitation**(2609.28660):三阶段(形态优化 → 残差 RL → 蒸馏);
  Sharpa 手真机 **89.3%**(300 试验 / 30 物体 / 10 类,零样本);
- **DexRoam**(2609.35761):**tracker-free 采集**(消费级 VR + 头戴立体相机);
  真机 **GR00T N1.7 29%→56%、π0.5 32%→57%**,**一半机器人演示**即匹配纯机器人训练;
- **UMR**(2609.34256):统一动作表示;LIBERO **97.5%** / RLBench **85.7%**;
  真机**每任务 ~10 分钟人演示、无机器人演示**,六设定均值 **91.7% vs HumanEgo 60.8%**;
- **Praxis**(2609.30735):**每技能仅一条**人类自中心视频演示;
- **Ego2Robot**(2608.02580):自中心人视频 → 机器人数据;**18,561 小时 / 15 本体**。

**新观察(这是判断)**:路线 B 的焦点从"**重定向动作**"升级到"**对齐每一个模态**"
(本体 / 动作语义 / 时序 / 视觉 / 触觉)——DexRoam 三阶段、VisTacAlign 视觉+触觉双对齐。

**复现步骤**:

1. **采集**:手持夹爪 + 腕部相机(**UMI / PolyUMI**,免标定、本体无关)或 VR / 动捕;
2. **对齐**:逐模态对齐(本体映射 → 动作语义 → 时序重定时 → 视觉替换 → 触觉对齐);
3. **训练**:模仿学习 / VLA 微调。

**许可**:⚠️ **UMI 软硬件"开源"但许可类型未核**(**不得默认 MIT**);PolyUMI 已开源(待核实许可)。

**踩坑**:①**对齐成本 vs 绕开损失**(全对齐保真但贵;绕开依赖中间表示覆盖);
②**视频保真度损失如何影响下游未被单独测**(透镜④开放问题 2)。

## 4. 路线 C · 程序化仿真合成

**逻辑**:少量人演 → 仿真中自动扩增海量**物理可行**演示,用引擎替代采集。

**代表与口径(已核实)**:

- **MimicGen**(2310.17596):~**200** 条人演 → **50K+** 演示 / **18** 任务;
- **DexMimicGen**(2410.24185):**60** 条人演 → **21K** 演示(双臂灵巧 / 人形);
- **DynaForge**(2609.25631):规划引导残差学习生成**动态**演示;九仿真任务生成成功率
  **41.30% → 78.37%**;
- **PhyVisGen**(2609.25653):物理侧 IPC 高保真软接触 + 视觉侧实时路径追踪;
  纯合成演示策略在 **5 项真机任务 65–95%**,**无真机演示、无微调**;
- **SynthDemo-RL**(2609.21650):教师-学生;**每任务 50 条合成轨迹、无新人演示**,
  在 LIBERO-PRO 上救回 **27/27** 个零成功任务;标准 LIBERO **96.0%**。

**复现步骤**:

1. **仿真环境**:Isaac 系(MimicGen 系环境);
2. **源演示**:少量人演 / 遥操作作为"种子";
3. **扩增**:程序化生成(规划 + 残差 / 资产化);
4. **训练**:用合成数据训策略 → 迁真机。

**许可**:**数据 CC BY 4.0**(宽松);⚠️ **代码为 NVIDIA 自定义许可(非 OSI,勿当 MIT/Apache)**。

**踩坑**:①**分布 / 接触物理差距**(Real-to-Sim-to-Real 警告"便宜不等于无损");
②**域差**(渲染 vs 真实成像)影响合成数据可用性。

## 5. 路线 D · Real2Sim2Real 资产化合成

**逻辑**:从现实**重建资产**,在仿真里造数据,再零样本迁回现实——**免源轨迹**。

**代表与口径(已核实)**:

- **Real-to-Sim-to-Real**(2609.18293):**函数保持**的约束引导网格变形 + 物理一致位姿转移;
  ⚠️ 明说标准形状增广会**破坏任务关键几何界面**;
- **DEXTERA**(2609.21045):**单张 RGB 图** → 四阶段资产化;sim-real 共训 **29.2%→61.9%**;
- **ZeroBot**(2609.34010):**零人演示 / 零预训练 / 零物体模型**;单视图 + 目标位姿 →
  image-to-3D;**87%** 成功 / 平均训练 **119 秒**;
- **DREAM**(2608.29078):**部署期**演示生成;LLM 把语言指令转符号目标 → TAMP 生成轨迹。

**复现步骤**:

1. **重建**:单图 / 单视图 → 3D 资产(高斯 / mesh);
2. **造数**:仿真任务原语 + 物体中心轨迹合成;
3. **训练 + 零样本迁移**。

**许可**:随各项目(**待核实**);**门槛骤降**是本窗口新动向(这是判断)。

**踩坑**:**"函数保持"是硬约束**——便宜不等于无损,任务关键几何仍必须对齐。

## 6. 路线 E · 数据"翻新"与复用(**本窗口新出现的一类**)

**逻辑**:不造新数据——**把本会被丢弃的数据回收成训练信号**。

**代表与口径(已核实)**:

- **Kintsugi-VLA**(2609.31048):把仿真中**失败 rollout** 转成定向**恢复数据**;
  Franka 任务恢复成功率 **34.6% / 38.4%**,较同窗口均匀采样 **+5.8 / +6.7 个百分点**;
- **ε4P**(2609.26672):翻新**低精度目标任务数据** + **高精度错配任务数据**;
  真机亚毫米级任务性能**至多 +31.7 个百分点**。

**核心判断(这是判断)**:数据的价值**不在"成功与否",而在"噪声级 / 状态分布上的信息量"**。

**复现步骤**:

1. **留档**:采集时**不要丢弃**失败 / 低质轨迹,打上元标注;
2. **定位**:估计"可恢复性",找"终端低可恢复性前沿";
3. **翻新**:转成恢复数据 / 迁移精度 → 入训练集。

**踩坑**:①**"一段坏数据的信息量"缺通用度量**(透镜④开放问题 4);
②翻新数据可能**反拖累**干净任务(Kintsugi 报 76.8%→74.7%,**这是绝对成绩的下降**,需权衡)。

## 7. 路线 F · 异构语料工程(**本窗口新出现的第二类**)

**逻辑**:把机器人数据 + 人演示 + UMI + 合成数据**对齐到统一 state-action 表示**,
做成 **20K+ 小时的"语料"**。

**代表与口径(已核实)**:

- **InternW0-Δ**(2609.31394):异构语料按统一表示策展;**>20K 小时**;承诺开源
  代码 / 权重 / 数据管线 / 处理后数据;
- **WB-WAM**(2609.34199):共享物理动作空间;**1,880.2 小时**部分标注视频与运动数据;
  HumanoidArena **81.9%**,真机 5 任务均值 **84.0%**。

**复现步骤**:①定义统一表示 → ②各源对齐 → ③联合训练(MoT / 共享动作空间)。

**踩坑**:**统一表示可能抹掉源特有结构**(透镜④开放问题 5)——**"哪种统一表示丢的信息更少"尚无工作比较**。

## 8. 配比:真机 : 合成 : 翻新 怎么定(**本教程的增量点**)

**为什么是配比不是站队(这是判断)**:合成可用(MimicGen 用 ~200 条人演换 50K+),
但**便宜不等于无损**(Real-to-Sim-to-Real);路线 E 又显示**坏数据也有信息**——
于是"真机 vs 合成"的二分**本身不够**,真问题是**配比**。

**⚠️ 现成缺口**:**没有**同策略同预算下真机 vs 合成 vs 混合的受控对比
(账本二缺口二 / 透镜④开放问题 1)——**"边际投入该给采集还是给合成"目前只能拍脑袋**。

**实验设计(可直接照做)**:

| 项 | 内容 |
|---|---|
| **自变量** | 数据配比(真机 : 合成 : 翻新),**固定总预算 / 固定策略 / 固定任务集**下扫描 |
| **因变量** | 任务成功率(主)、数据效率(次) |
| **对照** | 纯真机 / 纯合成 / **纯视觉基线** |
| **样本量** | 每格 ≥ K 任务 × 50 回合(**统计功效待定**) |
| **混杂控制** | 固定任务集 / 固定演示数口径 / 固定训练预算 / 同种子多次 |
| **产出** | 配比-成功率曲线(**第三方可复跑**) |

> 本实验设计与 **G2 规格书 §7.2** 同一设计——**平台跑出的曲线将来喂 G4**。

## 10. 踩坑清单

| 坑 | 症状 | 规避 |
|---|---|---|
| **多相机时间不同步** | 数据错位、策略学错 | 硬件触发 / PTP;软同步易漂移 |
| **仿真-真机域差** | 合成数据训的策略真机失效 | 物理保真合成 / 域随机化 / 少真机微调 |
| **许可传染** | 商用被 NC 条款卡 | 查三维选型表;聚合库逐源看 |
| **"数据量"口径混用** | 跨论文规模不可比 | 先确认数的是轨迹 / 小时 / 任务 / 场景 / 本体 |
| **样本薄的"新路线"** | 路线 E/F 各仅 2 篇证据 | 引用时标明样本量(这是判断) |
| **数字-结论错配** | 把"高出 X 分"读成"成绩 X" | 逐条标口径(P-004 守则) |

## 结论

1. **六条路线各有其位**:A 最稳(可复现性高)、B 最省遥操作、C/D 门槛已降、
   E 零新增采集、F 面向预训练规模;**选型先看"手上有什么"**(真机? 图? 坏数据? 多源?)。
