# 方向线精读 · 批 5:机制层——组件怎么坏、度量怎么选(2026-10-27)

> 性质:补"被测对象内部"的知识。前四批解决"怎么测",本批解决"**为什么曲线会长成那样**"。
> 证据等级:FoundationPose / STRAP / PointNet++ / DINOv2 / XMem / Grounding DINO / AnyGrasp = abs + 全文(关键句主会话独立复核);OT 与分段两篇 = 摘要级(标明)。
> **本批两条会改实验设计的结论**:§3(编码器选择几乎不重要)与 §4(度量与 N 交互 = 致命混淆)。

## 0. 两条最要紧的(这是判断)

**① 视觉编码器选谁,在机器人子轨迹检索上几乎不重要。**

STRAP 原文:*"We don't find any representation to significantly outperform the other with **DINOv2 separated from CLIP by only +0.7% across all 10 tasks**."* 表 1 注释:*"DINOv2 and CLIP features perform similarly, making STRAP flexible in the encoder choice."*(主会话 curl 复核,逐字命中)

**为什么反直觉**:DINOv2 在**图像实例检索**上碾压 CLIP(Hard 子集 Oxford/Paris:mAP 52.3/82.6 vs 19.7/60.2)。但那个优势**没有迁移到"动作片段检索"**。
→ **后果**:①我们**不应该**在 E2 里花预算做编码器消融——那是已知的零效应;②更重要的,**检索质量的瓶颈不在表征,在度量与对齐**。这把研究重心从"换个更好的编码器"推到"换个正确的相似度",方向更清楚。

**② 检索度量会随库规模 N 退化——这会让我们的 N 扫描得出错误结论。**

三条机制(判断,有文献支撑):
1. **hubness / 距离集中**:d 固定时 N 增大,最近与次近距离差收缩,少数 hub 被反复召回。**KoLeo 消融是直接反证**——DINOv2 仅"把特征铺开"就带来 *"instance retrieval performance improves by more than 8%"*,说明该度量对**分布形状**极敏感,而形状随 N 变。
2. **极值偏置**:DTW / Chamfer / OT 都是 **min 型统计量**,候选越多 min 被拉得越低;S-DTW 的自由端点还让**长参考天然占优**。
3. **度量容量上限**:余弦只有 d 维自由度,对几十维手工运动学特征,N 大时近邻结构退化。

**后果(关键)**:度量退化与预算效应**同向**——N 大 → 度量退化 → 看起来"加库没用"。**这会把等值线系统性压平,而我们无法区分"库没用"与"度量坏了"。**

→ **E2 必须加一条设计**(见 §5):**固定一个与 N 无关的度量做主扫描,另单跑一条"余弦 × N"对照臂**,专门量出度量退化斜率。**没有这条对照臂,N 轴结论不可解释。**

## 1. 三个组件的输入输出契约与失效模式

| 组件 | 输入 | 输出 | 硬先验 |
|---|---|---|---|
| Grounding DINO | 图像 + 文本 | **框 + 短语**(不出 mask) | 无 mask;需阈值/NMS |
| XMem | 视频 + **首帧 mask** | 逐帧 mask | 半监督,**首帧必须人工或外接 SAM** |
| FoundationPose | **RGB-D** + 2D 框 | 6D 位姿 | **CAD 模型 或 ~16 张带位姿的参考图**;内参 |
| AnyGrasp(可选) | 单视角点云 | 7-DoF 抓取 + 置信分 | 内参、夹爪宽度;无需模型 |

**两处容易记错、必须写准**:
- **Grounding DINO 不做分割**:*"cannot be used for segmentation tasks like GLIPv2"*。所以"Grounding DINO + XMem"这条链**中间缺一环**(首帧 mask 从哪来),MT3 论文写的是"分割 + 传播",这一环在实现里必须补。
- **FoundationPose 吃的是 RGB-D,不是纯点云**;2D 检测是外部的,**分割错会原样传下去**。

### 1.1 失效模式(本批最有用的表)

| 模式 | 为什么坏(机制) | 量化 |
|---|---|---|
| **对称 / 多峰** | 回归取**均值** → 得到一个不存在的朝向;ICP 目标多极小 | FP T-LESS **AR 83.0** vs MegaPose 54.3 |
| 遮挡 | 检测先崩,位姿无从谈起 | 仅自陈,无数字 |
| **透明 / 反光** | 深度缺失 → 点云空 | AnyGrasp **直接排除**此类物体 |
| 纹理缺失 | 对应关系退化,只剩几何 | FP 自陈失败组合 |
| 细长 | 点云稀疏 + 夹爪宽度受限 | 仅 <3mm 碎片定性 |
| **快动 / 模糊** | 记忆更新跟不上 | XMem 唯一自陈失效 |
| 长尾小物 | 900 query 上限,小目标 token 少 | GD 在 LVIS rare 不如 GLIP |
| **同类实例** | 记忆按外观读,不按身份 | XMem 鸟群串例 |

**两条跨模块机制(容易被忽略)**:
- **检测阈值是隐变量**:GD 的框数随阈值单调变化,而阈值又决定 FP 的初始化框与深度中位数 → **调一个阈值会同时改变分割与位姿的结果**,做消融时必须钉死。
- **XMem 的长时记忆是压缩原型**:长遮挡后细节**不可恢复**(不是"慢慢变差",是"丢了就没了")。

### 1.2 FoundationPose 相对"回归 + ICP"改了什么(机制层)

1. **不回归,先造假设再判别**。对称/遮挡下位姿后验是多峰的,回归输出均值 = 一个不存在的朝向。FP 用 icosphere 采 Ns·Ni 个全局假设,各自精化,再用分层排序网络在 K 个假设间做 self-attention 打分,**选一个模式**。→ T-LESS 的 83.0 不是"回归更准",是"不再取平均"。
2. **精化 = learned render-and-compare**。输入渲染 RGB-D 与观测 crop,输出相机系 Δt、ΔR(**解耦**,避免平移依赖朝向),可迭代;crop 按假设位姿裁,等于把平移误差变成可学的视觉信号。作者明说**不需要 ICP**:*"without fine-tuning on the target dataset or ICP refinement"*。
3. **model-free 分支**:神经 SDF + 颜色场从约 16 张参考图合成任意视角 RGB-D,把"要 CAD"降级成"要几张**带位姿标注**的图"。

**算力**:1.3 s/物体(init 4 ms、refine 0.88 s、select 0.42 s),tracking 32 Hz,RTX 3090。→ **单卡可,但估计非实时**;若我们 E3 要在真机闭环里用它,必须按 1.3 s 预算设计控制频率。

**精度**:YCB-V model-free ADD-S/ADD = 97.4/91.5;LINEMOD ADD-0.1d = 99.9;BOP 三集 AR 83.3。

## 2. 归因:三类错误在观测上**不能**直接分开

**这是本批对我们"阶段级归因"最重要的一条。**

单看端到端结果,**"检索错 / 分割错 / 位姿错"无法分离**。MT3 报的"检索 22.3%"如果是端到端单标签归类,**它不可信**——因为至少四类错误会互相伪装:

| 真实原因 | 会被误判成 | 机制 |
|---|---|---|
| **分割错** | **位姿错** | mask 混入桌面/邻物 → 深度中位数初值偏移 → refinement **自信地收敛到错位姿**,而位姿模块看不到 mask 错 |
| 对称翻转 | 分割错 | 残差大但 mask 对 |
| 检索到相似物 | 位姿错 | **对错物体估得很准** |
| XMem 漂移 | 检索错 | 首帧其实是对的 |

**→ 唯一可靠的做法:oracle 替换阶梯 + 反事实臂。**
- 用 **GT mask** 重跑:若 ADD 显著下降 → 分割归因;
- mask 对、margin 小、**翻转 180° 后 ADD-S 正常** → 对称歧义;
- 三者都正常但任务失败 → 身份/检索。
- **对 10% 的 episode 跑 oracle mask / oracle pose 两支反事实**——这是把 22.3% 拆成三项的**唯一证据**。

**必须记录的中间量(否则事后只能靠猜)**:
- 每帧:prompt、top-k 框 + 分数、mask、mask 面积、重检测 IoU、mask 内点数/深度有效率;
- 位姿:top-K 假设 + 分数、**margin(top1 与 top2 分数间距)**、迭代 Δ 范数、fitness/inlier RMSE、**帧间旋转跳变**;
- 身份:crop 嵌入相似度;
- 动作:grasp pose 与成败。

**⚠️ 一条指标陷阱**:**只报 ADD 是错的**。对称物体上 ADD 会把**正确**位姿记成错误,必须同时报 **ADD-S**。我们若引用别人的位姿精度,必须确认它报的是哪个。

## 3. 度量族:余弦缺的是"显式对应"

| 度量 | 适用 | 机制代价 | 失效 |
|---|---|---|---|
| **余弦** | 压成单向量后的语义相似 | 无点对点对应;时间被抹平 | 外观方差主导;整体近但局部错位仍判近 |
| **Chamfer** | 点云几何 | 双向最近点求和,**多对一** | 对密度与离群点敏感 |
| **EMD / OT** | 点云 + 轨迹对齐 | 质量守恒、一一对应,**线性规划级** | 计算贵 |
| **SWD** | 点云 | 投影到一维排序比分布,置换不变、近线性 | 投影方向数需调 |
| **S-DTW** | 变长子序列 | 时间 warp 吸收速度/时长差 | 见下 |

**S-DTW 的四个失效点(必须记住,因为我们要用它)**:
1. 只 warp 时间**不 warp 幅值** → 慢而大的动作与快而小的动作代价不可比;
2. **退化匹配**:原文 *"To avoid degenerate matches, we limit the step size of the S-DTW backtracking to [1,2]"* ——放开步长则最优解塌缩为"一帧对多帧"、代价趋零(**极值偏置,参考越长越严重**);
3. **累计代价随路径长度增长** → 跨 query 的 top-K **不可比**,系统性偏向短路径/长参考;
4. 只对齐时序**不对齐因果** → 推与拉在嵌入上相近即低代价。

**复杂度**:距离矩阵 O(n·m·E),DTW O(n·m),全库 O(N·M),*"scales linearly with the size of D_prior"*;DROID(76k)≈**300 s**。→ **N 扫描的成本是线性的,可承受**(与批 3 的机时核算一致)。

**OT 用于轨迹**:OTR(2303.13971)用 *"optimal transport to compute an optimal alignment between an unlabeled trajectory ... and an expert demonstration"*(摘要级,未读全文)。

**分段**:STRAP 用**速度阈值**(*"transition states where the absolute velocity drops below a threshold: ||ẋ|| < ε"*,并把相邻段合并到 *"all are ≥ 20"*)。这是**运动学而非固定窗**,比等长滑窗原则化,但两个超参(ε、最小段长)对**无停顿动作(搅拌、擦拭)完全失效**,作者自评 *"This procedure can certainly be improved further"*。
更原则化的方向(判断):**多信号变点检测(速度/曲率/接触)**,且**最小段长应由下游可复用性决定,而不是拍一个 20**。

## 4. 度量 × N 的交互:为什么这是致命混淆

见 §0 第②条。补充一条**方向性推理**(判断,待验):

若 N 增大导致 top-K 里假邻居比例上升,那么"**最优 K 会随 N 增大而左移或提前饱和**"——这与朴素直觉("库大了就能多用几条")**方向相反**。
→ **这给出一个可测且非平凡的预测**,比"曲线画出来了"有力得多(见 §6 H1 修订)。

---

## 5. 对 E2 设计的四条修改(本轮直接产出)

1. **不做编码器消融**。STRAP 已证 DINOv2 vs CLIP 差 +0.7%,这个预算是浪费。改用**冻结 DINOv2 + 说明"编码器选择对本任务非敏感(引 STRAP)"**。
2. **主扫描固定一个与 N 无关的度量**(建议 **S-DTW 或 OT**:对时长/采样率不变、免训练);**余弦作独立对照臂**,单跑一条"N × 余弦"曲线,**专量度量退化斜率**。
3. **所有度量归一到同一可解释量纲**(例如 top-K 的**代价分位数**),否则"K"的有效含义会被度量偷偷改写。
4. **加反事实臂**:对 10% episode 跑 **oracle mask** 与 **oracle pose**,否则阶段归因无证据。

## 6. 假设 H1 修订(承批 4)

**原 H1**:最优 K 与检索精度耦合(检索越准,最优点越右移)。
**修订 H1'**:**最优 K 是"该 N 下的检索精度"的函数,而不是 N 本身的函数**;由于度量随 N 退化,**最优 K 可能随 N 增大而左移或提前饱和**。
**为什么修订**:原版把 N 与精度当成同向,忽略了 §4 的退化机制。修订版把两者分开,并给出**方向相反的预测**——这正是可证伪的地方。
**怎么测**:在每个 N 上先测 **top-1 检索精度**(用人工标注的小样本,约 100 条 query 足够),再画"最优 K vs top-1 精度"的散点。若散点落在一条单调曲线上 → H1' 成立;若最优 K 与 N 单调而与精度无关 → H1' 被证伪,改回"库规模本身有独立效应"。
