## 0. 本批两条最硬的收获(这是判断)

**收获一:失败归因可以做成统计模型,不必只做协议。**

RoboArena 的聚合模型是 `θ_p + τ_t + ν_t + ψ_{p,t}`(策略能力 + 潜在任务桶 + 桶内难度 + 策略×任务偏移),用 EM + clipped Newton 拟合,平局用 Davidson 扩展单标量 ν_tie。
→ **直接扩展**:加一个**阶段项** `σ_{p,t,s}`(策略×任务×阶段),就能把"某策略在对齐阶段显著更差"变成一个**可给置信区间的估计**,而不是一句"我们观察到"。这是领先点③从"协议"升级为"模型"的具体路径,也是本批最有价值的方法学产出。

**收获二:领域最好的两个评测协议,都没有报失败归因。**

RoboArena 只有 LLM 生成的定性 failure modes(附录 F)+ 11% 的"偏好与 progress 背离";COLOSSEUM 只有 14 个扰动轴的降幅 + 配图说明。**两篇都没有"哪一步断了"的测量,也都没有 context/compute 预算轴。** 这是空位的直接证据,而且是在**最讲究测量的两篇**里空着——比"没人做"更有说服力。

## 1. RoboArena(arXiv:2506.18123v2,CoRL 2025 / PMLR 305:336-364)

**⚠️ ID 更正**:批 1 记录只写了 venue,未记 ID;本次核定 **2506.18123**(v1 2025-06-22,v2 2025-11-29)。32 位作者,一作 Atreya;Berkeley / Stanford / UW / Montreal / NVIDIA / UPenn / UT Austin / Yonsei。

### 1.1 它反对什么(原文)

- *"existing approaches for robot benchmarking typically rely on heavy standardization ... and do not readily scale"*(Abstract)
- *"maintaining large, centralized fleets of evaluation robots, and manufacturing differences between said robots"*(§1)

### 1.2 机制

- 中心服务器**随机抽两个策略**下发;评测者自选场景与指令;**同一对比较内锁死初始条件**,两策略背靠背各跑 1 次至完成或超时(超时值未获取);**不同比较之间可随意换场景**(§3.1)。
- 双盲 = 只给评测者远端推理服务器 IP。**偏好判定完全交给评测者**:*"we leave it to the evaluator to decide how to determine their policy preference"*。
- 反馈三项:0–100 的 progress、二值偏好、自由文本。
- 聚合:`θ_p + τ_t + ν_t + ψ_{p,t}`,潜在任务桶 **T=60**(搜索 10–200),EM + clipped Newton(Eq.1, Tab.1)。平局用 Davidson 扩展,单标量 ν_tie,初值 0.5(附录 B.1);BT 基线把平局记半胜。
- **无功效分析**:只说 100 对比较即收敛(§5.3);612 对是累计量,不是设计样本量。

### 1.3 数字(主会话逐条复核)

| 数字 | 内容 |
|---|---|
| **7 / 7** | 7 个通用策略 × 7 所大学 |
| **612** | 累计成对比较 |
| **4,284** | 累计评测 episode(= 计算 oracle 排名用的全量) |
| **100** | 收敛所需成对比较数(*"converges to high-quality rankings within just 100 pairwise comparisons"*) |
| r = .69/.90/.97/.98/.98 | Regular/Elo/BT/TASK/PROG 与 oracle 排名的相关(图 6) |
| MMRV% = 13/5.7/2.7/1.8/1.1 | 同上,平均排名偏差 |
| **11%** | A/B 偏好与 progress 背离的比例(附录 D) |

### 1.4 局限与对我们的三条可用 / 三条反对

**可用**
1. **对内锁初始条件**——把场景方差从比较里消掉。我们的阶段归因必须让两策略跑同一个 episode。
2. **潜在难度桶 + policy×task 偏移**——把异质难度显式建模而不是当噪声,且**免标注**。→ 加 stage 随机效应即 §0 收获一。
3. **预算–精度曲线**(图 7:横轴 episode 数,纵轴与 oracle 的相关)。→ 我们把横轴换成 **context 预算 B**,纵轴换成"排序相关 + 归因误差",就是我们的核心图。

**反对**
1. **只报聚合排名不报方差**:图 6/表 2 无可核验 CI;图注与正文均未说明误差棒/阴影带的构造与置信水平。
2. **"自由选任务"做不了因果**:作者自陈 *"challenging to perform experiments that only vary a single condition at a time"*(§7)。我们要做 scaling 曲线,**必须**单变量控制,这条路不能抄。
3. **模型里没有评测者/机构效应项**:宽严只能靠双盲随机化在平均意义上抵消,无法校准。→ 我们若做多评估员,必须显式加 evaluator 项。

**自陈局限(§7)**:跨本体未做、单变量不可控、对抗评测者、Goodhart。**未把成本与方差列为局限。**

## 2. THE COLOSSEUM(arXiv:2402.08191v2,RSS 2024)

**⚠️ ID 更正**:批 1/批 2 草稿里我猜的 2502.06844 **不是这篇**(那是一篇 2-bit 量化论文)。正确 ID = **2402.08191**。作者 Pumacay、Singh、Duan、Krishna、Thomason、Fox;UW / Allen AI / USC。

### 2.1 它反对什么

- *"a majority of studies evaluate robot performance in environments closely resembling or even identical to the training setup"*
- *"benchmarks are not designed to stress-test the policies against systematic perturbations"*(§I)

### 2.2 机制与数字(复核)

- **20 个 RLBench 任务 × 14 个扰动轴**,共 **20,371 个任务-扰动实例**;**235 个 test set × 25 episode**。
- 判据:**二值成功** → task-averaged success rate。**没有配对、没有统计模型、没有平局概念。**
- 挑战赛:每轴固定 25 episode,按相对 No Perturbation 的**百分比降幅**排名。
- 1 个训练 seed + 1 个评测 seed;**只有真机部分做了 3 runs 并给 std**(图 6A)。
- 5 个基线(VoxPoser、R3M-MLP、MVP-MLP、PerAct、RVT);单轴掉 30–50%,多轴同开 ≥75%。
- sim→real:4 个真机任务、10 episode × 3 runs,**R̄² = 0.614**;7/14 轴的 R² = 0.74–0.94(§V-C)。

### 2.3 一处关键瑕疵(必须引,因为它正好是我们的立论反例)

*"we do not fix the object pose variations across our test episodes"*(§IV-D)

→ **单轴归因与位姿采样混淆**:同一个轴上的 25 个 episode,物体位姿是随机抽的。于是"这个轴掉了 40%"里,有一部分其实是位姿方差。
→ **这是本批对我们最有用的反面教材**:连领域最好的扰动基准,都在"归因的混杂变量"上失手。**我们的协议必须锁位姿,或把位姿作为显式因子。** 这句话可以直接写进我们论文的动机段。

### 2.4 局限(§VI)

真机每轴仅 2 个变体,资源受限;成本只出现在收益话术里(*"at a fraction of the setup cost"*)。

## 3. 仿真底座:LIBERO 与 RoboTwin 2.0

### 3.1 LIBERO(arXiv:2306.03310,NeurIPS 2023 D&B)

- **4 套件 / 130 任务**(摘要原文 *"four task suites (130 tasks in total)"*,主会话复核);Spatial/Object/Goal 各 10,LIBERO-100 = 90 短程 + 10 长程(论文称 LIBERO-Long,README 称 `libero_10`)。
- **每任务 50 条人类遥操 demo**(*"50 trajectories of high-quality demonstrations for every single task"*)。许可:代码 MIT、数据 CC BY 4.0。
- **判据**:0/1 稀疏,**由仿真器谓词判定**(*"The simulation terminates when all predicates are verified true"*);每任务 **20 rollout**、≤600 步;**3 seeds {100,200,300}**,报 mean ± SE。无 CI。
- **脚本行为**:固定初态(`metric.py`: *"get fixed init states to control the experiment randomness"*),从 `.pruned_init` 按 `arange % shape[0]` 轮转;**无视觉随机化**;`use_mp: true / num_procs: 20` 并行。
- **口径陷阱(四条,全部要写进我们的方法节)**
  1. 论文指标是 **FWT/NBT/AUC**,不是平均成功率——与报 avg success 的论文不可直接比;
  2. *"we pick the model checkpoint that achieves the best success rate as the final policy"* → **best-ckpt 天然偏高**;
  3. 同权重两次评测不一致(GitHub issue #86:*"the success rates are different"*,维护者未答);
  4. **LIBERO-Plus(2510.13626)**:*"performance dropping from 95% to below 30% under modest perturbations"* —— 底座本身对扰动极脆。

### 3.2 RoboTwin 2.0(arXiv:2506.18088)

- 50 个双臂任务、5 本体、731 物体/147 类;每 task-embodiment 100 干净 + 400 域随机轨迹,总 >10 万条。代码 MIT。
- 判据 0/1,由各任务 `check_success()` **几何谓词**判定;**每任务 100 rollout × Easy/Hard 两档**;**未报标准差或 CI**。
- **不固定初态**,按 seed 生成场景(`st_seed = 100000*(1+seed)`)。
- **陷阱**:Easy/Hard 混报不可比;**评测只用单一本体**(Aloha-AgileX)→ 跨本体数字不可比。
- 自陈:铰接物体与精确位姿任务 0%(*"Tasks with 0% success—such as 'Open Laptop' and 'Shake Bottle'"*)。

### 3.3 给 E2 的落地结论

**选 LIBERO,不选 RoboTwin 做主扫描。** 理由:RoboTwin 的 Hard 域随机化会把**域随机方差叠到 K 的效应上**,正好污染我们要测的自变量。

**最小可行配置(建议)**:
- 任务:Spatial + Object 各 10(共 20);
- 库规模 N:10 / 25 / 50(取官方 50 demo 的子集,**保证同源**,不混自采);
- K ∈ {1, 4, 8};每条上下文 L 取 2 档;**固定 B = K·L** 做等预算曲线;
- `n_eval = 50`(用满 50 个初态,不停在默认 20),**3 seeds**;
- 规模:20 任务 × 50 rollout × 3 seed ≈ **3,000 episode/配置**。
- **统计底线**:单臂 SE,20 rollout ≈ 0.11、50 rollout ≈ 0.07 → **5pp 的差异必须靠"配对同初态 + 多 seed"才敢宣称**,单次 50 rollout 不够。

**必须报告的元数据(否则别人复算不出)**:任务 ID 清单;demo 条数与来源(官方子集 vs 自采);`n_eval`/`num_procs`/`max_steps`;**初态文件版本**;ckpt 选择规则(best vs last);seed 列表;聚合方式(任务内平均→套件平均 vs pooled);代码 commit;用的是 `libero_10` 还是 `libero_100`。

**会被质疑的五件事**:20 rollout 报两位小数;best-ckpt 抬高基线;Long 与 `libero_10` 混称;Easy/Hard 混报;不写初态版本。

## 4. 四条地基(ACT / DP / OpenVLA / DROID)

| 篇 | 机制一句话 | 主数字 | 它把什么变成"已解决" | 自陈局限 |
|---|---|---|---|---|
| **ACT/ALOHA**(2304.13705v1,Zhao/Kumar/Levine/Finn) | leader-follower 关节遥操(<$20k)+ CVAE 吸收多模态 + Transformer 一次出 k 步(有效时域降 k 倍)+ 推理时重叠 chunk 指数加权 | 6 真机 + 2 仿真;每任务 50 条(≈10 min);Cup Open 84%/Slot Battery 96%/Slide Ziploc 88;/Thread Velcro 20%;去 CVAE 35.3%→2% | 低价硬件 + 50 条演示可做毫米级双臂;**action chunking 成为默认组件** | **无泛化实验**;每任务从零训 5 h、80M 参数;失败归因 *"difficulty of perception and lack of data"* |

### 4.1 四条地基合起来留下的缺口

**共同确立的范式**:大规模人类演示 → 端到端 BC(chunk / diffusion / token 三种参数化)→ 单任务或跨本体少样本。四篇都把**数据规模与多样性**当泛化的唯一调节手段,把**策略结构**当性能瓶颈(DP 原话:policy structure 是 *"a significant performance bottleneck"*)。

**共同未解决(四条)**:
1. **评测不可比**:25 trials/1 seed(ACT)、10 rollouts(DROID)、29 任务但分本体(OpenVLA),无 held-out 场景协议。
2. **数据效率的绝对下限从未刻画**:ACT 50 条但每任务重训;OpenVLA 要 970k 预训练再 10–150 条微调;DP 只有相对曲线。**三篇都在说"相对更省",没人回答"多少条才够"。**
3. **失败不可归因**:端到端黑箱,错了分不清是感知、覆盖不足还是表达力。
4. **演示质量天花板**:BC 原则上不能超出演示支撑集。

**检索式策略要填的是第 2+3 条**。免训练检索把"新任务"变成"检索 + 时序拼接已有片段",零梯度、数据即策略,失败可直接定位为"检索不到"。

### 4.2 我们必须提前准备的反驳(本批最重要的一段)

**最锋利的反驳**:**"检索式方法没有学习,超不过演示质量"——而且它有实证:ACT 表 I 里 VINN 在两个真实任务终局成功率≈0。**

**我们的回答(三层,按强度递进)**:
1. **归因层**:VINN 输的不是"检索",是**单步检索 + 无时域结构**(检索一个动作,而不是一段带时序的演示)。**ACT 自己证明这两个缺陷可以补**——chunk 把有效时域降 k 倍、temporal ensemble 消抖动。同一套补丁搬到检索侧(chunk 级检索 + 闭环重检索)即可。这不是辩解,是同一篇论文提供的证据。
2. **对称性层**:**"超不过演示质量"对 BC 同样成立**。DP 倒酱 IoU 0.74 vs 人类 0.79,OpenVLA 自陈 *"typically <90%"*——**没有任何一条路线超过人类**。所以这不是检索的原罪,而是**整条模仿学习路线的共同上限**。
3. **差异层**:检索真正的差异不是"更强",而是**可归因 + 零训练成本 + 库可增量更新**。这也是为什么"测量"是这条路线最有价值的贡献——**它的失败是可解释的,而这正是端到端 BC 缺的**(缺口 3)。

→ **写法建议**:引言不要主张"检索式更强",主张"**检索式让失败可归因,而可归因才让 scaling 可测量**"。这个主张不可被 ACT 表 I 打穿。

## 6. 对主线的净影响

### 领先点③(阶段级归因)——**从"协议"升级为"模型",这是本批最大增量**

- 原:两阶段独立判据 + 双评估员一致性 + 基线对称。
- 升级:**在 RoboArena 的 `θ_p + τ_t + ν_t + ψ_{p,t}` 上加阶段项 `σ_{p,t,s}`**,用同一套 EM 拟合,输出**"某策略在某阶段的劣势及其置信区间"**。
- 为什么这是真增量:RoboArena 与 COLOSSEUM **都没报归因**(§0 收获二),而 COLOSSEUM 的轴级降幅还混了位姿方差(§2.3)。**"带混杂控制的阶段级归因模型"确实是空的。**

### 领先点①(上下文预算曲线)——**底座确定**

- 用 LIBERO(Spatial+Object,20 任务,50 rollout,3 seed),不用 RoboTwin(域随机化污染自变量)。
- 报告清单已列(§3.3),**初态版本 + ckpt 规则 + 聚合方式**三项最容易被质疑。

### 领先点②(换算率)——**新增一条硬要求**

- 由批 2 的 Skild 380(插值、无 CI)与本批 LIBERO 的 SE 数据共同推出:**换算率必须报交叉点 CI + 插值规则 + 相邻测点间距**。

### 新增风险登记

- **R-1**:LIBERO 底座本身对扰动极脆(95%→<30%,LIBERO-Plus)。→ 我们的结论**只在"原始 LIBERO 分布"内成立**,不得外推到扰动鲁棒性。**必须在论文里写死这条边界。**
- **R-2**:best-ckpt 选择会抬高基线。→ 我们统一用 **last ckpt**,并在附录说明。
- **R-3**:DP/OpenVLA/DROID 三篇都自陈"评测样本极小且无 CI"。→ 我们与它们比时**不能只比自己跑的数**,必须注明"原论文口径"与"我们复现口径"两列。
